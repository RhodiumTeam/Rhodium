# 无头优先，需要时独占切到 TUI

这篇回答：槽位平时用哪种方式跑 agent，为什么终端界面只在需要时切过去，而且不和无头同时存在。

前置阅读：[术语表](../../GLOSSARY.md)、[产品说明](../product.md)、[调研摘要](../research.md)

状态：已接受（2026-10-21）

槽位默认以无头模式运行。需要亲手操作时，用 `/rh_tui` 切到 TUI 模式，同一时刻只能是其中一种。

无头优先，是因为北极星是手机 IM 遥控。流式输出、工具调用折叠、审批按钮、插话，都需要结构化的事件。无头接口直接给出这些，终端界面只能靠读屏或 hook 去拼。

两种模式互斥，是因为两个进程不能同时写同一份对话记录（Claude 官方文档，见[调研摘要](../research.md)“外部约束”）。所以切换时先让无头进程退出，再在终端里用 `claude --resume` 打开同一段对话。

## 考虑过的其他方案

- **agent 一律在终端界面里跑，状态另外靠 hook 和读屏获取**。这是 2026-10-19 第一轮调研的结论，后来改成了无头优先。输入仍靠往终端里打字。读屏会随 agent 升级而失效：coder/agentapi 靠屏幕判断状态，Claude 一升级就截不到输出。
- **终端和手机随时都能接手，手机来消息就抢占终端**。Happy 和 HAPI 是这样做的：手机一发消息，就结束终端里的 Claude，改由手机那边接着跑。代价是你在终端里做到一半，会被一条手机消息打断。

## 后果

- 聊天记录以 agent 自己的对话记录文件为准。所以 TUI 期间的回合，切回无头后也看得到。
- 切换要停一个进程、再起一个进程。默认等当前回合结束，加 `!` 才打断。完整规则见[产品说明](../product.md) §4.2。
- TUI 期间，IM 发给这个槽位的消息不投递，只回一句提示。这是独占的直接代价，规则同样在[产品说明](../product.md) §4.2。
- v1 里无头槽位不出现在 Herdr 里，只能在网页看板上看。
