# 托管进程用 Rust 写，不解析协议，带版本号

这篇回答：托管进程用什么语言写、只做哪些事，以及它将来怎么升级。

前置阅读：[术语表](../../GLOSSARY.md)、[调研摘要](../research.md)

状态：已接受（2026-10-21）

托管进程用 Rust 写，只用标准库，不引第三方库，估算约 200 行。

它不理解任何 agent 的协议，只做三件事：

- 按换行符把输入输出切成行。
- 把收发的每一行存到磁盘。
- `rhodium` 重连时，把它错过的输出补发给它。

Claude 怎么升级都碰不到它，所以它可以写好就长期不动。

它和 `rhodium` 之间的协议带版本号。升级时，旧版托管进程不原地替换，一直跑到它托管的 agent 进程退出为止，例如空闲回收或切到 TUI。之后再起的托管进程都用新版。

选 Rust，是因为要的就是“写好就不动”。只用标准库，就没有依赖要跟着升级。内存也更省：估算每个 2–4MB，用 Bun 写约 15MB（[调研摘要](../research.md) §1）。

## 考虑过的其他方案

- **和主程序一样用 Bun**。架构讨论时最初推荐的是这个方案。
  - 好处：仓库只有一门语言。
  - 代价：每个托管进程多占约 12MB（估算）。
  - 空闲回收后通常只剩一到三个托管进程活着（估算），所以内存差距不大，不是主要理由。
  - 最后选了 Rust，看重的是写好就不动。

## 后果

- 仓库里有两门语言，构建要同时用到 `bun` 和 `cargo`。
- 只要还有旧版托管进程活着，`rhodium` 就要能说它那个版本的协议。
