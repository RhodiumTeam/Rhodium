# 看板可以同时开几个入口，每个入口一个端口、一种认法

这篇回答：看板能不能同时经 tailnet 和你自己的反代开放，怎么开才不让一个入口的请求冒充另一个入口认的人。

前置阅读：[术语表](../../GLOSSARY.md)、[产品说明](../product.md)、[ADR-0013](0013-board-exposure-is-yours.md)

状态：已接受（2026-11-17）。它改掉了 [ADR-0013](0013-board-exposure-is-yours.md) 末尾的“看板还是只听一个端口、只用一种认法”。

[看板](../../GLOSSARY.md)可以同时开几个入口。入口是看板听的一个端口，带它自己的认法和主机名白名单，规矩和 ADR-0013 里的一样。例如：

- 7800 给 `tailscale serve`：按 `Tailscale-User-Login` 认你，只认 tailnet 和本机的主机名。
- 7802 给 `cloudflared`：不认身份，认人交给 Cloudflare Access，只认你配的域名。

你按要去的地址选：在 tailnet 上开 `https://<机器>.ts.net/`，在外面开你的域名。几个入口背后是同一个看板，看到的、能做的都一样。

## 为什么每个入口一个端口

ADR-0013 不做两种认法同时开，是因为它们共用一个端口：Cloudflare 不删请求里自带的 `Tailscale-User-Login`，公网上谁都能自己写这个头，冒充你进来。

分开端口后，这条路走不通：

- `cloudflared` 只转到不认身份的那个端口。那里本来就不看 `Tailscale-User-Login`，写了也没用。
- 公网请求就算被误转到 tailscale 那个端口，主机名是你的域名，不在 tailnet 的白名单里，直接 403。
- 留下的风险和 ADR-0013 里 Tailscale 模式的那一条一样：端口前接了把主机名改成本机地址的代理。例如把 `cloudflared` 配成转到 tailscale 端口，还把 `httpHostHeader` 写成 `localhost`。这样配就是配错了，和以前一样。

## 考虑过的其他方案

- **一个端口，按主机名换认法。** 公网来的按 Access，`*.ts.net` 来的按 Tailscale。主机名是请求自己写的，一个配错的反代就能让公网请求顶着 `*.ts.net` 的主机名进来。分端口把这层判断交给了“请求进了哪个端口”，这不是请求能自己写的。
- **校验 Cloudflare Access 的令牌。** 理由同 ADR-0013：只能配一家。

## 后果

- 配置里 `[board]` 照旧是第一个入口；再加的写在 `[[board.extra]]` 下，每个一张表，项和 `[board]` 一样。旧配置不用改。
- 每个入口各自查主机名、同源和认人；网页终端的握手也是。
- 配置里哪个入口写错，整个看板都关着，和以前一样，不只关那一个：一个入口听不到时，你很难发现自己在用的是哪个。
- `rh doctor` 每个入口各查一遍：听的地址、不认身份的入口不登录能不能打开。
- 页面只用相对地址，不记自己是从哪个入口打开的。装到手机桌面的，各入口算两个应用。
