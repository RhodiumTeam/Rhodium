# Rhodium IM 文字与交互规范

这篇回答：Rhodium 在 QQ 和 Telegram 里自己说的每一类话、过程消息里的工具行、选择面板和按钮，具体写成什么样。

前置阅读：[产品说明](product.md)、[架构](architecture.md)

- 产品说明 §5 讲 IM 里会发生什么，架构 §8 讲消息怎么发。这篇只定写法：用什么词、怎么排、按钮上写什么、按下以后怎样。
- agent 自己说的话一个字不改，不归这里管。
- 这篇有几处改了上游文档的说法，列在 §12。实现时上游一起改。
- 飞书（v1 之后）照 Telegram 的写法：一样发 Markdown，过程消息一样编辑同一条，按下面板一样原地往下走。不同的只在平台能力，例如没有按钮行、没有复制按钮，见[架构](architecture.md) §8。

样例记法：

- 一个代码块是一条消息。
- 块里以 `[` 开头、成对出现的 `[ ]`，是一行按钮，一个 `[ ]` 是一个按钮。工具行也以 `[🔧` 开头，它是消息正文，不是按钮。
- Telegram 样例是 rich message 的 Markdown 原文。rich message 是 Telegram 正文直接写 Markdown 的消息类型（[架构](architecture.md) §8.1）。QQ 样例是纯文本。
- 查询命令的回复（§7，§8 的列表和详情）两边都发 Markdown，样例是两边共用的 Markdown 原文。
- 写着“两边一样”的，只写一份。

样例数据：

| 槽位 | agent | 状态 |
|---|---|---|
| dispatcher/main | Claude | 空闲，主 Bot 的默认目标，目录 ~/RhodiumWorkplace |
| Rhodium/main | Claude | 运行中 |
| Rhodium/docs | Claude | 需要你 |
| Rhodium/pi | pi | TUI 模式，dispatcher/main 派生的一次性槽位 |
| shop/api、shop/bench、shop/docs-site、shop/fix-login、shop/review | Claude | 空闲或未运行 |

## 1. 原则

1. **写成句子或者分行，不拼接。**
   - 不同类的信息，要么组成一句话，要么各占一行。
   - 不用 `·`、`|`、两个空格、一串逗号把属性连起来。
   - 反例：`dispatcher/main  claude  无头  空闲  /home/user/RhodiumWorkplace`
   - 正例：`这里的消息交给 dispatcher/main，用 Claude。`
2. **只给此刻需要的。**
   - 默认值、内部状态、上下文里看得出的都不写。
   - 反例：`生命周期: 长期`、`审批模式: 关（默认）`
   - 正例：`设置都是默认。`
3. **先说发生了什么、要你做什么。** 命令、退出码、路径放在后面。
   - 反例：`dispatcher/main 请你确认：rh release Rhodium/pi`
   - 正例：`dispatcher/main 想把 Rhodium/pi 切回无头。`，命令在最后。
4. **用你的词，不用系统的词。**
   - 窗口、槽位、对话的叫法见 §2.6。
   - 不说“投递”“路由”“处理”。
5. **结构靠换行和空行，不靠图标。**
   - 一条消息最多三块：说明、内容、提示。块之间空一行。
   - 查询命令的回复用标题分节，不受三块的限制（§7）。
6. **按钮能做的事，文字不再教。**
   - 有按钮就不写“点按钮作答”“发 /x <编号>”。
   - 只说不明显的后果和别的做法，例如“回别的话算拒绝”。
7. **一件事一条消息说完。**
   - Telegram 改原消息，不追加。
   - QQ 只能追加，每条都要单独读得懂。
8. **旁白和 agent 的话分得清。**
   - agent 的话原样放。
   - Rhodium 加的工具活动是旁白，写成 `[🔧 …]` 工具行。Telegram 上工具行再放进引用块。
   - Rhodium 自己说话不用“我”，不用“请”“您”和语气词。

## 2. 符号和写法

### 2.1 符号

| 符号 | 意思 | 用在哪 |
|---|---|---|
| `✓` | Telegram：现在是这个。QQ：你按过这个 | 只在按钮上。QQ 按过的按钮（`visited_label`，按过后按钮上显示的字）写 `✓ 原文字`，原文字不带 `★` |
| `★` | QQ：发面板时现在是这个 | 只在 QQ 面板的按钮上，例如 `[★ Rhodium/pi]`、`[★ 4. Rhodium/pi]`。QQ 改不了发出去的面板，又会给按过的按钮加 `✓`，所以现在那项不用 `✓`，免得按了另一项后两个都带 `✓`（2026-10-22 决定） |
| `…`（一个字符） | 截断；进行中 | `~/Rhodium/…/render.ts`、`正在切回无头…` |
| `🔧` | 工具活动 | 只在工具行的开头：`[🔧 Edit、Bash ×2]` |
| `×N` | 连着调了 N 次 | 只在工具行里，紧跟工具名 |
| `[ ]` | 工具行的边界 | 只在工具行里 |

- 除了工具行的 `🔧`，Rhodium 自己的话不用 emoji。按钮上的 `✓`（U+2713）和 `★`（U+2605）是文字符号，不是 emoji，各家手机上样子一样。agent 写的 emoji 原样保留。
- 不用：`·`、`|`、`→`、`←`、`‹`、`›`、`▸`、`【】`、两个以上空格对齐。`×` 只用在工具行里。
- `/` 只出现在槽位名、路径和命令里，不当分隔符。
- `〔工作区/槽位〕`：agent 的话发到目标不是它的窗口时，第一行写这个（[产品说明](product.md) §5.9）。只用在 agent 的话上。

### 2.2 Telegram 的 Markdown，QQ 的纯文本

Telegram 上，Rhodium 自己的话也发 rich message，只用三种写法：

- 行内代码：能复制的东西。命令、路径、工具参数、搜索词。
- 代码块：审批要看的命令或内容。
- 引用块（`>`）：过程消息的工具段；引用你说过的话。
- 不用：粗体、斜体、标题、表格、公式、剧透、高亮。查询命令的回复例外，见下。
- 拼进来的动态内容不在代码里时，照架构 §8.2 的实测转义，和 agent 的话一样。
- 平台拒收 rich message、改发纯文本时，就发 QQ 那一版。

QQ 上，Rhodium 自己的话按纯文本写，查询命令的回复例外，见下：

- 引用你的话用中文引号“”。
- agent 的话照旧，能发 Markdown 就发。所以工具行和正文之间空一行。
- QQ 只在 Markdown 消息上显示按钮（2026-10-22 真机实测）。带按钮的那几条，适配器把纯文本转义成 Markdown 发，看上去和纯文本一样（架构 §8.2）。写法不用跟着改。
- 平台拒收 Markdown、改发纯文本时，按钮显示不出来，改写在正文后面。按钮数据（§11.4）不同，写法不同，原因见架构 §8.2：
  - 回答提问、从几条提问里挑的按钮：写成编号列表，再加一句“回编号选一个。”。只有这两种编号。

```
要运行这条命令，允许吗？

rm -rf build && npm run build

回别的话算拒绝，并转告它。

1. 允许
2. 拒绝

回编号选一个。
```

  - 数据是命令的按钮（面板选项、动作）：一行一个，写成 `标签：命令`，不编号。例如运行中的 `/status`（§7.1），改发纯文本时标题去掉了记号：

```
Rhodium/main
运行中，这一回合跑了 3 分钟
[🔧 Bash] npm test，正在运行（3 分钟）

模型设置
Agent：Claude Code
模型：Sonnet 4.5 high

状态
目录：~/Rhodium
上下文：31% (~62k / 200k Tokens)

停止：/stop
换模型：/model
思考强度：/effort
压缩上下文：/compact
```

  - 复制按钮写成一行 `复制：原文`。
  - [取消]、翻页、填进输入框的按钮（[自己起名…]）不写。
  - 没有编号的，不加“回编号选一个。”。

查询命令的回复（§7，§8 的列表和详情），两边都发 Markdown（2026-10-24 定）：

- 只用两种写法：
  - `##`、`###` 标题，给回复分节。
  - 粗体，只给行首的数字：`**91%** 7d，9h 26m 后重置`。
- Telegram 上目录照上面放进行内代码。QQ 上不用行内代码。
- 别的字照原样显示，不当格式（[架构](architecture.md) §8.2）。
- 平台拒收、改发纯文本时，去掉标题记号和粗体，别的不变。
- 为什么和上面不一样：查询回复有几块并排，手机上要一眼分开几节、扫到快满的那个数。

### 2.3 标点、换行、用词

- 全角标点：，。、：；？（）“”。
- 中文和英文、数字之间空一个半角空格：`切到 Opus 4.5`、`2 次`。全角标点两边不空。
- “标签：值”用全角冒号，冒号后不空格：`目录：~/Rhodium`。标签只用这几个：现在、已选、命令、原因、目录、上下文、改过的设置、在等的、Agent、模型。
- 句子以“。”结尾，问句以“？”结尾。标签行、列表行、按钮、工具行不加句号。标题、`/status` 的状态行（§7.1）、数字打头的行（§7.2）也不加。
- 同类几项用“、”。不同类分行，或者写进一句话。
- 括号只放补充：agent 种类、恢复时间、默认是谁、目录。一行最多一对，不套括号。
- 上下文的约数例外，用半角括号和 `~`：`19% (~186k / 1M Tokens)`（§2.4）。
- 动词：
  - 你的命令做完了，写“已……”：`已切到 Opus 4.5。`
  - 自己发生的事，写“……了”：`Rhodium/pi 崩溃了。`
  - 进行中，写“正在……”。

### 2.4 数字、时间、路径、名字

| 东西 | 写法 | 例 |
|---|---|---|
| 计数 | 阿拉伯数字，和单位之间空一格 | `3 次`、`2 个` |
| 大数 | 千分位 | `12,345` |
| token 数 | 1000 起写 k，100 万起写 M，M 留一位小数 | `127`、`7.9k`、`186k`、`18.9M` |
| 上下文 | 百分比，半角括号里写约数和当前模型的最大上下文。不到 1% 写 `<1%`。不知道最大上下文时只写约数 | `19% (~186k / 1M Tokens)`、`~62k Tokens` |
| 金额 | `$` 加两位小数。不到一分写 `<$0.01` | `$15.35` |
| 额度窗口 | 短写：5 小时写 `5h`，7 天写 `7d`。只管某个模型的，后面写模型名 | `5h`、`7d`、`7d Fable` |
| 额度的重置时间 | 24 小时内写还剩多久，短写，只取两个单位；再远写时刻；已经过了写 `已重置`。只用在额度那几行（§7.2），别处的将来时刻照下面 | `1h 46m 后重置`、`46m 后重置`、`10/27 06:00 重置` |
| 过去的时刻 | 今天 `14:30`；昨天 `昨天 14:30`；今年 `10/18 14:30`；往年 `2025/10/18`。不写秒 | |
| 将来的时刻 | 同上，24 小时内加剩多久 | `19:00 恢复（还有 2 小时 10 分）` |
| 时长 | 只取最大的两个单位 | `45 秒`、`3 分钟`、`2 小时 10 分` |
| 路径 | 家目录写 `~`。工具行里，槽位目录下的写相对路径。超过 40 字，中间写“…”，留最后两段 | `~/Rhodium/…/src/render.ts` |
| 槽位 | 总写全名 `工作区/槽位`。只有 `/rh_ls` 的分组里只写槽位名 | `Rhodium/pi` |
| 对话 | 时间加开头几个字。导入时默认槽位名用 ID 前 8 位，这是唯一露 ID 的地方 | `昨天 22:10 那段` |
| 模型 | agent 给的显示名，不写模型 ID。默认模型写“默认”，括号里写它实际用的模型，不写 Claude 给的 `Default (recommended)` | `Sonnet 4.5`，不写 `claude-sonnet-4-5`；`默认（Opus 5.5）` |
| 思考强度 | 原值，不翻译 | `high`、`max` |
| ultracode | 原样写 `ultracode`，开关写“开”“关” | `ultracode 改成开。` |
| agent | 句子和按钮里写 `Claude`、`pi`、`Codex`。`/status` 的 `Agent：` 一行写 `Claude Code`、`Pi`、`Codex CLI`（§7.1） | |
| 模式 | 按[术语表](../GLOSSARY.md)：无头、TUI 模式。说“TUI”，不说“终端模式” | `切到 TUI`、`在 TUI 里`、`切回无头` |
| 退出码、信号 | 只出现在 `原因：` 行 | `原因：agent 退出，退出码 1` |

### 2.5 长度

| 东西 | 上限 | 超了怎么办 |
|---|---|---|
| Rhodium 的一条话（不算列表、agent 原文） | 6 行。查询命令的回复按节算，每节 6 行 | 拆块，或删掉不必要的那句 |
| 面板按钮上面的文字 | 3 行 | 只留问题、现在、页码 |
| 简略工具行 | 4 项 | 后面写“，另外 N 次” |
| 详细工具行 | 一行 60 字 | 末尾“…” |
| 工具参数 | 40 字 | 末尾“…” |
| 一个工具段（详细） | 10 行 | 整段改用简略写法，一行 |
| 引用你的话 | 60 字，并成一行 | 末尾“…”。复制按钮里放全文（§11.5） |
| 审批内容 | 15 行，1000 字 | 留前 15 行，末尾写“（共 40 行，全文在看板上）” |
| `/resume` 预览 | 12 个汉字 | 末尾“…” |
| 列表正文 | 30 行 | 最后写“还有 N 个没列出” |
| 一条消息 | 架构 §8.1 能力表：QQ 2000 字，Telegram 4096 字 | 照架构 §8.2 的切法，补齐代码围栏；Telegram 过程消息在段和段之间切（§3.3） |

截断按看到的字算，不切开汉字或 emoji。

### 2.6 窗口、来源的叫法

给你看的话里：

- 这个窗口写“这里”。
- 别的窗口写“QQ 私聊”“Telegram 私聊”“飞书私聊”。同一个平台有几个 Bot 时带上 Bot 名：“QQ Bot main 的私聊”。
  - Bot 名默认是配置里的 ID。配置给 Bot 写了 `label`，就用 `label`：“QQ Bot Echo 的私聊”。命令里照旧写 ID。
- 例：`已并入 QQ 私聊那边正在跑的回合，回复会发在那边。`

agent 收到的来源行，也用同样的叫法：

- `[来自 QQ 私聊]`
- `[来自 Telegram Bot main 的私聊]`

两边都永远不出现：openid、聊天 ID、pane ID、完整的对话 ID、进程号、systemd 单元名、追踪 ID。

## 3. 过程消息

### 3.1 工具行（两边共用）

一段工具：agent 两段话之间的所有工具调用。

不进工具行：

- AskUserQuestion、ExitPlanMode、要审批的调用。它们另发成提问（§4）。
- TodoWrite，Codex 的 update_plan。它们是 agent 记账，不是干活。

**简略写法**（QQ 默认）：

- 一段写成一行，放在方括号里，开头是 `🔧`：`[🔧 Read、Grep]`。
- 按调用的顺序排。连续调了同一个工具，合成一项，次数写在名字后面：`×2`。只调 1 次不写次数。
  - `[🔧 Edit、Bash ×2]`：Edit 1 次，接着 Bash 2 次。
  - 不连着的同名工具不合并：`[🔧 Read、Bash、Read ×2]`。
- 各项用“、”连。
- 最多 4 项，再多写“，另外 N 次”：`[🔧 Read ×6、Bash ×4、Edit、Grep ×2，另外 3 次]`。

**详细写法**（Telegram 默认）：

- 每个工具一行：`[🔧 工具名] 参数`。
- 连续调了同一个工具，合成一行，次数写在名字后面。参数用“、”连，重复的写一次：
  - `[🔧 Read ×3] src/a.ts、src/b.ts、src/c.ts`
  - `[🔧 Bash ×2] npm test`
- 下表写“只写名字”的工具，只写方括号那部分。

参数取哪个：

| 工具 | 参数 |
|---|---|
| Bash；pi 的 bash；Codex 的 exec_command | 命令一行、不超过 40 字，写命令；否则写 `description`；都没有，命令截到 40 字。Codex 没有 `description` |
| Read、Edit、Write、NotebookEdit；pi 的 read、edit、write；Codex 的 view_image | 文件路径 |
| Codex 的 apply_patch | 第一个文件的路径，不止一个再写“等 N 个文件” |
| Grep、Glob | pattern |
| WebSearch；Codex 的 web_search | 搜索词 |
| WebFetch | 网址去掉 `https://` |
| Agent、Task | `description` |
| Skill | skill 名 |
| MCP 工具 | 名字写 `服务.工具`，不带参数 |
| 别的 | 只写名字 |

- pi 的小写工具名首字母大写：bash 写 Bash。
- Codex 的工具名照原样写，不改大小写：`exec_command`、`apply_patch`。它们由 Codex 的条目种类换来，对照表见[架构](architecture.md) §6.4（2026-10-27 第 34 轮定）。
- Telegram 上，命令、路径、pattern 放进行内代码；`description` 是一句话，不放。
- 像密钥的值打成 `***`：`sk-`、`ghp_` 开头的一串；`Bearer`、`token=`、`--token` 后面的值；`API_KEY=…` 这样、名字里带 KEY、TOKEN、SECRET、PASSWORD 的值，不分大小写。先打码再截断。工具行会把参数发到 QQ 和 Telegram 的服务器上。例：`curl -H "Authorization: Bearer ***" …`

**正在运行**（只在 Telegram）：

- 一个工具开始了还没结束，它占工具段的最后一行：`[🔧 Bash] npm test，正在运行`。简略写法只写 `[🔧 Bash] 正在运行`。
- 跑满 1 分钟，后面加用时：`[🔧 Bash] npm test，正在运行（2 分钟）`，每分钟更新一次。
- 工具结束，这一行并回上面的行。
- 下一段话开始、消息被冻住、回合结束时，这一行去掉。

### 3.2 QQ

agent 每说完一段话发一条。这之前的工具写成一行 `[🔧 …]`，放在这条开头，下面空一行。

```
我先看一下配置。
```

```
[🔧 Read、Grep]

配置里少了 X，我来补上，然后跑测试。
```

```
[🔧 Edit、Bash ×2]

改好了，测试都过了。
X 的默认值设成了 30，和文档里写的一致。
```

- 最后一条就是最终回复，不加任何标记。
- 第一段话前面没有工具，就没有工具行。
- 回合结束时还剩工具、没有话了：不单发。`rh send me` 接管的回合例外（§3.4）。
- 整回合一句话都没说：发 `[🔧 Bash ×2]`，空一行，`这一回合没有回复文字。`
- 一段话超过 2000 字，照架构 §8.2 的切法切；工具行只放在第一条。
- 提问另发，不带工具行；攒着的工具留给下一段话。
- agent 写在行首的 `#393`、`#tag` 照原样显示。QQ 不要空格就把它当标题，渲染器替它转义（架构 §8.2）。

详细写法（`/rh_verbose` 打开后），每个工具一行：

```
[🔧 Read] src/config.ts
[🔧 Grep] X

配置里少了 X，我来补上，然后跑测试。
```

额度（每条入站消息能回几次被动回复，见[产品说明](product.md) §5.5）：

- 每段话用一次被动回复。留 2 次给最终回复和兜底提示。
- 用到线了，后面的话攒着，回合结束时和最终回复拼在一起发。
- 一条放不下，中间的话缩成一句，放在最前面：

```
中间还有 2 段话没发出来，看板上能看到。

[🔧 Edit、Bash ×2]

改好了，测试都过了。
```

被动回复全用完（产品说明 §5.5 的“完成，回任意字查看”）：

```
dispatcher/main 回复完了。这边的回复次数用完了，回任意一个字就发过来。

[看回复]
```

按钮数据是一个没副作用的字（`查看`）。按下也算一条入站消息，带来新的被动额度。

### 3.3 Telegram

一个回合一条消息，不断编辑。段的顺序就是事件的顺序：agent 的话是普通段落，工具段是引用块，段和段之间空一行。agent 说过的话都留着。

回合中，第二次跑测试：

```markdown
我先看一下配置。

> [🔧 Read] `src/config.ts`
> [🔧 Grep] `X`

配置里少了 X，我来补上，然后跑测试。

> [🔧 Edit] `src/config.ts`
> [🔧 Bash] `npm test`
> [🔧 Bash] `npm test`，正在运行
```

定稿。最终回复就是最后一段，不另发，不加“完成”：

```markdown
我先看一下配置。

> [🔧 Read] `src/config.ts`
> [🔧 Grep] `X`

配置里少了 X，我来补上，然后跑测试。

> [🔧 Edit] `src/config.ts`
> [🔧 Bash ×2] `npm test`

改好了，测试都过了。
X 的默认值设成了 30，和文档里写的一致。
```

简略写法（`/rh_verbose` 关掉后）的定稿：

```markdown
我先看一下配置。

> [🔧 Read、Grep]

配置里少了 X，我来补上，然后跑测试。

> [🔧 Edit、Bash ×2]

改好了，测试都过了。
X 的默认值设成了 30，和文档里写的一致。
```

- 引用块里每行都要真换行。rich message 要是把单个换行并成空格，行尾加两个空格（待实测，§13）。
- 回合中途来了提问或图片：这条消息冻住，去掉“正在运行”那行。后面的内容在提问下面新开一条接着写。
- 超过 4096 字：在段和段之间切，不切开工具段。这条封口，新开一条接着写。
- 改发纯文本时：工具段不放引用块，工具行照样写。

### 3.4 agent 自己用 `rh send me` 发到了这里

agent 在一个回合里用 `rh send me` 往开始这个回合的窗口发了文字，就算它接管了这一回合的回复（[产品说明](product.md) §5.5）：

- 这一回合后面它说的话不再转发，最终回复也不发。免得你收到两遍。
- 工具行照常显示，写法同 §3.1。
  - Telegram：`rh send me` 那条发在过程消息下面，过程消息在这里冻住，和中途来了图片一样（§3.3）。后面的工具段在 `rh send me` 那条下面新开一条接着写，里面只有工具段，“正在运行”照旧。
  - QQ：本来要发一段话的地方，只发这段话前面的工具行，照旧用一次被动回复。
  - QQ 回合结束时，还没发出去的工具合成一行单发一条，最终回复前后的都算。这里不照 §3.2 的“不单发”，因为最终回复不发，这些工具没别的地方放。
  - `rh send me` 自己那次 Bash 调用也是工具，照样进工具行。例如 `rh send me` 以后跑了一次 `ls`，回合结束时发 `[🔧 Bash ×2]`。
- 已经转发出去的留着。QQ 发出去的几条本来就撤不掉。
- 你的消息之后并进这个回合，接管就解除（[产品说明](product.md) §5.5）。agent 从那以后说的话照常显示，最终回复照常发；它在插话之前说的照旧不发。Telegram 上接着写在 `rh send me` 那条下面那一条里。
- 你在 IM 里回答了这个回合挂着的提问，接管也解除，同上。Telegram 上接着写在提问下面的新消息里（§3.3）。提问超时、被撤回的不解除。
- `rh send me` 之前说的话照常发。QQ 上额度用到线、攒着没发的（§3.2），回合结束时和最后那行工具行拼成一条发；放不下，照样缩成“中间还有 N 段话没发出来，看板上能看到。”

不算接管，这一回合照常转发：

- 只发文件、图片，不带文字。
- 发到了别的窗口。例如别的窗口插过话，成了联系窗口。

### 3.5 `/rh_verbose`

- 按窗口记，改的是这个窗口的工具行写法。
- 默认：Telegram 详细，QQ 简略。
- 不带参数就是切换；`/rh_verbose on` 改成详细，`/rh_verbose off` 改成简略。2026-10-24 第 31 轮问过要不要改成先出面板，定的是照旧切换。

两边一样：

```
工具行改成详细：每个工具一行，带文件名或命令。

[改回简略]
```

```
工具行改成简略：只写工具名和次数。

[改回详细]
```

按钮数据：`/rh_verbose off`、`/rh_verbose on`。写明开还是关，QQ 上旧按钮晚点按也不会弄反。

## 4. 提问和审批

规则：

- 提问来自这个窗口的目标，不写槽位名，直接问。
- 来自别的槽位，第一行写 `Rhodium/pi 问你：`。
- 选项有说明，或者选项名放不进按钮，正文才列编号。否则选项只在按钮上。
- 提示只说不明显的：能直接写回答；回别的话算拒绝。

### 4.1 选择题

两边一样：

```
部署到哪个环境？

1. staging
2. production：会通知所有用户

也可以回编号，或直接写你的回答。

[staging] [production]
```

选项没有说明：

```
先跑测试，还是先提交？

也可以直接写你的回答。

[先跑测试] [先提交]
```

来自别的槽位：

```
Rhodium/pi 问你：

先跑测试，还是先提交？

也可以直接写你的回答。

[先跑测试] [先提交]
```

几个问题一起问（不带按钮）：

```
有 2 个问题，每行答一个：

问题 1：部署到哪个环境？
1. staging
2. production

问题 2：要先备份数据库吗？
1. 要
2. 不要

可以回编号，也可以直接写。
```

可多选的，问题后面加“（可以多选，编号用空格隔开）”。

### 4.2 审批

QQ：

```
要运行这条命令，允许吗？

rm -rf build && npm run build

回别的话算拒绝，并转告它。

[允许] [拒绝]
```

Telegram：

~~~markdown
要运行这条命令，允许吗？

```sh
rm -rf build && npm run build
```

回别的话算拒绝，并转告它。

[允许] [拒绝]
~~~

第一行按工具换：

| 工具 | 第一行 | 内容 |
|---|---|---|
| Bash | 要运行这条命令，允许吗？ | 命令全文 |
| Edit | 要改 `src/config.ts`，允许吗？ | 改成的内容 |
| Write | 要写 `src/config.ts`，允许吗？ | 文件内容 |
| WebFetch | 要打开这个网页，允许吗？ | 网址 |
| Codex 的 exec_command | 要运行这条命令，允许吗？ | 命令全文 |
| Codex 的 apply_patch | 要改 `src/config.ts`，允许吗？不止一个文件写“要改 3 个文件，允许吗？” | 改动的 diff |
| Codex 要额外权限 | 要多给它这些权限，允许吗？ | 一行一项，例如“联网”“写 /etc/hosts” |
| 别的 | 要用 X，允许吗？ | 最多 3 行“参数名：值”，每个值截到 40 字。不印 JSON |

来自别的槽位：第一行前面加槽位名，`Rhodium/pi 要运行这条命令，允许吗？`

### 4.3 计划确认

两边一样：

```
写好了计划，批准后才动手：

（计划原文，agent 的 Markdown）

回别的话算不批准，并转告它。

[批准] [不批准]
```

### 4.4 同时挂着几条提问

```
有 2 条提问在等你，先选一条再回答。刚才那句没交出去。

1. 部署到哪个环境？
2. Rhodium/pi 要运行：rm -rf build

[第 1 条] [第 2 条]
```

- 按下后，把那条提问带着它自己的按钮重发一遍。数据 `pick:<提问 ID>`。
- 来自这个窗口目标的，不写槽位名；别的槽位的写上。

## 5. 确认请求和回执

确认请求：agent 用 `rh` 做一件要你点头的事，例如把槽位切回无头（[术语表](../GLOSSARY.md)）。

### 5.1 agent 发起的

QQ：

```
dispatcher/main 想把 Rhodium/pi 切回无头。
这会结束 TUI 里的 agent，对话留着接着用。

命令：rh release Rhodium/pi
回别的话算拒绝，并转告 dispatcher/main。

[同意] [拒绝]
```

Telegram：同样的文字，命令放进行内代码：``命令：`rh release Rhodium/pi` ``。

认不出调用者：第一行写“有个认不出的程序想……”，提示只写“回别的话算拒绝。”。

### 5.2 你自己发起的（例如 `/rh_release`）

不再多回“已请你确认：……”那一句。按钮写成动作：

```
把 Rhodium/pi 切回无头吗？
这会结束 TUI 里的 agent，对话留着接着用。

[切回无头] [取消]
```

### 5.3 动作的说法

| 子命令 | 第一行（agent 发起） | 后果 | 你发起时的按钮 |
|---|---|---|---|
| release | 想把 X 切回无头 | 这会结束 TUI 里的 agent，对话留着接着用。 | [切回无头] [取消] |
| tui | 想把 X 切到 TUI | （没有） | — |
| stop | 想停掉 X | 正在跑的回合会中断，对话留着。 | — |
| archive | 想归档 X | 对话留着，发消息就恢复。 | — |
| agent | 想把 X 换成 pi | 会从一段新对话开始，旧对话发 /resume 能回去。 | — |
| rename | 想把 X 改名为 new-name | （没有） | — |
| use | 想把这里改交给 X。不是这里时写那个窗口的叫法（§2.6） | （没有） | — |
| bind | 想把 QQ Bot main 的默认槽位改成 X | 这里的消息也会改交给 X。（这里跟着这个默认走时才写。网页上没有“这里”，写这个窗口的叫法：QQ 私聊的消息也会改交给 X。） | — |
| pair --rm | 想去掉 QQ Bot qq2 的一个主人 | 那个账号的消息不再触发 agent。 | — |
| forget | 想让 Rhodium 忘掉 QQ Bot qq2 的一个聊天窗口 | 它选的槽位和收发记录都删掉，那个账号再发消息会重新记下。 | — |
| send | 想给 X 发消息：“……” | （没有） | — |
| 别的 | 想执行一条 rh 命令 | （没有） | — |

agent 发起的，按钮一律 [同意] [拒绝]。

use、bind、pair --rm、forget 是 2026-10-29 加的（#485）：

- 窗口和账号不写 ID（§2.6）。说的不是这里时，在叫法后面写它现在交给谁，好认出是哪个小号：`想去掉 QQ Bot qq2 的一个主人（它的私聊现在交给 Rhodium/pi）`。
  - 说的正是这里时，use 写“这里”，别的在叫法后面写“（就是这里）”：`想去掉 QQ Bot qq2 的一个主人（就是这里）`。
  - `rh use … -` 写成 `想把这里改回默认，交给 Rhodium/main`。
- “命令：”一行里，窗口 ID 和账号换成 `…`：`rh use qq2/… Rhodium/pi`、`rh pair qq2 --rm …`。
- 结果也不写 ID，用窗口的叫法：`已去掉 QQ Bot qq2 的一个主人。`、`已忘掉 QQ Bot qq2 的一个私聊。`。认不出的调用者的回执带上它（§5.4）。

急停（`rh stop --all`）不进 IM，只在 ssh 里用。agent 不能用它（[产品说明](product.md) §6.2），你在手机上也没有它的按钮和命令。

你自己发起的，只有 release 先确认（[产品说明](product.md) §5.6）。别的直接执行，写“—”的那几行没有确认这一步：

- `/rh_agent` 在面板里按一下就换（§9.4）。
- 带参数的命令照旧直接执行（§9.1）。
- 槽位详情里只有 [切回无头] 先确认（§8.3）。

### 5.4 回执

agent 发起的，你同意以后，Rhodium 只回“已回答：同意”。执行结果交给 agent，由它用 `rh send me` 告诉你（产品说明 §5.8）。

- Telegram：不另发。改原来那条，把最后一块（提示）换成回执，撤掉按钮。

```markdown
dispatcher/main 想把 Rhodium/pi 切回无头。
这会结束 TUI 里的 agent，对话留着接着用。

命令：`rh release Rhodium/pi`
已回答：同意
```

- QQ：新发一条 `已回答：同意。`。按过的按钮显示 `✓ 同意`（待实测，§13）。
- 认不出的调用者、已归档的调用者，没有 agent 能马上告诉你，回执带上结果：`已回答：同意。Rhodium/pi 已切回无头。`
  - 切换要等一会儿的，回执先写 `已回答：同意，正在切回无头…`。切完 Telegram 改这条，QQ 另发一条结果。

你自己发起的，Rhodium 自己报结果：

- Telegram：改原来那条。先换成 `正在切回无头…`，切完再改成结果，不另发：

```markdown
把 Rhodium/pi 切回无头吗？
这会结束 TUI 里的 agent，对话留着接着用。

Rhodium/pi 已切回无头。
```

- QQ：按下回一条 `正在把 Rhodium/pi 切回无头…`，切完再发一条 `Rhodium/pi 已切回无头。`。
- 按了 [取消]：Telegram 把最后一块换成 `已取消`；QQ 回 `已取消，Rhodium/pi 没动。`。

各种回执：

| 情况 | Telegram（改原消息的最后一块） | QQ（新发一条） |
|---|---|---|
| 选择题 | `已回答：staging` | `已回答：staging。` |
| 审批，允许 | `已允许。` | `已允许运行这条命令。` |
| 确认请求，同意 | `已回答：同意` | `已回答：同意。` |
| 拒绝时带了话 | `已拒绝，并转告：“先别动，我还在用。”` | 同左 |
| 打字回答 | `已回答：先别跑全量` | `已把这句当作回答交给它。` |
| 从几条里选了一条再答 | 改的是重发的那条 | `已回答 Rhodium/pi 的提问：允许。` |
| 回答没看懂 | 不改，新回一句 | `没看懂这个回答。这条提问有 2 个问题，每行答一个。` |
| 超时，选择题 | `没等到回答，已让它自己判断。` | 不发，省额度 |
| 超时，审批和确认 | `没等到回答，按拒绝处理。` | 不发 |
| 按了失效的按钮 | 弹出“这个按钮已经失效了” | 回一句同样的话 |

### 5.5 agent 要的配对码

agent 用 `rh pair <Bot> --add` 加小号时，码由 Rhodium 发给你，不经 agent（产品说明 §5.11，2026-10-29 加，#485）。发到调用者的联系窗口，两条：

```
dispatcher/main 要给 QQ Bot qq2 加一个主人。
10 分钟内，用要加的那个账号私聊 QQ Bot qq2，发下一条里的码。只用你本人的账号。
不想加就别理它。
```

```
K7QX2M9P
```

- 码单独一条，长按就能复制整条。Telegram 上写成行内代码，点一下就复制。
- 认不出的调用者经你同意的：第一句写“有个认不出的程序要给……”。
- 发码的账号配上以后，那个窗口照旧回“已配对”。

## 6. 通知

- 第一句总写出是哪个槽位。通知可能来自任何槽位，也可能隔几小时才看。只有额度用完合成一条时，槽位写在第二行（§6.2）。
- 原因、退出码放在 `原因：` 那一行，通常是第一块的最后一行。没能启动的崩溃，下面再接 agent 自己最后报的错（§6.1）。

### 6.1 崩溃

QQ：

```
Rhodium/pi 崩溃了，这一回合没做完。
正在自动恢复这段对话。
原因：agent 退出，退出码 1

它那条提问作废了，之后回的编号会当成新消息。
这条不确定它收到没有，需要的话再发一遍：
“帮我看下测试为什么挂了”

[复制]
```

Telegram：

```markdown
Rhodium/pi 崩溃了，这一回合没做完。
正在自动恢复这段对话。
原因：agent 退出，退出码 1

它那条提问作废了，之后回的编号会当成新消息。
这条不确定它收到没有，需要的话再发一遍：
> 帮我看下测试为什么挂了

[复制]
```

- [复制] 怎么做见 §11.5。不确定的有几条时，每条一个按钮：[复制第 1 条] [复制第 2 条]。

没能启动时，`原因：` 下面加一行 `它最后报的错：`，接这个进程报错输出（`err.log`）的最后最多 3 行原文，两边一样：

```
shop/api 崩溃了，没能启动。
等着的消息都还在，不用重发。下次来消息时再启动它，到时一起交给它。
原因：agent 退出，退出码 1
它最后报的错：
No conversation found with session ID: 3f2a9c1e-5b7d-4e8a-9f60-2c1d8e7b4a93
```

- 空行不算一行。颜色这类终端控制码去掉。
- 3 行加起来超过 300 字就截掉后面，末尾写 `…`。
- 它没报过错，这两行都不写。之前的进程留下的报错不算。
- 中途崩溃的不加：跑久了的进程报错里杂音多，最后几行不一定是原因。
- Codex 开不了线程时不加，`原因：` 那行直接写 Codex 的报错，见[架构](architecture.md) §6.4。

第二行按情况换：

| 情况 | 第二行 |
|---|---|
| 自动恢复 | `正在自动恢复这段对话。` |
| 运行数到上限 | `同时运行的槽位满了，有空位就自动恢复。` |
| 磁盘不够 | `磁盘快满了，有了空间就自动恢复。` |
| 熔断 | `10 分钟里崩了 3 次，不再自动恢复。发一条消息就重新启动它。` |
| 没能启动，有消息在等它 | `等着的消息都还在，不用重发。下次来消息时再启动它，到时一起交给它。` |

第二块（作废的提问、不确定的消息）没有就整块不写。

### 6.2 额度用完

两边一样：

```
dispatcher/main 用完了 Claude 额度，19:00 恢复（还有 2 小时 10 分）。
到时它自己接着做。这之间发给它的消息先存着，到时一起交给它。
```

- 额度续跑关着：第二行写 `到时不会自己接着做，要你发一条消息。`
- 这期间你又发了一条：`dispatcher/main 在等额度，19:00 恢复。这条先存着，到时交给它。`

几个槽位碰上同一次额度用完，发到同一个窗口的合成一条。第一个用完后先等 30 秒，这期间用完的都算进来（[产品说明](product.md) §4.6）：

```
Claude 额度用完了，19:00 恢复（还有 2 小时 10 分）。
在等的：dispatcher/main、Rhodium/main、Rhodium/docs。
到时它们自己接着做。这之间发给它们的消息先存着，到时一起交给它们。
```

- 每个 agent 的额度各算各的。写的是这个 agent 的名字，例如“Claude 额度”。合成一条也只合同一个 agent 的槽位。

- 恢复时间写最早恢复的那个。
- 30 秒以后又有槽位用完：两边都另发一条。只有一个槽位，照只有一个槽位的写法。
- 有的槽位额度续跑关着，最后加一行：`Rhodium/docs 到时不会自己接着做，要你发一条消息。`
- 全都关着：第三行写 `到时不会自己接着做，要你发一条消息。`，不加这一行。

### 6.3 切到 TUI

QQ（两条：命令的回复，完成通知）：

```

```

```

[切回无头]
```

Telegram：一条，先是第一句，切完改成第二条的样子。

- Herdr 会话名只在不是 `default` 时写：`在 Herdr rhodium-dev 会话里……`。
- [切回无头] 的数据是 `/rh_release Rhodium/pi`，按下先出确认（§5.2）。

回合还在跑（两边一样）：

```
Rhodium/pi 这一回合还没跑完，跑完就切到 TUI。

[打断，马上切]
```

数据 `/rh_tui !`。

其他：

| 情况 | 写法 |
|---|---|
| 本来就在 TUI 里 | `Rhodium/pi 已经在 TUI 里了。`，按钮 [切回无头]，数据 `/rh_release Rhodium/pi`。Telegram 的按钮行只有 `/rh_tui`（§11.6），切回无头靠这个按钮 |

| 等回合结束时急停了 | `你请求的 rh tui Rhodium/pi 被急停取消了，Rhodium/pi 停着，还是无头模式。` |
| 你在 TUI 里退出 | `Rhodium/pi 切回无头了，接着用你在 TUI 里最后那段对话。` |
| Herdr 重启 | `Herdr 重启了，Rhodium/pi 在 TUI 里的进程没了，已经切回无头。` |
| 切回无头时带回了你在 TUI 里改的设置 | 上面两种通知后面另起一行：`已应用 TUI 中的设置：思考强度 high，ultracode 开。`，只写改了的那几项；换了模型时写显示名：`已应用 TUI 中的设置：模型 Sonnet 5.5。`，pi 的写原值：`模型 deepseek/deepseek-v4-pro` |
| 没能切回无头 | `Rhodium/pi 没能切回无头，这里的消息还不会交给它。` ／ `原因：……`，按钮 [再试一次] |

### 6.4 归档或删除后回到默认

```

```

- 你自己在这个窗口用 `/rh_archive` 归档的，并进命令的回复，不另发。前半句命令回复已经说了，只留后半句：

```

这里的消息改交给 dispatcher/main。
```

- 别的情况发到指着它的窗口：一次性槽位自动归档的，在终端或别的窗口归档的。长期槽位也一样。
- 删除的槽位，“归档了”换成“删除了”。删除不在 IM 里做，所以总是另发：

```
Rhodium/fix-login 删除了，这里的消息改交给 dispatcher/main。
```

### 6.5 回复额度用完，改从别的 Bot 告诉你

```

```

### 6.6 你的消息没交给它

排着的你的消息不再交给 agent 时，单独发一条，引用原文，附 [复制]（§11.5）。例如切到 TUI 时还在等打断生效的（[产品说明](product.md) §4.2）。两边一样：

```

“帮我看下测试为什么挂了”

[复制]
```

第一行按情况换：

| 情况 | 第一行 |
|---|---|
| 切到 TUI | `Rhodium/pi 切到 TUI 了，你排着的这条没交给它，要的话到终端里再发：` |
| 急停 | `Rhodium/pi 急停了，你排着的这条没交给它，需要的话再发一遍：` |
| `rh stop` 或急停时，写过去了它还没收下 | `Rhodium/pi 停下了，这条不确定它收到没有，需要的话再发一遍：` |

- 有几条时写“这 2 条”，每条一个按钮：[复制第 1 条] [复制第 2 条]。
- 发到这几条消息来的窗口，不按联系窗口找。来自几个窗口的，各发各的。
- 不并进“切到 TUI 了”、故障通知这些消息。

## 9. 选择面板

### 9.1 哪些命令有面板，面板怎么走

不带参数时出面板，带参数照旧直接执行：

- `/rh_use`、`/rh_bind`、`/rh_agent`
- `/model`、`/effort`、`/ultracode`、`/resume`
- `/rh_import`、`/rh_archive`
- 所有“是 / 否”的确认（§5.2）
- `/rh_ls`（§8）和 `/status` 下挂的常用按钮（§7.1）

骨架（所有面板一样）：

- 第一行：问题。
- 第二行：`现在：<值>`。
- 要翻页时第三行：`第 1 页，共 3 页。也可以回编号。`
- 按钮。现在的那一项前面加标记：Telegram 加 `✓`，QQ 加 `★`（§2.1）。最后一行是导航：翻页、[返回]，最后是 [取消]。
- 本章的样例都照 Telegram 写，QQ 上把现在那项的 `✓` 换成 `★`。

一个面板走几步，两个平台走法不同：

- Telegram：一条消息走完。按下就编辑这条消息，中间步骤有 [返回]。选完，问题留着，下面写回 `已选：<值>`，需要时再加一句后果，撤掉按钮。
  - 选了以后还有下文的，也在这条里收尾，不另发结果、不留旧按钮：
    - 要等回合结束：后果写在 `已选：` 下面，按钮只剩下文要的那个，例如 [打断，马上换]（§9.4）。
    - 要你确认（§5.2）：确认请求另发一条，这条写回 `已选：<按钮上的字>`，撤掉按钮。
    - 做不成：原因直接写在这条里，撤掉按钮。
- QQ：每一步一条新消息，没有 [返回]。按钮事件自带被动回复额度（[架构](architecture.md) §8.1），不花你那条消息的额度。选完新发一条结果句。按过的按钮显示 `✓ 原文字`。

按了现在的那一项（Telegram 上带 `✓`、QQ 上带 `★` 的），什么也不做，只说一句“本来就是”：

- QQ 回这一句，例如 `w/a 本来就是 pi，没有改动。`、`这里的消息本来就交给 w/b，没有改动。`、`这个 Bot 的默认槽位本来就是 w/a，没有改动。`
- Telegram 照常写回 `已选：<值>`，下面加这一句。
- 只管 `/rh_use`、`/rh_bind`、`/rh_agent`。`/model` 按现在的模型照常进第二步（§9.5）；`/effort`、`/ultracode`、`/resume` 设回原值、回到原对话，本来就没有改动。

面板开着，指还没选完、也没取消。退出面板有两种：

- 按 [取消]。每个面板都有，包括 `/rh_ls`、槽位详情和 `/status`。确认的 [取消] 怎么回见 §5.4。
  - Telegram：原来的文字留着，去掉页码那行，下面写回 `已取消`，撤掉按钮。
  - QQ：回一句 `已取消，没有改动。`
- 面板开着时，你在这个窗口发了命令（`/` 开头的消息）。按这个面板自己的按钮不算。Telegram 和按了 [取消] 一样改，QQ 不另回。
  - `/status` 例外：它也有 [取消]，但不算开着的面板。打命令不退出它，下面的按钮照样能按。

退出以后：

- 多步面板里，前面已经生效的步骤不撤回，也就不写“已取消”。例如 `/model` 第二步退出时，模型已经换了：Telegram 写回 `已选：Opus 4.5，思考强度还是 high`，QQ 按 [取消] 回 `思考强度还是 high。`（§9.5）。
- 回的数字不再算选面板（§11.4）。QQ 旧消息上的按钮照样有效（§11.3）。
- 发命令就会退出，所以一个窗口最多开着一个面板。

候选从哪来：

- 每条有面板的命令，在命令定义里带一个“列候选”的函数。它给出每个候选的显示文字、按下发的命令、是不是现在的那个。
- 分页、编号、按钮排布、现在那项的标记，由各平台的渲染统一做，命令自己不管。
- 以后网页上的选择面板也用同一份候选。

### 9.2 `/rh_use`

- 第一项永远是默认：
  - 跟着默认走时：`✓ 默认（dispatcher/main）`，QQ 上是 `★ 默认（dispatcher/main）`。
  - 单独选过别的时：`回到默认（dispatcher/main）`，数据 `/rh_use -`。
- 默认目标那个槽位，后面不再列一次。
- 现在的那一项前面加 `✓`，QQ 上加 `★`（§9.1）。
- 顺序：默认；这个窗口目标所在工作区的槽位；其他工作区。工作区之间、工作区里都按名字排，不分大小写。位置不跟状态跳。

一页放得下（不编号、不写页码。QQ 上 `✓` 换成 `★`，别处一样）：

```
[回到默认（dispatcher/main）]

[✓ Rhodium/pi]
[取消]
```

要翻页（QQ 上同样换成 `★`，例如 `[★ 4. Rhodium/pi]`）：

```

现在：Rhodium/pi
第 1 页，共 2 页。也可以回编号。

[1. 回到默认（dispatcher/main）]
[2. Rhodium/docs] [3. Rhodium/main]
[✓ 4. Rhodium/pi] [5. shop/api]
[6. shop/bench] [7. shop/docs-site]
```

```
第 2 页，共 2 页。也可以回编号。
```

## 10. `/rh_help` 和错误提示

### 10.1 `/rh_help`

`/rh_help` 是 Rhodium 的首页：第一行写这里交给谁，下面每个 Rhodium 功能一个按钮。不再列命令清单。两边一样，QQ 上照常没有 Markdown：

```
这里的消息交给 dispatcher/main，用 Claude。

[槽位] [切换] [切到 TUI] [换 agent]
[改名…] [归档] [导入] [默认槽位]
[工具行详略]
[取消]
```

- 第一行：
  - 有目标：`这里的消息交给 <槽位>，用 <agent>。`，agent 写显示名。
  - 没有目标：`这里还没指定槽位。`，按钮里没有 [切到 TUI]。
- 槽位在 TUI 里时，[切到 TUI] 换成 [切回无头]。两个只给一个。
- 按钮数据：

  | 按钮 | 数据 |
  |---|---|
  | 槽位 | `/rh_ls` |
  | 切换 | `/rh_use` |
  | 切到 TUI | `/rh_tui` |
  | 切回无头 | `/rh_release`，按下先确认（§5.2） |
  | 换 agent | `/rh_agent` |
  | 改名… | QQ 是填字按钮，把 `/rh_rename ` 填进输入框；Telegram 是 `/rh_rename`（§9.9） |
  | 归档 | `/rh_archive` |
  | 导入 | `/rh_import` |
  | 默认槽位 | `/rh_bind` |
  | 工具行详略 | `/rh_verbose`，在详细和简略之间切换（§3.5） |
  | 取消 | `cancel` |

- 9 个功能按钮一页放下，不翻页，不编号。这是“一页最多 8 个”（§11.2）唯一的例外。3 行功能加 1 行 [取消]，QQ 一条最多 5 行，放得下。
- 按下以后和 `/status` 下面的按钮一样（§7.1）：Telegram 上这条原地变成对应的面板，最后一行有 [返回]，数据 `/rh_help`；QQ 新发一条。没有面板的（切到 TUI、工具行详略），照 §9.1 收尾。
- 和 `/status` 一样，它不算开着的面板：打命令不退出它，下面的按钮照样能按，回数字也不算选它。
- agent 的命令不在这里，在 `/` 菜单里，各带一句说明。
- 长说明不放这里，ssh 里 `rh --help` 有。

`/` 菜单里每项的说明：

- 不超过 12 个字，取自命令定义，和网页的命令面板共用。
- `/rh_help` 的说明是 `Rhodium 的功能`。

### 10.2 错误提示

先说哪里不对，再说怎么办。能给选项的直接给面板。不贴 `<工作区/槽位>` 这种语法，给一个例子。

| 情况 | 写法 |
|---|---|
| 没有这条命令 | `没有 /rh_x 这个命令，发 /rh_help 看有哪些。` |
| 参数不对，包括不认识的 `--` 选项 | 按 IM 里的写法给一个例子：`/rh_release 后面只写槽位，例如 /rh_release shop/api；不写就是这里的槽位。` 不回 `rh` 的用法，也不回英文报错。所有 `/rh_` 命令都这样，例子取自命令定义 |
| agent 写错 | `没有叫 gpt 的 agent，选一个：`，下面 [Claude] [pi] |
| 槽位不存在 | `找不到 Rhodium/foo，选一个：`，下面是这条命令的面板 |
| 重名 | `有 2 个槽位叫 main，选一个：`，下面 [dispatcher/main] [shop/main] |
| 这里没有目标 | `这里还没指定槽位，选一个：`，下面是 `/rh_use` 面板 |
| 命令没完成 | `没换成。` ／ `原因：……` |
| 还在启动 | `dispatcher/main 还在启动，过几秒再试。` |
| 归档 Bot 的默认目标 | `dispatcher/main 是 QQ Bot 的默认目标，先用 /rh_bind 换一个再归档。` 几个 Bot 都以它为默认目标时都列出，用“、”隔开（[产品说明](product.md) §5.2） |

被拒收（消息没交给 agent），一律先说“这条没交给它”：

| 情况 | 写法 |
|---|---|
| TUI 模式 | `Rhodium/pi 在 TUI 里，这条没交给它。发 /rh_use - 改和 dispatcher/main 说，或者发 /rh_release 把它切回无头。`，按钮 [切回无头] [换一个槽位] |
| Herdr 在重启 | `Herdr 正在重启，这条没交给 Rhodium/pi。等一会儿再发。` |
| 磁盘快满 | `磁盘只剩 3.2 GB，这条没交给 dispatcher/main。清出空间再发。` |
| 回答提问时带了图片 | `Rhodium/pi 在等你回答提问，图片和文件不能当回答，这条没交给它。先用文字回答，再发一遍。` |

TUI 模式那句：

- 照旧拒收，但写清下一步的两条命令。这里有按钮也写命令，是原则 6 的例外。
- `dispatcher/main` 是这个 Bot 的默认目标。这个窗口本来就跟着默认、在 TUI 里的就是默认目标时，没有 `/rh_use -` 那半句：`dispatcher/main 在 TUI 里，这条没交给它。发 /rh_release 把它切回无头。`
- `/status` 照常回答（§7.1），`/rh_` 命令照常执行。别的通用命令照旧拒收，回同一句。

## 11. 按钮

### 11.1 文字

- 选项按钮写选项本身：`Opus 4.5`、`Rhodium/pi`、`staging`。
- 动作按钮写动词短语，2–6 个字：`切到 TUI`、`切回无头`、`停止`、`归档`、`开新对话`、`打断，马上切`。
- 不写斜杠命令：写“换模型”，不写 `/model`。Telegram 的按钮行例外（§11.6）。
- 现在的那项前面加 `✓ `，QQ 上加 `★ `（§2.1）。QQ 按过的按钮自己显示 `✓ 原文字`。别的按钮不加符号。
- 要翻页的列表，按钮前加编号：`8. shop/fix-login`。标记在编号前：`✓ 4. Rhodium/pi`、`★ 4. Rhodium/pi`。
- 回答 agent 的请求，沿用它的问法：[允许] [拒绝]、[批准] [不批准]、[同意] [拒绝]。你自己发起的，用动作加取消：[切回无头] [取消]。
- 导航：[上一页] [下一页] [返回]，面板最后是 [取消]（§9.1）。不用箭头。
- 按了还要你接着打字的，以“…”结尾：[自己起名…]。
- 离开正文也看得懂。不要 [是] [否]、[1] [2]。

### 11.2 排布

按字宽算：汉字和全角标点算 2，英文字母、数字、半角符号算 1。

| 一行几个 | 每个最多几个字宽 |
|---|---|
| 1 个 | 36 |
| 2 个 | 18 |
| 3–4 个 | 9 |
| 5 个 | 不用 |

- QQ 先用和 Telegram 一样的数，真机实测后再改（§13）。
- 名字类按钮（槽位、模型、对话）按顺序排：相邻两个都不超过 18，就并成一行；否则单占一行。
- 同一组的短按钮挤进最少的行：思考强度一行，是和否一行。
- 一页最多 8 个、最多 4 行，再加一行导航（翻页、[返回]、[取消]）。QQ 一条消息最多 5 行按钮（[架构](architecture.md) §8.1），正好放下。
- 单占一行还超过上限的，截断加“…”。槽位名先截工作区那半：`shop-ba…/fix-login`。
- 顺序：选项按列表顺序，现在那项不挪；动作按常用程度，会结束东西的放最后；是在左，否在右；最后一行是导航。
- QQ 颜色（`render_data.style`）：选项和主动作蓝色（1）；取消、返回、翻页灰色（0）。

### 11.3 按下以后

| | Telegram | QQ |
|---|---|---|
| 结果在哪 | 改被按的那条，文字和按钮一起换 | 对这次按下的被动回复，新发一条 |
| 多步面板 | 同一条往下走，中间步骤写 `已选：X`，有 [返回] | 每步一条新消息，没有 [返回]。旧按钮按了照样有效 |
| 选完 | 写回 `已选：X`，撤掉按钮 | 新发结果句；按过的按钮显示 `✓ 原文字`，不带 `★` |
| 翻页 | 原地换按钮和页码 | 新发一条，只有页码和这一页的按钮 |
| 取消 | 原文下面写回 `已取消`，撤掉按钮 | 回一句 `已取消，没有改动。` |
| 弹出提示 | 只在失效或出错时弹 | 没地方弹，改发一句 |

### 11.4 按钮数据和回编号

| 种类 | 数据 | 有效期 |
|---|---|---|
| 面板选项、动作 | 命令原文，例如 `/rh_use shop/api` | 一直有效 |
| 回答提问 | `ask:<提问 ID>:<序号>` | 提问了结就失效 |
| 从几条提问里挑 | `pick:<提问 ID>` | 提问了结就失效 |
| 翻页 | `page:<页码>:<命令>` | 一直有效 |
| 回到默认 | `/rh_use -` | 一直有效 |
| 工具行开关 | `/rh_verbose on`、`/rh_verbose off` | 一直有效 |
| 面板的 [取消] | `cancel` | 一直有效。退出这个窗口开着的面板，没有开着的就只回那一句 |

- Telegram 的 `callback_data` 最多 64 字节。超了，槽位换成它的短 ID（库里的行 ID），不换成编号。QQ 用同样的数据。
- 回编号：
  - 只有要翻页的面板才编号。编号跨页连续。
  - 你回数字之前，这个窗口里最新的一条消息是这个面板，数字才算选面板。你发的、发给你的都算；QQ 翻页新发的那条算同一个面板。
  - 面板之后这里又有了别的消息，数字就照常交给 agent。例如 agent 说了话、来了通知。Telegram 上，面板之后过程消息里多了 agent 的话，也算。
  - 面板退出了（§9.1），数字也照常交给 agent。
  - 有提问在等你时，数字先当提问的回答。
  - 面板里没有的编号，照常交给 agent。

### 11.5 复制按钮

消息里引用了一段你发过、但不确定 agent 收到没有的话（例如 §6.1 崩溃通知），附一个 [复制] 按钮，方便你再发一遍：

- Telegram：inline 按钮用 `copy_text`，按下把全文复制到剪贴板。
- QQ：指令按钮（`action.type` 2，`enter` 为 false），按下把全文填进输入框，不发出。
- 平台不支持时，把那段话单独发一条，方便长按复制。例如：
  - Telegram 的 `copy_text` 最多 256 字，超了就单独发。
  - QQ 指令按钮实测填不进输入框，或者数据太长被拒。
- QQ 拒收 Markdown、改发纯文本时，按钮显示不出来，全文写在正文后面一行：`复制：原文`（§2.2）。
- 正文里的引用截到 60 字（§2.5），按钮和单独发的那条放全文。

### 11.6 按钮行

按钮行是输入框旁边常驻的一排按钮，放 Rhodium 的功能。放哪些、怎么排，见[产品说明](product.md) §5.7。这里只定写法。

QQ（输入框上方）：

```
[停止] [槽位] [切换] [换 agent] [帮助] [终端] [更多]
```

- “终端”“更多”是折叠的按钮，点开是子按钮：
  - 终端：[切到 TUI] [切回无头]
  - 更多：[改名] [归档] [导入] [默认槽位] [工具行详略]
- 写中文，和面板里的动作按钮同一套说法（§11.1）。名字都在平台的上限里：一级最多 5 个汉字，子按钮最多 7 个。
- 按钮行上的“改名”不带“…”：它发出不带参数的 `/rh_rename`，回一个例子（§9.9）。
- 全平铺的那份备着，现在没用上（折叠的显示正常，§13 第 10 条）。真要退回平铺，按产品说明的顺序排，去掉“默认槽位”和“工具行详略”：

  ```
  [停止] [槽位] [切换] [换 agent] [帮助] [切到 TUI] [切回无头] [改名] [归档] [导入]
  ```

Telegram（输入框下面一行）：

```
[/rh_ls] [/rh_use] [/rh_tui] [/rh_help]
```

- 按钮上写命令本身。按下就以你的名义把这段字发出来，聊天里多一条你发的 `/rh_ls`，和手打的一样处理。
- 它随一条短消息发下来，配对后和内容变了时各发一次：

  ```
  常用按钮放在输入框下面了。
  ```

  - 配对时这一句跟在“已配对”后面，另起一条。
  - 你发 `/start` 时也再发一次（[产品说明](product.md) §5.7）。
  - 这条不带 inline 按钮。
