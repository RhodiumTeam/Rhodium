# IM 按钮行规格

这篇回答：把 IM 里常驻的按钮和 `/` 菜单按“谁提供的”分开，要做成什么样、满足哪些需求、怎么测、怎么验收、明确不做什么，以及怎么拆工单。

前置阅读：[术语表](../../GLOSSARY.md)、[产品说明](../product.md)、[架构](../architecture.md)、[IM 文字与交互规范](../im-style.md)、[v1 规格](v1.md)

这件事在 2026-10-24 的拷问里定下。放哪些按钮、怎么排写在[产品说明](../product.md) §5.7，怎么推写在[架构](../architecture.md) §8.4，按钮上的字和 `/rh_help` 的样子写在[IM 规范](../im-style.md) §10.1、§11.6。这里不重复，只写需求、要改的代码、测试和交付。

这篇用到两个新词，见术语表：

- [按钮行](../../GLOSSARY.md)：输入框旁边常驻的一排按钮。
- [`/` 菜单](../../GLOSSARY.md)：打 `/` 时弹出的命令列表。

## 问题

**两处放的是同一份清单。**

- QQ 输入框上方那一排和 `/` 弹出的列表，都从同一个优先级里截：前 10 个进那一排，前 20 个进列表。
- 两边都是 Rhodium 的命令和 agent 的命令混着放。

**列表装不下了。**

- Claude 槽位有 21 个命令，QQ 的 `/` 列表最多 20 项，`/rh_rename` 被挤掉了。

**那一排跟着 agent 跳。**

- 换到 pi，那一排少了 `/usage`，`/context` 补进来，按钮的位置就变了。
- 每次换 agent 两样一起推。QQ 改那一排每分钟只能 5 次。

**Telegram 上没有常驻的按钮。**

- 只有 `/` 菜单。看槽位、切换都要打命令或者翻列表。

**`/rh_help` 只是一段字。**

- 列着 20 个命令，看完还要自己打。

## 方案

- 按钮行只放 Rhodium 的功能，外加一个“停止”，不随 agent 变：
  - QQ：平铺“停止、槽位、切换、换 agent、帮助”，折叠的“终端”和“更多”里放其余的。
  - Telegram：新做一行 4 个常驻按钮，按钮上直接写命令：`/rh_ls`、`/rh_use`、`/rh_tui`、`/rh_help`。
- `/` 菜单只放 agent 的命令，最后一个 `/rh_help`，跟着窗口目标的 agent 变。Claude 槽位 11 项，pi 槽位 10 项（pi 的 `/usage` 2026-10-24 起也列，见[产品说明](../product.md) §5.7）。
- 两样分开记哈希，换 agent 只推 `/` 菜单。
- `/rh_help` 变成 Rhodium 的首页：第一行写这里交给谁，下面每个功能一个按钮。
- 手打的 `/rh_` 命令照旧能用。

QQ，手机上大致是这样：

```
[停止] [槽位] [切换] [换 agent] [帮助] [终端] [更多]   ← 按钮行，“终端”“更多”点开是子按钮
┌──────────────────────────────────────────────┐
│ /                                              │   ← 打 / 弹出 agent 的命令
└──────────────────────────────────────────────┘
```

Telegram：

```
┌──────────────────────────────────────────────┐
│ ☰  消息                                        │   ← ☰ 是命令列表，打 / 也是它
└──────────────────────────────────────────────┘
[/rh_ls] [/rh_use] [/rh_tui] [/rh_help]              ← 按钮行，收起键盘时露着
```

## 实现决定

### 命令定义

- `/` 菜单在 `src/commands.ts` 的 `IM_COMMANDS` 里挑：名字不以 `rh_` 开头、这个 agent 用得了的，照原顺序，最后加 `rh_help`。挑法和网页命令面板的 `commandsFor`（#293）一样，两处共用一个函数。
- 没有 agent 时（窗口没有目标、网页上槽位没有 agent），只挑没有 `agents` 限制的，和现在的 `menus()` 一样。网页命令面板现在会把只有 Claude 有的也列出来，跟着改。
- `IM_COMMANDS` 不再是菜单的优先级，只是 `/` 菜单的顺序。上面的注释跟着改。
- `rh_help` 的说明改成 `Rhodium 的功能`。
- 按钮行和 `/rh_help` 首页的按钮也在 `src/commands.ts` 定义，一处写字和命令：
  - QQ 按钮行：5 个平铺，加两个折叠的，每个按钮是中文名字加命令。另有全平铺的 10 个，备着不用。
  - Telegram 按钮行：4 个命令。
  - 首页：9 个功能按钮（[IM 规范](../im-style.md) §10.1）。
- `imHelpText` 删掉。`rh --help`、`rh --skill` 不变。

### 推送

- `src/router.ts` 的 `menus()` 给每个 Bot 分开交出两样：按钮行和 `/` 菜单，各带要推到的窗口。
  - Telegram 的 Bot 没配对时两样都不交，和现在一样。交给程序的 Bot 照旧跳过。
- `src/daemon.ts` 的 `syncMenus()` 两样各算各的哈希，各记各的失败。哈希连同窗口一起算。
- `src/store.ts` 加一条迁移：`bot` 表加一列 `rowHash`。原来的 `menuHash` 只管 `/` 菜单。
  - 升级后两样的内容都和库里的对不上，各推一次。Telegram 上这就是第一次发按钮行。
  - 以后做去掉 Bot（`rh bot rm`，[架构](../architecture.md) §14.8）时，和 `menuHash` 一起清掉。
- 适配器契约（`src/contracts.ts`）：
  - `setMenu(items, chat, panel)` 拆成推按钮行和推 `/` 菜单两个方法。
  - 能力表的 `menu` 跟着改：`/` 菜单的上限（QQ 20、Telegram 100），按钮行是哪一种（QQ 的自定义菜单、Telegram 的回复键盘）。不再有“前 10 个”的截取。
  - 第一张工单里，Telegram 的能力表写“没有按钮行”，`menus()` 不给它交按钮行，也不记它的 `rowHash`。第三张再打开。不然第一张里空推一次就把哈希记上，第三张合进来以后内容没变，就再也不推了。

### QQ

- `src/qq.ts` 推按钮行：`PUT /v2/menu`，平铺的是 `send_message`，折叠的是 `menu` 带 `sub_menu_items`（[架构](../architecture.md) §8.4）。
- 指令面板照旧找备注为 `rhodium` 的那个，只是内容换成 `/` 菜单。
- 2026-10-24 在手机上看过：按下直接发出命令，折叠的点得开，改了以后顺利换上（[产品说明](../product.md) §5.7，[IM 规范](../im-style.md) §13 第 10、11 条）。所以推平铺加折叠的那份，全平铺的那 10 个不用。

### Telegram

- `src/telegram.ts` 推 `/` 菜单：照旧 `setMyCommands` 带 `scope: chat`。
- 推按钮行：往你的私聊发一条短消息，`reply_markup` 是回复键盘，一行 4 个，`is_persistent`、`resize_keyboard` 都开。字见 [IM 规范](../im-style.md) §11.6。
  - 这条由适配器直接发，和推 `/` 菜单一样，不走出站队列，不进消息记录。
  - `syncMenus()` 推它之前，先等 `sending` 那条链上已经排着的发完，再过 `pace(chat, adapter)`（[架构](../architecture.md) §8.4）。配对提交以后 `stepped()` 马上就调 `syncMenus()`，而“已配对”走 `queueSend`，要先等 `pace`；不这样等，两条谁先到说不准，也会跳过同一聊天约每秒 1 条的间隔。
- 收到 Telegram 上的 `/start`，路由把这个 Bot 的 `rowHash` 清空，下一次 `syncMenus()` 就重推按钮行。清空聊天记录以后，客户端给的“开始”按钮发的就是 `/start`，按下按钮行就回来了。`/start` 其余照旧，作为透传命令交给 agent。
- 按下按钮发来的就是一条 `/rh_ls` 这样的命令，路由不用改。

### 首页和别的回复

- `/rh_help` 照 `/status` 的按钮那样排，不走分页，所以 9 个按钮不受一页 8 个的限制。
  - 按钮在 Telegram 上原地换成对应的面板，带 [返回]，和 `/status` 一样。
  - 它不算开着的面板，和 `/status` 一样。
- “改名…”用现有的填字按钮（`Candidate.fill`），Telegram 上自动退回普通按钮。
- `/rh_tui` 遇到已经在 TUI 里的槽位（`src/router.ts` 里回“已经在 TUI 里了”那一句），下面加 [切回无头]。

### 要改的文档

产品说明 §5.6、§5.7，架构 §8.1、§8.4，IM 规范，术语表已在这次改好。手机上看的结论已写回产品说明 §5.7、架构 §8.4 和 IM 规范 §13。

## 测试决定

照 [v1 规格](v1.md#测试决定)的规矩：只测外部看得到的行为，测试名带故事编号。

- 命令定义：
  - Claude 的 `/` 菜单是那 11 项、照顺序，pi 的是 10 项。除了最后的 `/rh_help`，没有 `rh_` 开头的。
  - 网页命令面板和 IM 的 `/` 菜单，除了 `/rh_help` 一样。
  - 没有 agent 时，两处都和 pi 槽位一样，没有 `/ultracode`。
  - QQ 按钮行在平台的上限里：一级不超过 10 个，每个折叠的不超过 5 个；名字一级不超过 10 个字符、子按钮不超过 14 个，汉字算 2 个。全平铺的那份也不超过 10 个。
- 整机测试，用假 IM：
  - QQ 样子的 Bot：起来后推一次按钮行、一次 `/` 菜单。`/rh_agent pi` 以后只推 `/` 菜单，按钮行没再推，`/` 菜单少了 `/ultracode`。
  - 按钮行推失败，过了重试时间随下一个输入只重推它，`/` 菜单不重推。重启以后两样都不重推。
  - Telegram 样子的 Bot：没配对时什么都不推。配对以后，先收到“已配对”，再收到带按钮行的那条。再配对给另一个账号，按钮行推给新窗口。
  - Telegram 样子的 Bot：发 `/start` 以后，按钮行那条再收到一次；`/` 菜单不重推。
  - 交给程序的 Bot 两样都不推。
  - 手打 `/rh_rename`、`/rh_verbose` 等不在 `/` 菜单里的命令照旧执行。
- 适配器，用假的平台接口：
  - QQ：`PUT /v2/menu` 的内容里，平铺的是中文名字加命令，“终端”“更多”是 `menu` 带子按钮；指令面板 11 项。
  - Telegram：`setMyCommands` 带这个窗口的范围；按钮行是一条消息，带一行 4 个按钮的回复键盘，开着 `is_persistent` 和 `resize_keyboard`，没有 inline 按钮。
- `/rh_help`：
  - 有目标时第一行写槽位和 agent；没有目标时写“这里还没指定槽位。”，没有 [切到 TUI]；槽位在 TUI 里时是 [切回无头]。
  - 9 个功能按钮加 [取消]，一页，不编号。
  - QQ 上“改名…”是填字按钮。Telegram 上按“槽位”，这条原地变成 `/rh_ls` 的面板，最后一行有 [返回]。
  - 打一条命令以后，首页的按钮照样能按。
- 对已经在 TUI 里的槽位发 `/rh_tui`，回复带 [切回无头]，数据 `/rh_release <槽位>`。

## 你来验收

2026-10-24 你在正式环境 1.0.0-67523b1 上看过按钮行、折叠的按钮、`/` 菜单和 Telegram 按钮行的几条，都对（[IM 规范](../im-style.md) §13 第 10 到 12 条）。

在开发 Bot 上，手机 QQ：

- 按钮行是“停止、槽位、切换、换 agent、帮助、终端、更多”。点开“终端”“更多”，子按钮都在。
- 点“槽位”，出 `/rh_ls` 的面板。
- 打 `/`，列表是 agent 的 11 个命令加 `/rh_help`。`/rh_agent pi` 以后再打 `/`，少了 `/ultracode`；按钮行没变。
- 点“帮助”：第一行写着这里交给谁，下面是 9 个按钮。按“改名…”，`/rh_rename ` 填进了输入框。
- 回合在跑时点“停止”，停下。

手机 Telegram：

- 升级后收到一条“常用按钮放在输入框下面了。”，输入框下面是 4 个按钮。收起系统键盘，它还露着。
- 按 `/rh_ls`，出面板。之后来一条带按钮的消息（例如 `/status`），按钮行还在。
- 打 `/` 或点左边的菜单按钮，是 agent 的命令加 `/rh_help`。
- 清空和 Bot 的聊天记录，按“开始”：又收到那条，按钮行回来了。
- 把一个槽位切到 TUI，再按 `/rh_tui`：回复下面有“切回无头”。

## 不做的事

| 不做的事 | 什么时候再说 |
|---|---|
| agent 自己的命令和 skill 进 `/` 菜单 | 以后另开工单。要先存下 agent 启动时报的命令清单，网页的命令面板也一样 |
| Telegram 的菜单按钮改成在 Telegram 里打开网页 | 不做。网页只在 tailnet 里能开，还要校验 Telegram 的登录，是另一件事 |
| Telegram 按钮上写中文，Rhodium 把中文认成命令 | 不做（2026-10-24 定）。按钮上直接写命令 |
| QQ 的开关按钮（`switch`）用来开关工具行详略 | 按需。按下以后 Bot 收到什么，文档没写 |
| 群聊里的按钮行和 `/` 菜单 | 随群聊。QQ 群没有按钮行；指令面板到时按 agent 分、只挂给指定的群 |
