# 查询命令规格

这篇回答：`/status`、`/usage`、`/context` 这类查询命令，在网页和 IM 上要做成什么样、满足哪些需求、怎么测、怎么验收、明确不做什么，以及怎么拆工单。

前置阅读：[术语表](../../GLOSSARY.md)、[产品说明](../product.md)、[架构](../architecture.md)、[IM 文字与交互规范](../im-style.md)、[v1 规格](v1.md)、[网页能写规格](web-write.md)、[IM 按钮行规格](im-buttons.md)

这件事在 2026-10-24 的第 31 轮拷问里定下。各项事实写在上游，这里不重复，只写需求、要改的代码、测试和交付：

- 每条命令显示什么：[产品说明](../product.md) §5.6。
- 网页上查询结果放在哪：[产品说明](../product.md) §7。
- 数据从哪来、结果是什么形状、IM 怎么发 Markdown：[架构](../architecture.md) §6.1、§6.2、§6.3、§8.2。
- IM 里每个字怎么写：[IM 规范](../im-style.md) §2.2–§2.5、§7、§8、§9.5、§9.6。

这篇用到几个词：

- 查询命令：只给你看信息、不做动作的命令：`/status`、`/usage`、`/context`，以及 `/rh_ls` 的列表和槽位详情。
- [信息卡](../../GLOSSARY.md)：网页对话页上浮在输入框正上方的卡片，见术语表。
- 轻提示、选择单、操作条：见[网页能写规格](web-write.md)开头。
- 当前对话：这个槽位现在这段对话，用量从它开始算起，见[产品说明](../product.md) §5.6。

## 问题

**网页按行数挑框子。**

- 多于一行的进底部单子，一行的进轻提示。Claude 的 `/usage` 是单子，pi 的 `/usage` 和 `/context` 是 3 秒就消失的轻提示。
- 轻提示带 ✓，像是做完了一件事，用在查询结果上不对。

**宽屏上单子对不齐。**

- 单子挂在整页上，居中于整个窗口。左边是列表或拓扑图时，它横在中间，盖住输入框的左半边，整页还模糊。
- 轻提示却在对话那一栏里。

**网页拿 IM 的句子拆行显示。**

- 第一行做大字，其余做灰字。5 小时那行看着是主角，其实快满的是 7 天那行。

**`/usage` 少，又难读。**

- 每个窗口一句长句，手机上折两行，百分比埋在句子中间。
- Claude 另外返回的窗口（例如某个模型单独的 7 天额度）丢了。
- 没有这段对话用了多少。pi 上只回一句“没有额度可查”。

**`/status` 和 `/context` 说法不一样。**

- `/context` 写百分比，`/status` 只写 token 数。
- `/status` 运行中不写跑了多久、在跑哪个工具。默认模型写成英文的“Default (recommended)”。

**“现在：”时有时无。**

- Claude 还没跑过回合时，`/model` 面板没有“现在：”。pi 的 `/resume` 列表也没有。

**Telegram 上都是纯文本。**

- IM 规范说 Rhodium 的话在 Telegram 上发 rich message、目录放进行内代码，实际一直发纯文本。

## 方案

- 每个 agent 给结构化的数据，路由按去处排：
  - IM 排成 Markdown：`##`、`###` 标题分节，行首的数字加粗。QQ 和 Telegram 都发它，拒收时改发纯文本。
  - 网页画成信息卡：进度条、对齐的数字、能点开的明细。
- 网页上，查询结果和选择单都放进信息卡，浮在输入框正上方，只占对话那一栏。轻提示只给动作的回执和出错。
- `/usage` 加上 Claude 另外返回的窗口和当前对话的用量；pi 上只有当前对话。
- `/status` 照给定的样子分节，上下文和 `/context` 同一个数；额度快满时多一节。

IM 里，Claude 槽位的 `/usage`（两边都是这份 Markdown）：

```
## Claude 额度
**28%** 5h，1h 46m 后重置
**91%** 7d，9h 26m 后重置
**38%** 7d Fable，9h 26m 后重置

## 当前对话
**$15.35** 等效 API 价格
**18.9M** 总 Tokens 消耗
```

网页上，宽屏时：

```
列表或拓扑图  │ 对话记录
              │ ┌ 用量 ─────────────────── ✕
              │ │ Claude 额度
              │ │ 5 小时     28%   ↻ 1 小时 46 分
              │ │ ▓▓▓░░░░░░░
              │ │ 7 天       91%   ↻ 9 小时 26 分
              │ │ ▓▓▓▓▓▓▓▓▓░   ← 琥珀色
              │ │ 当前对话
              │ │ 费用     $15.35   等效 API 价格
              │ │ Tokens    18.9M   ›
              │ └────────────────────────
              │ [ 输入框，照样能打字 ]
```

信息卡只在右边对话这一栏，左边不挡。

## 实现决定

### 这些没单独问，直接定了

第 31 轮里没单独问、直接定的。要改的话，都只动一处：

- 额度的重置时间 24 小时内写还剩多久，再远写时刻；时刻已经过了写“已重置”。
- Telegram 上查询回复发 rich message，目录放进行内代码。Rhodium 别的话（通知、提问、面板）这次不动。
- Claude 进程被强杀或崩溃时，那个进程用掉的部分不计入当前对话，也不另外标出。

第 31 轮开头列过、没被反对的，照做：

- 两边用同一份数据，网页不再拿 IM 的句子拆行。
- `/status` 和 `/context` 的上下文都带百分比，写法统一。
- 默认模型写“默认（Opus 5.5）”。
- `/model`、`/resume` 总写“现在：”。
- 网页 `/status` 里点“模型”开操作条上的模型卡片；`/rh_ls`、`/rh_help` 直接带你去；pi 上 `/ultracode` 回“pi 没有 ultracode。”。
- `/context` 在 IM 上也带“压缩上下文”。

写规格时顺带定的：

- 上下文不到 1% 写 `<1%`，不写 `0%`。
- `/status` 的额度那一节只在 Claude 进程在跑时有：`/status` 不拉起 agent，额度又只有进程问得到。
- `/status` 第二行用看板的状态词（需要你、运行中……），给定的样子就是这样。
- pi 的费用那行只有金额，不加说明，和演示一样。
- `Agent：` 写 `Claude Code`、`Pi`，上下文的约数用半角括号和 `~`，照备注里的原样。
- `/context` 只有一行，不加标题。`/rh_help` 首页和各个选择面板照旧，不加标题：它们第一行是问句或一句话，下面是按钮。
- pi 的 `/usage` 有了内容，所以 `/` 菜单和命令面板里 pi 槽位也列它，pi 的 `/` 菜单从 9 项变成 10 项。

### 数据

结果的形状见[架构](../architecture.md) §6.1。代码上：

- `src/contracts.ts` 的 `CommandResult`：
  - `usage`：`limits` 改成窗口列表，每项有窗口的类（5 小时、7 天）、限定的模型、百分比、重置时间；加 `extra`（额外用量，开着才有）和 `session`（费用、四类 token 和合计、Claude 按模型分的那份）。
  - `context`：加 `categories`，只有 Claude 给。
  - `status`：`usage` 换成 `context`（和 `/context` 同形），加 `limits`（Claude 进程在跑时才有）。
- `src/claude.ts`：
  - `usage` 照[架构](../architecture.md) §6.2 读 `rate_limits.limits`、`extra_usage` 和 `session`。没有 `limits` 列表的旧版 CLI 照旧读 `five_hour`、`seven_day`。
  - `context` 带上 `get_context_usage` 的 `categories`：只列占着上下文的；认得的 `id` 换成中文名（消息、工具、系统提示、技能、自动压缩预留），认不得的写原名。
  - `status` 在进程活着时发 `get_context_usage` 和 `get_usage`，两个都不花额度。
  - 默认模型的实际名字取自模型列表里 `default` 那项的 `description`（[架构](../architecture.md) §6.1）。
- `src/pi.ts`：`usage` 读 `get_session_stats` 的 `tokens` 和 `cost`，`limits` 为空；`status` 的上下文也取自它。
- `src/commands.ts`：`/usage` 去掉只给 Claude 的限制，说明改成“看额度和当前对话的用量”。

### IM

- `src/im-commands.ts`：
  - 查询命令的格式化给出两份：Markdown 和纯文本（[架构](../architecture.md) §8.2）。纯文本由 Markdown 那份去掉标题记号和粗体得到，不另写一遍。
  - 几个纯函数：token 数（k、M）、金额、窗口名（5h、7d、7d Fable）、重置时间（短写的剩多久、时刻、已重置）、百分比（`<1%`）。写法见 [IM 规范](../im-style.md) §2.4。
  - `statusText()` 照 IM 规范 §7.1 重写。上下文那行和 `/context` 用同一个函数，只是不加粗。现在锁住“没有百分比”的测试（`test/im-commands.test.ts`）跟着改。
- `src/router.ts`：
  - `headline()` 拆成两样：标题（槽位全名）和状态行。`/status` 和槽位详情都用它们。
  - 运行中跑了多久：槽位记下回合开始的时间，回合结束时清掉。正在跑的工具取自回合进度（[架构](../architecture.md) §7.1）；回合没有进度时不写这一行。
  - `answer()` 发查询回复时，出站消息带上 Markdown 那份。QQ 带按钮时用它，不再转义成原样。
  - `/context` 的回复带 [压缩上下文]，数据 `/compact`。
  - `/model` 面板的 `现在：` 从槽位记下的模型来，还没跑过回合也写；什么都没记，现在的就是默认。pi 的 `/resume` 候选标出现在那段。
  - `lsPanel()`、`slotPanel()` 照 IM 规范 §8 加标题。
- `src/telegram.ts`：查询回复照 Markdown 那份发 rich message。转义照[架构](../architecture.md) §8.2：格式只来自模板，拼进来的值两个平台都转义成原样（#326 定）。
  - 原地改的（`redraw`，例如 `/rh_ls` 点进槽位详情）也带 Markdown 那份。
  - 按 [取消] 时，写回的原文取自平台给的消息原文，是显示出来的字，标题记号已经没了。照旧写回，标题变成普通的一行，可以接受；要保住，就把原来的 Markdown 记在开着的面板上。

### 网页

- 回复：`RhReply` 的成功分支加可选的 `card`，就是驱动给的那份数据，`/status` 再加上 Rhodium 知道的槽位部分（全名、状态、目录、agent）。`rh` 命令行照旧只打 `text`。
- 挑框子（`web/src/write.tsx` 的 `show()`）：带 `card` 或 `panel` 的进信息卡，别的进轻提示。不再看行数。
- 信息卡（新组件，换掉 `web/src/palette.tsx` 里 `Answer`、`ModelSheet`、`AgentSheet` 的外壳和 `Bottom`）：
  - 挂在对话那一栏里，不再 portal 到整页。手机上整屏宽，左右留一点边。
  - 贴着输入框上沿往上长，再高在卡片里滚。最高多少见下面 2026-10-28 改的外壳。
  - 打开时对话记录照原样，不压暗（2026-10-29 改，#479）。
  - 顶上一行：图标加两个字的标题（用量、上下文、状态、模型、对话……），右边是叉。
  - 中间分块，每块一个小标题，前面放 agent 的 logo 或一个 lucide 图标。
  - 一行一项：名字在左，数字在右，数字用等宽数字对齐。
  - 能做的事放在最下面一排按钮，每个是图标加两个字。
  - 点外面、按 Esc、点叉关掉。开着时输入框照样能打字，新的回复来了换掉它。
