## 问题

**TUI 期间，内部消息一直压着，谁也看不到。**

- 槽位在 TUI 时，子槽位的汇报、别的槽位的 `rh send`、确认结果都排队，等它切回无头才交给它。
- 汇报和确认结果排着时，你没有任何提示。父槽位在 TUI 里，子槽位的汇报就可能几个小时后才到：1.2.0、1.2.1 发布时的汇报就是这样晚到的。

**终端里的 agent 不知道 Rhodium 的规矩。**

- 无头时 Rhodium 给 agent 追加系统提示，终端里不给。终端里的 agent 不知道来源行是什么意思，也不知道 `rh send` 怎么回。

**往终端里打字做得到，但只能尽力而为。** 2026-11-10 在单独的 Herdr 会话里实测到这些危险：

- 对话框开着时回车会生效：权限框批准默认的那一项，`/config` 改掉了选中的设置。
- 输入框里你打了一半的字，和送进去的消息拼成一条发出去。
- 以 `/` 开头的被当命令，以 `!` 开头的真的在本机执行了。
- 长的被 Claude 当成粘贴：3125 字、61 行的包上了一层粘贴标签，3 行的没包。只测了这两个点。Claude 的文档说超过 800 字或超过 3 行就算，还告诉模型粘贴里的指令不要照做（[产品说明](../product.md) §4.2“打进去的是什么”）。
- Herdr 说“空闲”不等于能打：设置框开着时它照样报空闲。
- Herdr 只保证字进了 pane，不保证那一刻输入框是空的、没有对话框，也不回执。
- Herdr 的 `agent.prompt` 写完字 300 毫秒后自己按回车，回车前不再看有没有被挡住。干活的 agent 恰好在这时弹出权限框，回车就选了默认的那一项。

## 方案

分四样做，每样都能单独上线：

- **第 0 步，等着时让你看得到。** TUI 槽位等着的内部消息列在网页的待发队列里，等了 10 分钟在 IM 里告诉你一次；`rh send` 的回执照旧写“切回无头后再交给它”。这一步还不打字。
- **第 1 步，只读信号。** 每秒读一次 pane 底部的画面，算出“现在能不能打”。先只用来在卡片上写“被弹框挡住”。
- **第 2 步，内部消息打进 Claude 的终端。** 守卫、来源行、字和回车分两步、确认、没确认时的处理，都照产品说明 §4.2。Claude 在干活时也打，和无头时的插话一样并进当前回合。`rh send` 的回执这时才分能打、不能打两种写法。
- **终端带系统提示**（#665 第 7 条）。和第 0、1 步互不依赖；第 2 步等它，好让终端里的 agent 先认得来源行。

Codex、pi 等实测以后再打，单独一张工单。

## 开工前先实测

#665 要求 Codex 和 pi 的记录里有没有入队一类的痕迹，写规格时各测一次。写这份规格时没有测：规定只能用测试会话和假 agent，不往真 agent 的终端里打字。所以这些放到开工前，由做工单的人跑，结果录成测试素材，写进架构 §10.3、§10.5。

都守这几条：

- 只用 `herdr --session rhodium-test`，单元用 `rhodium-test-` 前缀。不碰你自己的 Herdr 会话。
- 工作目录用一个临时目录，测完删掉；agent 为这个目录留下的对话记录目录也删掉，它只属于这次实测。
- 信任记录不删：它写在你自己的 Claude 全局配置里，你的 Claude 也在同时写这个文件。录信任框时用 Esc 关，不点信任；为了往下测点了信任的，在 PR 里写明留下了哪个临时目录的记录，由你决定删不删。
- 真 agent 跑得便宜：Claude 用 `--model haiku`，Codex 用低思考强度，pi 用它的默认模型。
- 不打开会改设置的对话框：`/config`、`/model` 这类一律不开。要录对话框的画面，用权限框、目录信任框和只读的 `/status`，只用 Esc 关。2026-11-10 的调研里，往 `/config` 里按了一个回车，就改掉了一项用户设置。
- 要换 Claude 的设置来录画面（vim 编辑模式、全屏画面），只在这一个进程的启动命令上带 `--settings '{"editorMode":"vim"}'` 这类参数，不写任何设置文件。带了不生效，就不录，照架构 §10.5 的退路做。

要测的：

1. **Herdr 的几个接口。** 用 `cat` 一类的假程序，录 `pane.read`（`source: "recent"` 加 `format: "ansi"`，用来对照的 `source: "detection"`；写一段带颜色的字，看前者带着样式、后者是纯文本）、只带 `text` 的 `pane.send_input` 和 `pane.send_keys` 的 `["enter"]`，包括 `pane_not_found`。看 `pane.send_input` 在 pane 开了括号粘贴时是不是包上了（0.9.5 源码是包的），多行的字写进去以后 `cat` 收到几行、有没有提前收到回车。存进 `test/fixtures/herdr/`，假 Herdr 照它写。
2. **Claude。**
   - 交互的 `claude` 认不认 `--append-system-prompt-file`、`--system-prompt-snapshot off`：起来以后问一句只有系统提示里才有的话。
   - 底部画面（`pane.read` 的 `recent` 加 `ansi`，架构 §10.3）：刚起来的空输入框（有没有灰色提示字）、有草稿、权限框、信任框、`/status`、干活中（输入框还认不认得出）。
   - 干活中、已经有一条消息排着时的画面：输入框里那句 “Press up to edit queued messages” 在哪、是不是灰字、认不认得成空输入框。不是灰字的，照架构 §10.5 把原文记进 Claude 的认法。认不成空输入框，干活时打进第一条以后后面的就都等着。
   - 回车前那一眼看的画面：写了字、还没按回车时的输入框。录四种：一行的、3 行以内的（看换行和折行怎么显示）、4 行以上会折成占位符的（占位符的样子）、只有一行但超过 800 字的（折不折、占位符是不是还是 `[Pasted text #N +M lines]` 的样子；不是的话照录到的改架构 §10.5 的比对）。再录一种带 emoji 和制表符的（“⚠️”“✔️”这类带变体选择符的，加一个带零宽连接符的，例如 “👨‍👩‍👧”）：读回来和写的不一样的，照录到的在架构 §10.5 写明比的时候去掉哪些字符。空闲和干活时各录一次。再录一次写完字马上弹出权限框时的画面。看默认的 80 行够不够把 3 行的输入框读全；不够就加大 `lines`。
   - 不折的长消息在窄 pane 里：正文接近 3 行、800 字、多是中文，pane 窄到手机上开网页终端那么宽。看输入框折成多少行、超过一屏时读不读得全。读不全的，回车前那一眼永远比不上，字会一直留在输入框里。那就按 pane 的行列数先算一遍：输入框放不下的，也照 2000 字那条存成文件，只打来源行和路径（架构 §10.5 照实测补）。
   - 上面这些画面，默认画面和全屏画面（`--settings '{"tui":"fullscreen"}'`）各录一份：开源以后，别人多半用的是另一种。
   - 空输入框里的灰色提示字，用 `recent` 加 `ansi` 录（`detection` 来源不管 `format` 都只回纯文本，Herdr 0.9.5 的源码和文档）：看能不能按颜色和你的字分开。分不开就停下，回来问你。
   - 权限框开着时（让它跑一条无害、要批准的命令，例如 `ls`），用 `pane.send_input` 写一段带数字的字，例如 “1 2 3”：确认选中的那一项没变、什么都没执行，再用 Esc 关掉。选中的项变了或执行了，就停下回来问你：写字以前的那个口子（产品说明 §4.2）就不只是丢字。
   - vim 编辑模式（`--settings '{"editorMode":"vim"}'`）的 NORMAL 和 INSERT：两种状态在画面上各有没有标记。NORMAL 没有标记的，照架构 §10.5 只读地查设置。
   - 对话记录：空闲时打进去的 `user` 行；多行、中文和 emoji 的正文打进去以后，和打的那一段比得上。
   - 粘贴里夹着看不见的字符：哪些会让 Claude 清掉，补进架构 §10.5 要去掉的那张单子。清掉以后是停在输入框里，还是直接发出去（Claude 的文档页和 2.1.316 的更新记录说法不一样），照实测改产品说明 §4.2 的说法。
   - 结尾是反斜杠的短消息（3 行以内，不折），例如一个 Windows 路径：回车以后是发出去，还是在输入框里换了行。照 Claude 的说明推，是换行，所以 Rhodium 在结尾补了一个空格（架构 §10.5）；没实测过。实测是发出去的，就去掉这个空格。
   - 结尾是 `@` 加半个文件名的字（例如“看看 @hel”，目录里有 `hello.txt`）：写进去以后有没有弹出补全，回车以后发出去的是原样还是补全了的。会弹、回车选了补全的话，再定怎么避开。
   - 多行的消息：打进一条正文 4 行以上、不到 2000 字的消息。录下终端里显示什么（占位符还是来源行）、记录里的 `user` 行什么样，以及带着终端那份系统提示（含讲粘贴标签的那一句，架构 §6.1）时，agent 照不照里面说的做。消息里请它做一件小事，例如读一个文件、回一句固定的话。不照做的，照产品说明 §4.2 退一步：把存文件的线降到 3 行、800 字。
   - 正在跑工具调用时打进去（例如让它跑一条 `sleep 20`）：马上写的 `queue-operation` 入队行；工具调用做完后它怎样并进同一个回合（`queued_command` 附件行，架构 §7.7）；回合里没有工具调用时，回合结束后的出队和单独的 `user` 行。Claude 干活时也打，这是最常见的路，确认靠的就是这条入队行。再用一条 4 行以上、会折成占位符的消息录一次：入队行的 `content` 是全文还是占位符。是占位符的话，照产品说明 §4.2 退一步，把存文件的线降到 3 行、800 字：打进去的不折，入队行里就是原文。不然这条会一直标成没确认，用户点重发它就做两遍。
   - 入队以后、agent 还没读到它以前，按 Esc，或者退出 agent：记录里留下什么（入队行之后有没有出队、删除一类的行），消息还在不在（Esc 会不会把它放回输入框）。入队算收到已经定了（#665 的补充评论），这里只录下来，好知道这种时候消息还在不在。
3. **Codex 和 pi。** 同上，另外：
   - Codex 会不会把写完字以后的回车当成换行：Rhodium 写完字先读一次画面才按回车，录下中间隔多久、隔多久才不当成换行。
   - 两家在干活时按回车会怎样：pi 是插话的，确认它并进当前回合，表里填“干活时也打”；Codex 照实测定干活时打不打。
   - 打进去的消息什么时候写进记录：空闲时、干活时是不是马上写。
   - Codex 有没有 `-c developer_instructions` 一类的配置项能带系统提示；pi 的终端认不认 `--append-system-prompt`。

## 测试决定

照 [v1 规格](v1.md#测试决定)的规矩：只测外部看得到的行为，测试名带故事编号。整机测试用假 IM、假 agent 和假 Herdr。

假 Herdr 要补：

- `pane.read`：测试给每个 pane 设一段底部画面，可以带 ANSI 样式。`source: "recent"`、`visible` 照样带着样式回；`detection` 和真 Herdr 一样只回纯文本，不然测试会过、真机上灰字一直被当成草稿。
- `pane.send_input`、`pane.send_keys`：记下收到的字和按键；写进去的字显示在这个 pane 的输入框里（测试设的底部画面跟着变），测试也能改成别的画面（例如写完字马上出现对话框页脚）；测试能让它们报错、断开或不回话。
- 设 pane 的 agent 状态（#664 已经加了）。
- 测试往这个 pane 报告的会话的记录文件里追加 `user` 行、`queue-operation` 行，扮演 agent 收到了。

要测的：

- 第 0 步（605）：
  - TUI 里的 Claude 槽位收到一条汇报：槽位信息里列着它，写着在等什么。
  - 用假时钟走 10 分钟：联系窗口收到一条通知。再来一条汇报，不再通知。队列清空以后再等满 10 分钟，又通知一次。
  - 切回无头：它照常交给无头的 agent，通知的标记清掉。
  - 确认结果在无头和 TUI 里都以 `[来自 Rhodium：确认结果]` 开头。
- 第 1 步（607）：
  - 画面上有 “Esc to cancel” 页脚：输入状态变成 `dialog`，记一条 `tui_input` 事件，看板那张卡写“被弹框挡住”。
  - Herdr 报 `blocked`、画面正常，也是 `dialog`。页脚没了，卡片回到“TUI 模式”。
  - Herdr 报 `unknown`、画面上有页脚：`dialog`。
  - pi 的槽位，Herdr 报 `blocked`：卡片也写“被弹框挡住”。
  - 输入框里只有灰色提示字（`recent` 加 `ansi` 读出暗色）：`ready`。只有 “Press up to edit queued messages” 一句（照实测的样子）：`ready`。两条横线之间第一行是单独的 `❯`、下面还有字：`draft`。页脚的词在一行中间、大小写不同：照样认出。
  - 状态不变时不写库，不发事件。
- 第 2 步（606、608–614）：
  - `rh send` 的回执：能打的槽位一句，pi 的槽位另一句。
  - 空闲、输入框空着：连着两次读以后调了一次 `pane.send_input`（只有字，字是来源行加正文），输入框里显示这一段以后才调 `pane.send_keys` 按回车。记录里追加对得上的 `user` 行：标已收下，正文清空，槽位信息里没了它。
  - Herdr 报干活中、画面上输入框空着：照样写字、按回车。记录里追加对得上的入队行：也算收到。
  - 写完字以后的那一眼（608、611）：
    - 画面上出现对话框页脚、Herdr 报 `blocked` 或 `unknown`、输入框里多了别的字、等了约 2 秒输入框里还不是写的那一段：都不调 `pane.send_keys`，马上标结局不明，网页上写“已投递，尚未确认收到”。
    - 写完字以后 `pane.read` 报错，或者不回话：不调 `pane.send_keys`，按假时钟到 2 秒就标结局不明，不再等那次读。
    - 输入框里只有一个 `[Pasted text #1 +N lines]` 占位符：照样按回车。正文只有 2 行时也一样，不按长度预判。占位符后面还有别的字：不按。
  - 记录里那条 `user` 行包着 `<pasted_content …>` 标签：也算收到。
  - 记录里一条 `user` 行包着 `<pasted_content …>`、标签里第一行是来源行：网页对话记录里它算那个来源发的，不算用户说的（架构 §7.7）。
  - 输入框有字、对话框页脚、vim 的 NORMAL、设置是 vim 而画面上没有 INSERT 标记、Herdr 报 `unknown`、认不出的画面、Herdr 报空闲但画面上有 `/status` 的页脚、Herdr 正在重启：都不调 `pane.send_input`。画面变好以后才调。
  - 只有一次读是空的，下一次就有字：不调。
  - 正文以 `/`、`!` 开头：打的那一段以 `[` 开头。正文里有 `\r`、`\x03`、`ESC[201~`、零宽空格、双向控制符：打的那一段里没有它们；零宽连接符和 emoji 留着。
  - 2500 字的正文：媒体目录里多一个文件，打的是两行。
  - 30 秒没有痕迹：标结局不明，网页上写“已投递，尚未确认收到”，不再写字，下一条这时才打。之后追加痕迹：标已收下。
  - 打完 10 分钟还结局不明：联系窗口收到一条通知，只一次。发通知时画面上输入框里正好是打的那一段，第三行是“它还在输入框里”那句；没按回车、但输入框是空的（写字时弹出了框），用平常那句。
  - 网页重发：再打一次。网页删掉：行没了。
  - 字还在输入框里时点重发：先不写字（输入框不空）。这时记录里追加原来那一段的 `user` 行（你在终端里按了回车）：标已收下，输入框空了也不再写字。
  - `pane.send_input` 回 `pane_not_found`：回到排队，不算结局不明。`pane.send_input` 或 `pane.send_keys` 连接断了：留在写入中，照确认走，不重打，不补按回车。
  - 重启（照 v1 规格的接缝二，在标了写入中以后、写字以前，写了字、按回车以前，和按了回车以后，各 `kill -9` 一次）：重启后不再写字，也不补按回车；记录里有痕迹的标已收下，没有的满 30 秒标结局不明。
  - 切回无头：没打过的交给无头的 agent；结局不明的不交，网页上还在；点重发以后交给无头的 agent。
- Codex 和 pi（615）：表里没填的 agent，画面正常也不调 `pane.send_input`。填了“干活时不打”的，Herdr 报干活中不调，在等什么写“等 agent 空闲”。
- 系统提示（616）：Claude 的终端启动命令带上两个参数，说明文件里是终端那份；子槽位是子槽位那份；从 pane 导入的槽位不带。
- 网页（Playwright，手机尺寸）：TUI 槽位的终端上面是待发队列，一条在等、一条写着“已投递，尚未确认收到”；点开看到原文；没确认的那条有“重发”，两条都能删。首页卡片写“被弹框挡住”。

## 你来验收

用一个 Claude 槽位，在手机上看网页，在电脑上看终端：

- 把一个父槽位切到终端，让它派出去的子槽位跑完：终端里出现这条汇报（短的是来源行；3 行以上或超过 800 字的是一个粘贴占位符；正文超过 2000 字的是来源行加一行路径，见产品说明 §4.2），agent 接着处理它。网页的对话记录里它以 `[来自 Rhodium：子槽位汇报]` 开头，待发队列里那条随即消失。
- 在终端的输入框里打半句话，不发。让别的槽位 `rh send` 给它：消息不进去，网页上写着等输入框空出来。把半句话发出去：输入框空了，那条消息随即打进去。这一回合还在跑工具调用的，它并进这一回合；已经做完的，它单独跑一个回合。
- 在终端里让 agent 跑一条要你批准的命令，不答：卡片写“被弹框挡住”。这时来的消息等着，10 分钟后 IM 里收到一次通知。答掉权限框：消息随即打进去。那条命令还在跑、这一回合还有工具调用的，它并进这一回合；已经做完的，它单独跑一个回合。
- 让 agent 干一件要跑好几条命令的长活，中途让别的槽位 `rh send` 给它：消息几秒内打进去，终端里显示它排着，待发队列里那条随即消失。agent 在这一回合里接着处理它，没有等这一回合做完。
- 在终端里问 agent“别的槽位的消息怎么回”：它知道用 `rh send <工作区/槽位>`。
- 有消息等着时切回无头：它们马上交给无头的 agent。
- 把一个 Codex 或 pi 槽位切到终端，让别的槽位给它发消息：照实测打进终端，和 Claude 一样；它在干活时也打（#713）。Codex 的终端里马上出现这条消息；pi 的终端里它先显示成 “Steering: …”，手上的工具调用做完才并进回合，待发队列里那条在输入框空了时就消失。

## 不做的事

| 不做的事 | 为什么 |
|---|---|
| 清掉输入框里你的字再打 | 不清、不拼，排队等（#665 第 3 条） |
| 确认不了时自动重发，或者替你再按一次回车 | 它可能已经到了，再来一遍 agent 就做两遍（#665 第 5 条） |
| 把“打完 5 秒内 agent 开始干活”当成收到 | 可能是内部回合，或者别的消息引起的（#665 第 4 条） |
| 用 Herdr 的 `agent.prompt` 打字 | 它写完字 300 毫秒后自己按回车，回车前不再看有没有被挡住；这时弹出的权限框会被回车选中默认项（[产品说明](../product.md) §4.2“哪些 agent”） |
| 不先看画面就按回车 | 权限框开着时回车照样批准（实测）。字和回车分两步，回车前那一眼没过就不按 |
| Claude 的 channel、收件 socket、hook 唤醒这类不靠键盘的入口 | 都带“不是用户说的”标记，不是用户消息；要写你的项目目录或过确认框（#665 调研结论：Claude 只能打字） |
| Rhodium 用 Herdr 的 `report-agent` 给 Claude 的 pane 打“别打”的标记 | 实测它抢不过 Herdr 从屏幕认出的状态 |
