## 问题

- 槽位在终端里时，你从 IM 发的消息一律拒收。人离开电脑，就只能先 `/rh_release` 把终端收回来，才能接着说话；收回又会结束终端里的 agent。
- 第一批已经能安全地往终端里打字，但只打内部消息。
- 终端里说的话不发到 IM。要让手机上的你知道，只能靠 agent 自己记得 `rh send me`。

## 方案

你定的五条（2026-11-16）：

1. 你从 IM、网页发的消息也打进终端，和内部消息守同一套规矩、排同一个队。
2. 回复自动转回发消息的窗口，和无头一样：终端里的回合结束时，Rhodium 从对话记录里取最终回复，发过去。`rh send me` 发过同样的话的，照无头的规矩不再发。
3. 按槽位的开关，默认开。关着时照旧拒收。
4. 从 IM 发的、以 `!` 或 `/` 开头的不打，回一句原因。
5. 输入框里有你打了一半的字时，排着，不清、不拼，和内部消息一样。

过程也实时转。查了现在 IM 的过程显示，能接上对话记录：Herdr 桥把新写的行换成过程事件交给路由就行。

- 路由给 IM 画过程消息，只用三种事件：一段话写完、一次工具调用开始和做完、回合结束带最终回复（`src/router.ts` 的 `edit`、`append`、`finish`）。
- 逐字增量只让 Telegram、飞书那条消息长得更顺，QQ 根本不用它。
- 网页对话页已经把三家的对话记录整理成同样的块：agent 的话、带名字和参数的工具调用、它的结果（[架构](../architecture.md) §7.7，`src/transcript.ts`）。
- 所以只要 Herdr 桥把新写的行换成这三种事件交给路由，过程消息的代码不用改。工具调用的参数要从原始行取完整的，交给无头时那套打码：对话页的块截过、也没打码（[架构](../architecture.md) §10.6 第 3 条）。代价写在[产品说明](../product.md) §4.2：没有逐字流出，Codex 没有“正在运行”那一行。

分三步做，见下面“拆工单”：先把你的消息打进去，再转最终回复，最后转过程。弹框的通知单独一张。

## 开工前先实测

都守第一批的那几条（[TUI 槽位的输入规格](tui-input.md)“开工前先实测”）：只用 `rhodium-test` 会话，不碰你自己的 Herdr 会话；临时目录测完删；真 agent 跑得便宜，Claude 用 `--model haiku`；不打开会改设置的对话框。结果录成测试素材，写进架构 §10.6。

1. **回合很短时 Herdr 报什么。** 三家各打一句只要回一个字的话，每 100 毫秒读一次 `pane.get`，录下状态的先后。看每秒一次的读会不会一次都读不到 `working`。架构 §10.6 的结束认法不靠读到它，这里只为写进素材，供假 Herdr 照着演。
   - 再各打一句要先说一段话、再调工具的。录下记录里第一行 agent 的话写进去的时刻，和 Herdr 第一次报 `working` 的时刻，看差多少。差过 1 秒的，架构 §10.6 第 4 条“连着两次空闲”加到盖得住的次数。
2. **记录里有没有回合结束的行。** Codex 有 `task_complete`（录制里已经有）。Claude 看有没有 `system` 行一类的回合结束标记（例如带用时的那种），有就写进架构 §10.6 一起认；pi 也看一眼。
3. **Claude 一个回合刚完、马上从自己的队列里拿出下一条时。** 干活时打进去一条，让它在没有工具调用的回合里排到回合结束：录下记录里上一回合的最后一段话、`dequeue`、单独的 `user` 行和下一回合的话的先后，以及 Herdr 那几秒报的状态。确认架构 §10.6 第 4 条挡得住“晚一秒的空闲”。
4. **图片路径打进去会怎样。** 打一条第二行是 `[图片] <一个 png 的绝对路径>` 的消息：Claude、Codex、pi 的输入框里显示的是原样，还是变成了一个图片占位符（例如 `[Image #1]`）；记录里是文字还是图片块。
   - 原样的，照架构 §10.5 打。
   - 变成占位符的，回车前那一眼比不上，这条会一直标“结局不明”。那就退一步：带附件的消息照 2000 字那条存成文件，只打来源行和一行路径，附件那几行写在文件里。
5. **被打断、被拒绝时记录里写什么。** 让 pi 说一段话、再调一个慢的工具，这时按 Esc；再让它一句话没说就按 Esc。看记录里有没有能认出“被打断”的行（例如 assistant 消息的 `stopReason`）。有就写进架构 §10.6 第 6 条；没有就在第 6 条写明 pi 被打断时只能等别的几种情况收尾。Claude、Codex 按 Esc 的打断行录制里已经有。
   - Claude 在终端里弹一个权限框，在框里选拒绝。看记录里写的是不是 `[Request interrupted by user for tool use]`：现有录制都是无头的，没录过终端里的拒绝。是的话，架构 §10.6 第 6 条的“拒绝也走这一条”就成立；不是的话，写下记成了什么，第 6 条照它改。
6. **最终回复对不对得上。** 同一句话（haiku，读一个文件再回一句），无头跑一次、终端里跑一次：从记录里按架构 §10.6 第 5 条取的最终回复，和无头时驱动报的一样。Codex 看 `item_completed` 里的 agent 的话带不带 `phase`。

## 测试决定

照 [v1 规格](v1.md#测试决定)的规矩：只测外部看得到的行为，测试名带故事编号。整机测试用假 IM、假 agent 和假 Herdr，假 Herdr 用第一批补好的那些（读画面、写字、按回车、往记录里追加行）。

- 开关和进队列（617、621、622、623、626）：
  - 开关开着（默认）、TUI 槽位输入框空着：IM 发一句，假 Herdr 收到来源行 `[来自 QQ 私聊]` 加正文，IM 上什么也没回。
  - `rh set <槽位> type-in=off` 以后再发：回“在 TUI 里，这条没交给它”，假 Herdr 什么也没收到。网页的设置一节有这一项，改了就生效。
  - 关掉开关以前就排着的：照旧打进去。
  - `/compact`、`/model x`、`!停一下`、`！`、只发 `!`：都不打，各回对应那句。`/status` 照常由 Rhodium 回答，`/rh_release` 照常执行。
  - 带引用和一张图片：打的是来源行、引用、正文、`[图片] <路径>` 那一行。
  - 画面是草稿、对话框、认不出、Herdr 断着：不打，回一句“这条先排着”，冒号后面照在等什么换。输入框空出来以后打进去。第二条再来，不再回。
  - 只是排在一条正打着的消息后面：不回。
  - 槽位还在切到终端、pane 没开好：照旧拒收。
- 没确认（624）：30 秒没痕迹，马上在那个窗口说一次“尚未确认收到”；满 10 分钟不再说。回车前那一眼没过的，马上说，第三行是“它还在输入框里”。网页发的不说。
- 最终回复（618、620、625、628）：
  - 空闲时打进去：记录里追加 `user` 行、两段 agent 的话，Herdr 连着两次报空闲：IM 收到最终回复，是后一段。Telegram 上是同一条消息的最后一段。
  - 刚打进去时 Herdr 还报着空闲、`from` 后面还没东西：不收尾。
  - agent 刚写出第一段话，Herdr 在那以前已经报了两次空闲：不收尾，要等那以后再连着两次空闲。
  - 干活时打进去：入队行以后、`queued_command` 附件行以前写的 agent 的话不转；附件行以后的转，回合结束发最终回复。
  - 照测试 3 录的先后（上一回合的话、`dequeue`、单独的 `user` 行，Herdr 晚一秒才报空闲）：最终回复是下一回合的话。
  - 记录里有一条 `rh send me`，送到了这个窗口：后面的话和最终回复不转；再从 IM 发一条、并进来：后面照转。前一个回合的 `rh send me` 到下一个回合才发失败：不撤下一个回合的标记。
  - 两个窗口各发一条：回复都在第一个窗口，第二个窗口收到“已并入”。
  - 终端里你亲手打的、没有来源行的回合中途你从 IM 发一条：发起窗口是这里，之前的话不补发。
  - 回合中途切回无头、pane 报告的会话变了、agent 的 PID 变了：不发最终回复，Telegram 那条去掉“正在运行”。
  - 终端里按 Esc 打断（Claude 的 `[Request interrupted by user]` 行、Codex 的 `turn_aborted`）：
    - 打断前 agent 说过一段话，之后 Herdr 连着报空闲：不发最终回复，那段话只作为过程留着。
    - 打断前一句话没说：`turnChat` 清掉，排着的汇报接着打进去；之后终端里没有来源行的回合不转到 IM。
  - `turnChat` 记着时来一条汇报：不打，网页上写“等这一回合回完你”；回合收尾以后打进去。
- 过程（619）：Claude 的 `tool_use` 行先到：Telegram 上出现“正在运行”；`tool_result` 行到了，并回工具段。Codex 的工具调用只在做完时出现。QQ 上一段话一条，工具行在开头。一次 Write 的参数超过 2000 字、Bash 命令里带着 `token=…`：IM 上的工具行有参数，值打成 `***`。
- 重启（627）：照 v1 规格的接缝二，在转了一段以后 `kill -9`：重启后不重发那一段，接着转。回合在 Rhodium 停着时结束（库里的 `tuiStatus` 是 `working`，起来时 Herdr 报 `idle`）：重启后补发最终回复。
- 弹框（629）：`from` 找到以后画面变成对话框：发起窗口收到一次；关掉又弹：这个回合不再说。网页来的回合不说。
- 系统提示（630）：终端那份里有“例外”那一条和窗口名来源行那一句，子槽位那份也有。
- 网页（Playwright，手机尺寸）：待发队列里你的消息写“你”和窗口名；一条汇报写“等这一回合回完你”。

## 你来验收

用一个 Claude 槽位，手机上用 QQ 和 Telegram，电脑上看终端：

- 把槽位切到终端，切好的通知第三行写着“这里的消息会打进终端”。在 QQ 里问它一句要读几个文件的话：终端里出现 `[来自 QQ 私聊]` 开头的这句，agent 干起来；QQ 上一段话一条地收到过程，最后是最终回复。
- 在 Telegram 里再问一句：同一条消息一段话一段话地变长，最后定稿。
- 在终端的输入框里打半句话，不发，再从 QQ 发一句：QQ 上回“这条先排着：输入框里有没发出去的字”。把半句话删掉：那句随即打进去。
- 让 agent 跑一条要你批准的命令，你不在终端里答：QQ 上收到一次“终端里弹了一个框在等你”。到网页终端里点批准，回复照常发回来。
- 让它干长活，中途从 Telegram 再发一句：Telegram 上回“已并入 QQ 私聊那边正在跑的回合”，回复在 QQ。
- 从 QQ 发 `/compact` 和 `!停`：各回一句原因，终端里什么也没出现。
- 从 QQ 发一张截图问它图里是什么：终端里是一行路径，agent 读了它，回答发回 QQ。
- 回合跑到一半时重启 Rhodium：回复接着转，不重复，最终回复照常到。
- `rh set <槽位> type-in=off`，再从 QQ 发一句：回“在 TUI 里，这条没交给它”。改回 `on`。
- 用一个 Codex 槽位、一个 pi 槽位各走一遍第一条。

## 不做的事

| 不做的事 | 为什么 |
|---|---|
| 在 IM 里答终端里弹的框，或者往框里按键 | 框里的回车会批准默认的那一项（第一批实测）。只告诉你一次，你到终端或网页终端里处理 |
| 以 `!` 开头的消息替你在终端里按 Esc 打断 | 你定的：不打，回一句原因。Esc 落在框上也会关掉框 |
| 逐字转过程 | 终端里的 agent 不经过 Rhodium 的驱动，对话记录里一段话写完才有一行 |
| 回复只靠 agent 自己 `rh send me` | 你定的：和无头一样由 Rhodium 转 |
| 网页终端下面的输入框也走打字的守卫和队列 | 那是你看着画面亲手打的，和在键盘上打一样（[产品说明](../product.md) §7） |
| 转回的回合到时没结束就替它收尾 | 无头也不设时限；收尾时取的最后一段话不一定是结尾 |
| 汇报父槽位 | 终端里的回合本来就不汇报；你直接找子槽位时，回复照无头发给你 |

## 还没定的

- 被弹框挡住的槽位要不要挪到看板的“需要你”（#665 留下的）。这一批照旧不挪，只在你等着回复时告诉你一次。
- pi 的桥接扩展、Codex 的 `--remote` 要不要做（[TUI 槽位的输入规格](tui-input.md)“以后再做”）。
