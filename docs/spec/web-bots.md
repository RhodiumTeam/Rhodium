# 网页管 Bot 规格

这篇回答：2026-11-17 定的“Bot 管理搬到网页上”要做成什么样：网页上新建 Bot 的向导、Bot 的右键菜单（添加小号、主人、删除）、建 Bot 的流程挪进 `rhodium` 让终端和网页共用、主窗口自动设，以及首页没有槽位时的引导；满足哪些需求、怎么测、怎么验收、明确不做什么，怎么拆工单。

前置阅读：[术语表](../../GLOSSARY.md)、[产品说明](../product.md)、[架构](../architecture.md)、[v1 规格](v1.md)、[网页能写规格](web-write.md)、[网页拓扑图规格](web-topology.md)、[网页新建导入和输入框规格](web-import-composer.md)

这些在 2026-11-17 的第 41、42 轮拷问里定下。各项事实写在上游，这里不重复，只写需求、测试和交付：

- 行为：[产品说明](../product.md) §5.11“网页上管 Bot”。
- 建 Bot 的流程、接口、主窗口自动设、去掉 Bot：[架构](../architecture.md) §8.5“终端和网页共用的建 Bot 流程”，§14.8 的 `rh bot rm`。
- 新接口谁能调：[架构](../architecture.md) §11。
- 原来不做的：[网页能写规格](web-write.md)“不做的事”里 `rh bot`、`rh pair` 那一行，这里换掉。

这篇用到几个词：

- 向导：新建 Bot 的弹窗，一步一屏。
- 配对屏：显示配对码、等你发码的那一屏。向导的最后一步和“添加小号”共用。
- Bot 菜单：拓扑图上 Bot 节点的菜单。宽屏右键，手机长按。
- 空白处菜单：拓扑图空白处的菜单。宽屏右键，手机长按（不在编辑模式时）。
- 宽屏、手机：同[网页放大模式规格](web-maximize.md)开头。中屏照宽屏。

## 问题

- 建 Bot、配对、加减小号只能在 ssh 里用 `rh` 做，网页上一样也做不了。网页上已经能做几乎所有别的事，这一块是割裂的。
- 去掉 Bot 连命令行都还没有，只能停服务手改配置和库。
- 主窗口只能手改配置文件。首次安装建完 Bot，不改配置就收不到 `rh send me` 和每日自检的推送。
- 首次安装后首页一片空白，只有一行“没有在用的槽位。”，不知道从哪开始。

## 方案

- 建 Bot 的流程整段挪进 `rhodium`：出二维码、等扫码、过期换码、核对粘贴的凭据、写配置、当场启用。终端里的 `rh bot` 和网页的向导都只是显示它的状态，行为只有一份。这一步原排在 Bot 程序第二段（[架构](../architecture.md) §14.9），提前做，只做终端和网页这两头；agent 发起建 Bot 照旧不做。
- 二维码由 `rhodium` 画成 SVG 图片：两个平台都只给网址（2026-11-17 实测 QQ 的 `create_bind_task` 只回 `task_id`），用已经装了的 `qrcode-terminal` 自带的编码器，不加依赖。
- 网页上：“+”菜单和拓扑图空白处菜单有“新建 Bot”；Bot 菜单有“添加小号”“主人”“删除 Bot”。
- `rh bot rm` 提前做（[架构](../architecture.md) §14.8 写好的那份），不含交给程序的部分。
- 还没有主窗口时，第一个配上你账号的私聊自动成为主窗口，写进配置文件。
- 首页没有在用的槽位时，页面正中给引导和“新建”“导入”两个按钮（#780，已做）。

## 实现决定

### 共用的建 Bot 流程

接口和状态见[架构](../architecture.md) §8.5。要点：

- 一次建 Bot 是 `rhodium` 内存里的一个流程，有 ID。开始时照现在的第一问检查名字、平台、槽位，过了才出码或等粘贴，不过就直接回原因。
- 流程的状态：等扫码（带二维码和链接、过期时间）、等粘贴、核对中、写配置中、等配对（带配对码、到期时间）、完成（带 Bot 名、是否设了主窗口）、失败（带原因）、已取消。
- 状态变了，事件流推一条 `bot_flow`，页面重取；终端的 `rh` 每秒问一次。
- 凭据（QQ 解出的密钥、粘贴的 token 和密钥）只在 `rhodium` 内存里，写进配置后就丢；不进库、不进日志、不回给页面。粘贴的走专门的接口，不经 `/api/act`，不进动作记录。
- 关掉向导、终端里 Ctrl-C：取消流程。`rhodium` 重启时没走完的都作废。
- 同一个名字同时只能有一个流程。

### 网页

- 向导用 `web/src/create.tsx` 的 `Form`（宽屏居中；手机从底部弹出，键盘弹起时抬高，#776）。每一屏一个标题：第 1 步“新建 Bot”；第 2 步扫码的写“扫码”，Telegram 写“填写 token”，飞书粘贴写“填写 App ID 和密钥”；第 3 步“配对”；最后“创建成功”。右上角“第 x / y 步”，没有别的解释文字。返回键在标题左边。
- 第 1 步：平台用 logo 单选，样子同新建槽位选 agent（没选中的灰掉）；“名称”“投递给”是 Base UI `Field` 的标签；“投递给”用 Base UI `Select`，每项是 agent 图标加全名。名称只收英文字母、数字和 `_ -`，不合法时框下说原因。
- 二维码是 `rhodium` 回的 SVG，放进 `<img>`。手机电脑一样大。
- 密钥框用浏览器原生的 `<input type="password">`，放在 Base UI `Field` 里，`autocomplete="off"`、不拼写检查、不自动大写；旁边一个眼睛键切换显示。不自己写遮挡。
- 配对码按原样等宽大字显示，不加空格。倒计时前一个时钟图标，写“m:ss”。
- Bot 菜单和空白处菜单用现有的 `MenuAt`（`web/src/write.tsx`）。菜单项要加“灰着”和“危险（红色）”两种样子；灰着的项悬停显示原因（Base UI `Tooltip`）。
- 主人列表和删除确认不用打字：手机上也居中（Base UI `Dialog`、`AlertDialog`），不从底部弹出。
- 手机上长按：Bot 节点和空白处，不在编辑模式时长按 500 毫秒、手指没动超过 10px 打开菜单，同首页列表的长按（#504）。编辑模式里照旧按在端点附近拉线。
- “添加小号”的配对屏在 Bot 菜单旁边弹出同一个 `Form`，标题“添加小号”，没有步数。

### `rh bot rm`

照[架构](../architecture.md) §14.8，不含交给程序的部分。网页的“删除 Bot”经 `/api/act` 的 `rh` 发 `rh bot rm <Bot 的 Rhodium ID>`，同 `rh pair`（架构 §8.5.1）。

### 主窗口自动设

照[架构](../architecture.md) §8.5。写配置和 `rh bot` 写 Bot 表一样：先写临时文件、读回检查、再换掉原文件；写不了就只记日志，不挡建 Bot 和配对。

### 首页的引导

已做（#780）。

## 测试决定

照 [v1 规格](v1.md#测试决定)的规矩：只测外部看得到的行为，测试名带故事编号。不连真的 QQ、飞书、Telegram：

- 建 Bot 的流程用假的扫码服务（QQ 的 `create_bind_task`、`poll_bind_result`，飞书的 `registerApp`），沿用现有 `--api-root` 和测试里的假平台。
- 接口测试（`test/board.test.ts` 或新文件）：
  - 开始一个流程：名字、平台、槽位不对的直接回原因；对的回 ID 和等扫码，带 SVG 二维码（672、674）。
  - 假服务报过期：状态里换了新二维码，事件流推了 `bot_flow`（675）。
  - 扫码完成带回账号：写进配置，Bot 当场连上，状态“完成”；没带回：状态“等配对”带配对码（677）。
  - 粘贴 token：核对不过回原因、什么都不写；核对过了写配置（676）。凭据不出现在任何回复、事件、日志、库里。
  - 取消：什么都不写（675）。
  - 只认看板自己的页面（§11）。
- 路由测试：没有主窗口时，扫码带回账号、第一次配对，各设一次主窗口；已有的不动（680）。`rh bot rm` 去掉 Bot、清配对和默认目标；主 Bot 拒绝（684、685）。
- `rh` 的终端测试：`rh bot` 照旧画码、照旧粘贴，背后走流程（686）。
- Playwright 冒烟，手机和宽屏各一：
  - “+”菜单和空白处菜单有“新建 Bot”；没有槽位时灰着（670、671）。
  - 向导走 QQ 扫码到“创建成功”，步数“第 1 / 2 步”“第 2 / 2 步”（672–674、677、679）。
  - 向导走 Telegram 到配对屏，模拟发码后变成“创建成功”（676–679）。
  - Bot 菜单：右键（宽屏）、长按（手机）打开，顶上写 Bot 名；添加小号出配对屏；主人列表去掉一个配对来的；删除确认后 Bot 不见了；主 Bot 的删除灰着（681–684）。

## 你来验收

在开发环境上，手机和电脑宽屏都看，浅色和深色各一遍：

- 首页没有槽位时的引导，按钮打得开新建、导入。
- 用网页建一个 QQ Bot：手机上点“在 QQ 里打开”走完；电脑上扫码走完。不用配对就“创建成功”。
- 用网页建一个 Telegram Bot：粘贴 token，到配对屏，私聊 Bot 发码，页面自己变成“创建成功”。
- 首次安装的环境（或没有主窗口的配置）：建完第一个 Bot，配置里多了主窗口，`rh send me` 推得到。
- 拓扑图上右键、手机上长按 Bot：添加一个小号；在主人里去掉它；删除一个不是主 Bot 的 Bot。
- 终端里 `rh bot`、`rh bot rm` 照旧能用。

## 不做的事

| 不做的事 | 什么时候再说 |
|---|---|
| agent 发起建 Bot（二维码发到 IM、token 经 IM） | 照旧在 Bot 程序第二段（[架构](../architecture.md) §14.9） |
| Bot 改名 | 少用，按需。现在照旧手改（`deploy/README.md`） |
| 网页上改 Bot 的 `label` | 按需 |
| 交给程序的 Bot（`app:` 目标）的新建和删除 | 随 Bot 程序 |
| 手机上的弹窗都改成居中 | 2026-11-17 定只改不用打字的；要打字的照旧从底部弹出 |
| 网页上设、换主窗口 | 按需；这次只做没有时自动设 |
