# 网页对话界面规格

这篇回答：网页这一期的第 2 步，也就是把槽位页改成对话界面，要做成什么样、满足哪些需求、怎么测、怎么交付、明确不做什么。

前置阅读：[术语表](../../GLOSSARY.md)、[产品说明](../product.md)、[架构](../architecture.md)、[IM 文字与交互规范](../im-style.md)、[v1 规格](v1.md)

这一步的范围在 2026-10-23 的拷问里定下。网页的整体规则写在[产品说明](../product.md) §7，页面和构建写在[架构](../architecture.md) §2，记录怎么整理、怎么实时更新写在[架构](../architecture.md) §7.7。这里只写需求、接口的变化、测试和交付。

## 问题

**对话淹在杂行里。**

- 现在的槽位页按行显示记录文件。Claude 的记录里，附件、排队、模式切换、标题这类杂行占七成多，实测只有 27–28% 是对话。
- 一页 50 行，常常只剩一两句话。
- 工具结果原样显示，最长的有 629KB，在手机上读不下去。

**回合进行中，页面上什么都不变。**

- 页面只在回合开始、结束这类事件时刷新。
- Telegram 的过程消息边写边改。网页反而比 IM 慢。

**对话排在最后。**

- 槽位页从上到下是进程、错误输出、最近事件，最后才是对话记录。
- 在手机上要翻过排障用的东西，才看到 agent 说了什么。

**看不出槽位在等你什么。**

- 挂着提问的槽位在看板上进了“需要你”，点进去却看不到问的是什么。
- TUI 模式的槽位只写着“TUI 模式”和 pane 名，要去终端才知道它在做什么。

## 方案

这一步做完后，点进一个槽位，看到的是一个聊天界面：你的话和 agent 的话一条条排下来，工具调用折成一行，正在写的话逐字出现。

手机上大致是这样：

```
← ✳ dev/main                                   [详情]    ← ✳ 是 Claude 的 logo
    运行中
在终端里（pane 3）       [在 herdr-web 里打开]    ← 只有 TUI 模式的槽位有

你：把 README 的错字改掉
▸ Read、Grep ×2                                 ← 两段话之间的工具，点开
agent：改好了三处……
▸ Edit ×3
正在跑 Bash bun test                      12 秒  ← 正在跑的工具单独一行
agent：测试过了，接下来▌                        ← 逐字出现的草稿，只有无头槽位有

审批：要运行 git push                           ← 挂着的提问，只读
回“允许”或“拒绝”。
10:42 超时，到 IM 里回答
```

这一步包含：

- 服务端把 Claude 和 pi 的记录整理成同一种消息块，按消息数分页。工具结果截短，展开时再取全文。
- 实时更新：有人在看的槽位，服务端盯它的记录文件；无头槽位另外推正文的逐字增量。
- 对话页：对话占满屏，进程和事件收进“详情”抽屉；工具折叠；往上翻自动加载更早的；“新消息”按钮。
- 只读的提问卡片。
- TUI 槽位的横幅和 herdr-web 链接。
- 宽屏左右分栏。
- 验收后新页换到原地址，删掉旧页。

全部在新页上做。新页先在 `/next/`，验收后换到原地址 `/`，旧页删掉（[架构 §2](../architecture.md#2-组件和职责)）。

## 用户故事

“用户”就是你本人。编号从 191 开始，164–190 留给 Bot 程序规格。

这里只列这一步要满足的需求。消息块怎么从记录里来，见[架构 §7.7](../architecture.md#77-对话记录)。

### 读对话

191. 作为用户，我想要点进槽位就看到对话占满屏，你的话和 agent 的话一条条排下来，各带时间，以便在手机上像读聊天一样读。
192. 作为用户，我想要 Claude 和 pi 的对话看起来一样，以便换了 agent 不用换一种读法。
193. 作为用户，我想要记录里附件、排队、模式切换这类杂行不出现，压缩对话、换模型、API 报错这类事显示成一行灰字，以便一屏里都是对话。
194. 作为用户，我想要我的话开头的来源行不混在正文里，改成一个小标签，例如“QQ 私聊”，以便正文干净，又知道这句是从哪发的。
195. 作为用户，我想要 agent 的话按 Markdown 显示，代码块用等宽字，以便读起来和 Telegram 里一样清楚。
196. 作为用户，我想要两段话之间连着的工具调用和思考并成一行，例如“Edit、Bash ×2”，点开是每个工具一行，再点开看参数和结果，以便工具多的回合也读得下去。
197. 作为用户，我想要很长的工具参数和结果先只显示开头，点“看全文”再取全文，以便手机上不用先等几百 KB 下载完。
198. 作为用户，我想要 pi 的思考折起来显示，Claude 的空思考不显示，以便需要时能看 agent 怎么想的。
199. 作为用户，我想要正在跑的那个工具单独一行，带运行了多久，以便知道 agent 正卡在哪一步。

### 翻页

200. 作为用户，我想要打开对话时停在最新的地方，往上翻到顶自动接上更早的，一路能翻回第一句，以便不用点“更早”，大记录也翻得动。
201. 作为用户，我想要往上翻着看时来了新消息，页面不跳，底部出一个“新消息”按钮，点了回到最新，以便读旧内容时不被打断。

### 实时

202. 作为用户，我想要回合进行中，agent 的每段话和每个工具调用一写进记录就出现在页面上，以便不用等回合结束。
203. 作为用户，我想要无头槽位的 agent 正在写的那段话逐字出现，写完换成记录里的那段，以便网页不比 Telegram 慢。
204. 作为用户，我想要断网或 Rhodium 重启后，页面自己接上，不丢一段、不重一段，以便不用手动刷新。

### 槽位的其他信息

205. 作为用户，我想要顶栏写着返回、槽位名、状态、agent 和模型，以便一眼知道在看谁。
206. 作为用户，我想要进程状态、错误输出和最近事件收在“详情”抽屉里，以便排查时一点就有，平时不占地方。
207. 作为用户，我想要槽位挂着提问时，对话底部有一张提问卡片：题目、选项、几点超时，写着“到 IM 里回答”，答掉后卡片消失，以便在网页上一眼看到它在等我什么。
208. 作为用户，我想要 TUI 模式的槽位顶部有横幅“在终端里”和 pane 名，带一个“在 herdr-web 里打开”的链接，对话照常实时更新，以便在手机上跟进度，要动手时一点就到终端。
209. 作为用户，我想要在电脑的宽屏上左边是看板、右边是对话，以便不用来回切。

### 页面

210. 作为用户，我想要看板首页不因为对话页变慢：对话页的代码进了槽位才下载，看板首屏照旧不超过 200KB，以便手机走中继时看板照样快。
211. 作为用户，我想要验收过后新页换到原地址，手机桌面上原来那个图标打开的就是新页，以便不用重新添加图标。
477. 作为用户，我想要电脑上鼠标移到看板上能点的地方，那里有一点淡淡的变化，亮色和暗色主题都有，手机上不变，以便一眼看出哪里能点。2026-10-27 验收时加的：原来输入框那一排都没有。

## 实现决定

这一节只写这一步定下的实现选择和接口。记录怎么整理成消息块、怎么实时更新，见[架构 §7.7](../architecture.md#77-对话记录)；页面、构建和用到的包，见[架构 §2](../architecture.md#2-组件和职责)。

### 已定的大方向

- 整理在服务端做。前端不解析 Claude 和 pi 的格式。
- 分页按消息数，不按行。
- 实时更新在现有的事件流上推，不加 WebSocket。逐字增量只在内存里，不入库（[架构 §7.2](../architecture.md#72-事件表)）。
- 不加 service worker，也不做网页推送。推送到第 3 步再定。后来定了不做，回合跑完另有未读和电脑上的跑完提醒，见[产品说明](../product.md) §7。
- 不加表，不加配置。

### 接口

旧页还在用的接口只加字段，不改原有的。切换以前，旧页照常能用。

| 路径 | 变化 |
|---|---|
| `/api/messages?slot=<槽位 ID>` | 新加。槽位当前对话的一页消息块，默认最新一页。`before=<位置>` 取更早的一页，`after=<位置>` 取新写的 |
| `/api/full?conversation=<对话 ID>&at=<位置>` | 新加。一块的全文：被截短的工具参数、结果、思考、系统行 |
| `/api/events?slot=<槽位 ID>` | 加 `slot` 参数。带它时，这条流另外推两种不带 `id` 的临时事件：记录长了、逐字增量 |
| `/api/slot` | 加字段：模型的显示名、TUI 时的 pane 名、挂着的提问 |
| `/api/transcript` | 旧页用。切换时和旧页一起删掉 |

几点说明：

- 消息块有哪几种、怎么分页、什么截短、位置是什么，见[架构 §7.7](../architecture.md#77-对话记录)。页面不用懂位置，原样带回。
- 每页带对话 ID。槽位换了对话，页面从新对话的最新一页重来，和第 1 步一样。
- 取全文按对话 ID，不按槽位。槽位换了对话以后，旧对话里的“看全文”照样能点。
- 挂着的提问：种类、题目和选项、截止时间。题目和选项的文字和推到 IM 的那条一样，用同一份写法（[IM 文字与交互规范 §4](../im-style.md#4-提问和审批)），不带按钮。
- 工具行的写法照 [IM 文字与交互规范 §3.1](../im-style.md#31-工具行两边共用) 的简略写法，不带 `🔧` 和方括号；展开后每个工具一行，参数照详细写法取。和 IM 不同的两点：
  - 不打码。看板只给你看。经你自己的反代开放时，反代能看到明文，这是你选的，见 [ADR-0013](../adr/0013-board-exposure-is-yours.md)。
  - AskUserQuestion、ExitPlanMode、TodoWrite 不进折叠那一行，但展开后列出来。

### 对话页

- 地址照旧：`#/slot/<槽位 ID>`。
- 手机上单栏：看板 → 点进对话，返回键回看板。宽屏左右分栏，左边看板，右边对话，中间能拖。
- 中屏没有分栏，打开对话就是[放大模式](../../GLOSSARY.md)（2026-10-28 定）。
- 宽屏上对话顶栏有一个放大按钮，点了进[放大模式](../../GLOSSARY.md)：左边换成一条窄侧栏，对话往左拉宽；同一个位置换成缩小按钮。
  - 原来 #285 做的是对话占满整页，2026-10-25 第 32 轮改成放大模式。地址、侧栏、缩小落在哪，都写在放大模式那篇规格里。
  - 手机和中屏上不显示这个按钮。
- 分栏宽度在这个标签页里记着。缩小回到原来的分栏宽度。
- 切列表和拓扑图时，对话留在原处，不重新画；agent 正在写的那段接着往下写，开头不丢（#285）。
- 顶栏：返回、agent 的 logo、槽位名，下一行是状态。模型不写在这里，写在输入框下面的按钮上（网页能写那一步改的）。
- agent 用它自己的 logo 表示，不写“用 Claude”。看板的槽位卡片和“详情”抽屉也一样，logo 都在名字前面。
- 点右上角开“详情”抽屉：进程、错误输出、最近事件，内容和第 1 步的槽位页一样。
- 工具调用按类型配图标（#206）。颜色只有四种：看（读文件、搜索、网页）、改文件、终端命令、子 agent。其余的和思考是灰的。
- 折叠那一行、展开后每个调用一行、正在跑的那行都带图标。
- 出错的调用图标变红，后面跟一个红色小圆叉（lucide `CircleX`），读屏读作“出错”。
- 折叠着的那一行标出哪一项出错、错了几次（2026-10-31 定，#495）：
  - 里面有调用出错，那一类的图标变红。
  - 出错的那一项后面紧跟一个红色小圆叉。这一项调用了不止一次，圆叉后面写错了几次，例如“Bash ×4”后面圆叉加“1”，是四次里错了一次。只调用一次的，只有圆叉。
  - 折进“另外 N 次”的调用出错了，在“另外 N 次”后面同样标一个，数字是它们出错的合计。
  - 读屏读作“出错 1 次”这样，只有圆叉的读作“出错”；鼠标移上去的提示一样。
  - 行尾不再写“出错”。原来整行只有一个“出错”，看不出是哪一项错了、错了几次。
  - 手机上这一行照常折行，圆叉和它那一项不分开。
  - 一项的名字和它的“×N”在一行放得下时也不分开，例如“Bash ×2”不拆成两行（#501）。IM 里的写法不变。
  - 一项长到一行放不下时才拆开：名字放得下就在“×N”前面换行；名字本身比一行还长就在名字里折行，对话不横向滚动。
  - 出错又没有“×N”的一项，名字放得下、加上圆叉放不下时，在名字最后一段前面换行，不在最后一个字母前面。最后一段是最后一个“.”“_”“-”后面那段，或者驼峰写法里从大写字母开始的那段，20 个字符以内。
  - 箭头固定在这一行的最右边，折不折行都一样，上下几行的箭头排成一列（#501，2026-11-01 定）。展开后每一步那一行也一样，出错的圆叉挨着箭头。
  - 折成几行时，左边的图标和右边的箭头都对着第一行，不对着几行的正中（#501）。
  - “另外 N 次”很短，不管出没出错都不从中间断开，带圆叉时连圆叉一起换行。
  - 圆叉和数字用主题里的红色，圆叉和行尾的箭头一样大，数字用小一号的等宽数字，浅色深色都一样。
- 正在跑的工具（怎么认出来见[架构 §7.7](../architecture.md#77-对话记录)）单独显示在最后，带运行了多久，每秒走一次。它有了结果，或者后面来了别的块，就并回上面那一行。
- 逐字增量拼成的草稿接在最后，用 Streamdown 渲染，Markdown 写到一半也不乱。草稿什么时候换成记录里的那段，见架构 §7.7。
- agent 的话里，表格比对话那一栏宽时，在自己的框里横向滚动；代码块关了自动换行时也一样。对话那一栏不跟着变宽，整个对话也不横向滚动（#488）。行内代码和长链接照旧折行。
- 你的话上方的文字来源标签（`rh send`、子槽位汇报）一行放不下时折行（#510，2026-10-31 定）：
  - 字全显示，不截断，也不在标签里横向滚动。
  - 例如 360px 宽的手机上，`槽位 HomeProject/homehelp，经 rh send` 折成两行，第二行是“rh send”。尽量不让最后一行只剩一个词。
  - 一行时照旧是药丸。两行时是圆角方块，不像压扁的药丸。
  - 412px 宽（Pixel 7）的手机上放得下，和原来一样。
  - 你的气泡那一栏，包括还在发送的那条，不比对话那一栏宽。标签再长，对话也不横向滚动。
- 你的气泡里，包括还在发送的那条，很长、不带空格的一段（路径、哈希、链接）在哪个字符处都能折行，每行塞满（#512，2026-10-31 定）：
  - 原来它只在 `-` 这样少数几处断开，折行后中间会剩一行只有几个字符。
  - 连着 24 个以上、中间没有空格的半角字符算一段。正文里的英文词没这么长，照旧不从中间拆开。
- 没能发出去的那条，气泡和还在发送时一样宽。红字原因、“不发了”和“重试”两个按钮在气泡下面一行，靠右（#553 审查时改，2026-11-01）。原来两个按钮在气泡左边，手机上把长消息挤成细长的一条。
- agent 的话里的代码块（#498，2026-10-31 定）：
  - 一块一个框。没有空的顶栏，也不框套框。
  - 框顶一条窄行。左边是语言名，字小、灰色、等宽。右边两个图标按钮：自动换行、复制。
  - 代码块没写语言时，语言名写 `text`，和 T3 Code 一样（2026-10-31 定，#507）。
  - 按钮的可点区域是 44px，顶行不因此变高。
  - 复制：复制这块代码，原样，不多加末尾换行。图标短暂变成对勾。复制失败时弹提示“没能复制。”。
  - 自动换行默认开。在任何一块上点一下，这一页和所有对话里的代码块一起换行或取消。
  - 这个选择存在这台设备的 `localStorage`，和主题一样。用不了存储的隐私窗口就不记。
  - 换行时长链接也能断开，每行的缩进保留。
  - 换行时续行对齐缩进（2026-10-31 定，#507），照 Expressive Code 的 preserveIndent：
    - 一行折下来的部分从这一行的缩进处开始，不退回行首。
    - 缩进很深时，续行最多缩进到框宽的三分之一，手机上也留得出地方写字。行首的缩进照原样显示，只在框边截住。
    - 缩进后面放不下第一个词时，第一行只有空白，字从下一行续行的位置开始。
    - tab 按显示的宽度算。看板的 tab 宽 4 格。
    - 复制照旧是原样，tab 不变成空格。
  - 关了以后，长行在框里横向滚动。滚动条是看板自己那种细的圆角滚动条，没有箭头。
  - 关了以后的左右留白和渐隐（2026-10-31 定，#507），照 T3 Code 表格用的 Base UI ScrollArea 渐隐：
    - 左右留白在代码上，不在滚动层上。滚到最右时，最后一个字离右边框也留着这段距离。
    - 一边还有没露出来的字时，这一边渐隐：离框 12px 以内的字完全透明，再往里 24px 逐渐变实。
    - 渐隐的宽度不超过这一边还能滚多远，所以一开始滚，左边的渐隐慢慢长出来，不会突然出现。
    - 放得下、不用滚的代码块没有渐隐。换行时也没有。
    - 底部的细滚动条不被淡掉。手机上滚动条浮在字上、不占地方，渐隐就从上到下整条都淡（#577）。
    - 正在写的代码块里一行变长，渐隐跟着更新。
  - 代码块不限高，多长都整块展开，框里不竖着滚。原来 Streamdown 的代码块最高 400px。
  - 没有语法高亮，和原来一样。
  - 工具输出和你说的话不是代码块，不变。
- agent 的话里的表格（#502，2026-11-01 定）：
  - 一张表一个框，不框套框。框的圆角、边框和底色和代码块的一样。
  - 单元格里的字离框左边的距离和代码块的字一样，表格下面紧跟着代码块时两边的字对齐。
  - 没有按钮。
  - 宽了在框里横向滚动，滚动条是看板自己那种细的圆角滚动条，没有箭头。
  - 格子里的英文词、路径和长串不在中间断开（#559），链接也一样。太长就把表格撑宽，进上一条的横向滚动。中文照常可以在两个字之间折行。
  - 表格被长串撑宽时，别的列不被压到只剩一个词或表头那么宽：
    - 一格至少有它的字排成一行那么宽，所以 `进行中` 这类短格子不折行。
    - 最多保留 12 个汉字那么宽，也不超过框宽按列数平分那一份的四分之三。字多的格子在这个宽度里折行。
    - 剩下的四分之一按字多字少分，所以每列都是长句时，字最多的那列最宽，不是各列一样宽。
    - 例：手机上 `| 文件 | 说明 |` 表，一格是长路径，说明那列比三分之一个框宽多一点，一句二十来个字的说明排四行。
  - 横向滚动时两边渐隐，和关了自动换行的代码块一样：哪边还有没露出来的，哪边渐隐。表头底色和行线也一起淡掉。
  - 表头底色整条一样，列和列之间没有接缝。
  - 不限高，多长都整张展开，框里不竖着滚。原来 Streamdown 的表格最高 300px。
  - 经 Markdown 画的表格都这样：agent 的话、草稿、预览、提问卡片、思考全文。
- 断线时顶栏标出“已断开”，重连后自己补齐。
- 看板的顶栏（#286）：
  - “Rhodium”后面一个色点。连上时色点旁边写往返延迟，例如 `38ms`。连接中、重连中照旧写字。
  - 点色点和延迟进 Rhodium 自己的页面。原来那个“状态”链接去掉了，给最右边的齿轮让地方，360px 宽的手机上一行放得下。
  - 顶栏按自己的宽度排（#635，2026-11-10 定）：
    - 380px 以上用宽松的排法：字大一号，间距和“列表”“拓扑图”的内边距大一些。延迟是三位数也放得下，齿轮不出卡片的右边。412px 宽的手机是这样。
    - 窄一些的用紧凑的排法，例如 390px 宽的手机、1024 宽分栏时默认宽的左栏。
  - 宽屏（`lg` 以上）上，延迟后面再加一个小图标（lucide `Activity`），看得出这里能点。手机上不加。
  - 宽屏上分栏时，左栏太窄、顶栏放不下这个图标，也不加。
  - 延迟每 30 秒量一次，请求 `GET /api/ping`，它什么都不回。页面在后台时不量，回到前台马上量。超过 300ms 色点变琥珀色。
  - 最右边一个齿轮，点开是设置卡，里面切主题：跟随系统（显示器图标）、浅色（太阳）、深色（月亮）。选择存在这台设备的 `localStorage`。2026-11-06 起是齿轮，原来是一个在这三样之间轮换的主题按钮。
  - 页面画出来之前，`theme.js` 先把选的主题设到根元素上，不会先闪一下另一种颜色。它是单独的文件，因为页面不跑内联脚本。
  - 宽屏（`lg` 以上）上和对话顶栏一样高，中线对齐，下面一条线，连这条线 57px 高（#617）。改对话顶栏的高度，这里要跟着改。
    - 分栏时这条线和对话顶栏下的线连成一条。
    - 没开对话时，这条线横贯整页。
  - 宽屏上顶栏钉在顶上，不跟着下面的列表滚（#635，2026-11-09 定）：
    - 分栏时钉在左栏顶上，和拓扑图页、放大模式的侧栏一样。没开对话时也一样钉住。
    - 列表在线下面滚，滚动条从线下面开始。所以线一直画到分栏线，不在滚动条那一截断开。
    - 顶栏和列表给滚动条留一样宽的空，所以列表出了滚动条，两边照样左右对齐，列表也不跳。
    - 列表把打开的那一行滚进视野时，这一行露在线下面，不被顶栏挡住。排在最后的，连卡片的底边一起露出来。
    - 没开对话时，焦点不在哪里或在顶栏上，按 PageDown、空格、↑↓、Home、End 滚列表，和原来滚整页一样。焦点在顶栏的按钮上时，空格照旧是按这个按钮。
    - 从 Rhodium 的页面回到列表，列表从最上面开始，和原来整页滚动时一样。
- TUI 横幅里的链接指向看板同一个主机名的 8787 端口，也就是 herdr-web。herdr-web 不能从地址直接打开某个 pane，所以只到它的首页，横幅上写着 pane 名。
- 提问卡片固定在对话底部。几条同时挂着就叠几张。卡片上没有能点的按钮。
- 文字照 [IM 文字与交互规范 §1](../im-style.md#1-原则)：安静克制，不用 emoji。图标用 lucide。
- 鼠标移上去（故事 477）：
  - 只在能悬停的指针上有，用 Tailwind 的 `hover:`，它只在 `(hover: hover)` 下生效。手机上不变。
  - 没有底色的图标按钮：一个淡的圆底，前景色 5%，比 44px 的点按范围小一圈（`index.css` 的 `hover-round`）。灰的图标同时变成前景色。
  - 列表的行、拓扑图上的节点：底色加深一点，前景色 4% 混进卡片的底色，和放大模式侧栏的行一样。
  - 输入框和别的输入：边框深一点，聚焦时照旧是聚焦的颜色。
    - 例外是对话页底下的输入框和终端下面的输入框：悬停、聚焦时边框都不变色，一直是平常的边框（#576，2026-11-06 定）。
  - 有底色的按钮（发送键、确认）：底色淡一点，和 shadcn 的按钮一样。
  - 文字按钮、折叠的标题：灰字变成前景色。
  - 命令面板和跳转框：鼠标移到哪一条，哪一条就是选中的，和方向键选的是同一个。
  - 只改颜色，不改大小、不挪位置。
- 用 Tab 键聚焦小按钮（#503）：
  - 焦点框沿着看得见的那一块的边画，不画在 44px 的点按范围上，所以不戳出所在的框。
  - 没有底色的图标按钮，画在悬停的那个圆上（`hover-round`）。
  - 44px 里套着一个小按钮的，例如发送键、对话顶栏的图标和“详情”，画在里面那个按钮上（`index.css` 的 `focus-child`）。
  - 新建槽位里选 agent 的三个按钮装在一个裁边的框里，焦点框也画在里面那个 36px 的圆角方块上，和框的边隔开，四个角一样圆。没选中的平时是淡的，键盘聚焦时不淡。
  - 看板顶栏的“列表”“拓扑图”也装在一个裁边的圆角框里。焦点框画在按钮里面，贴着框的内沿；第一个的左边两个角、第二个的右边两个角和框里面一样圆（2026-11-09 定）。
  - 列表里工作区的名字（点它折起卡片），焦点框是一个圆角框，框住名字和箭头，上下离字一样远，不压在下面卡片的边上。名字和卡片的位置不变（2026-11-10 定）。
  - 底色铺满 44px 的按钮（例如拓扑图详情里的关闭、收起详情），焦点框照旧画在 44px 上，它们所在的行不比它矮。
  - 拓扑图详情里的“操作”挂在状态那一行上，44px 的框往下一直伸到详情的底边。手机上收起的详情所以是 66px 高，框整个在里面，聚焦时详情不滚。框的底边贴着详情的底边。焦点框只框住那三个点，是里面一个 32×24 的圆角框，不框整个 44px，免得看着像一个比“打开槽位”低 12px 的键（#560）。鼠标悬停和按下的底色也只铺在这一块上。
  - 输入框底行的“模型和思考强度”和左右的键一样，焦点框是一个 36px 高的圆角框，在 44px 里面。左边的字和右边的箭头离焦点框一样远（#560）。
  - 拓扑图顶上的路径（总览、工作区、槽位）和这一行一样高，焦点框的外沿离按钮的边 2px，不压在这一行的上下边框上。
  - 只在键盘聚焦时有（`:focus-visible`）。鼠标点、手指点都不出焦点框。

## 测试决定

照 [v1 规格](v1.md#测试决定)的规矩：只测外部看得到的行为，测试名带故事编号。

- 消息块的整理在 `bun test` 里测，不用浏览器。输入是记录文件的片段：从 `test/fixtures/transcripts/` 里的真记录挑，再补几段手写的边角，例如结果比调用晚一页、Claude 另存的大结果、不是 JSON 的行、空思考、pi 的 `compaction`。
- 接口在 `test/board.test.ts` 那一层测：分页一路翻回第一句不重不漏；`after` 只给新写的；截短和全文；`slot` 参数的事件流在记录长了时推一条，没人看的槽位不盯；假 agent 报的正文增量推给看着这个槽位的连接，别的连接收不到。
- 前端里有逻辑的部分写成纯函数单测：调用和结果按 ID 拼上；草稿被记录换掉；重连后从上次的位置接上，不重一段。
- Playwright 冒烟测试（`test/board-smoke.test.ts`）再加三条，真 Chromium、手机尺寸：
  - 假 agent 跑一个回合，草稿逐字出现，最后换成记录里的那段。
  - 一段工具折成一行，点两层看到截短的结果，点“看全文”看到全文。
  - TUI 槽位有横幅和链接；有提问时卡片出现，答掉后消失。
- 看板首屏和对话页那一包的大小，都由 `test/build.test.ts` 守着，上限见[架构 §2](../architecture.md#2-组件和职责)。
- 悬停（故事 477）：冒烟测试在电脑尺寸上把鼠标移到操作条的几个按钮上，样子变了；手机尺寸上不变。输入框悬停、聚焦时边框都不变，电脑和手机尺寸都测（#576）。别的地方靠截图看。
- 真 Claude、真 pi 的记录格式变了，靠里程碑验收发现。
