# 对话页的宽度、刻度条和 rh send 规格

这篇回答：2026-11-20 定的对话页改版在 `main` 上落地的部分要做成什么样：`rh send` 发给你的话怎么显示，工具折叠行展开后不重复摘要，对话栏的三档宽度，右边的刻度条，`rh send` 怎么从标准输入读正文，系统提示和回执怎么改；怎么测、怎么验收、明确不做什么，怎么拆工单。往来行和消息块回合标记已拆到 `web-exchanges` 分支，不在这份规格的当前范围里。

前置阅读：[术语表](../../GLOSSARY.md)、[产品说明](../product.md)、[架构](../architecture.md)、[v1 规格](v1.md)、[网页对话界面规格](web-chat.md)、[网页图片、复制和引用规格](web-images.md)、[网页放大模式规格](web-maximize.md)

这些在 2026-11-20 看过两轮原型以后定下。各项事实写在上游，这里不重复，只写需求、做法、测试和交付：

- 行为：[产品说明](../product.md) §5.5（内部回合的最终回复只写一句现状）、§5.9（`rh send` 的正文可以从标准输入给，没推送时的回执）、§7“对话页的宽度、刻度条和 rh send”。
- `rh` 读标准输入和命令提取：[架构](../architecture.md) §7.7、§9.1。
- 词：[刻度条](../../GLOSSARY.md)、[内部回合](../../GLOSSARY.md)。刻度条就是讨论时说的“右侧时间线”，改名是为了不和详情里的“对话时间线”混。

这篇用到几个词：

- 发给你的：agent 用 `rh send me`、`rh send <平台名或 Bot 名>` 发的。
- 宽、窄：按对话栏自己的宽度分，40rem（640px）起算宽。手机竖着是窄，宽屏分栏里的对话是宽。

## 问题

- agent 在内部回合里常把 `rh send me` 说过的话在最终回复里再讲一遍。没推送时的回执还叫它“之后要说的话写在回复里”。
- `rh send me` 的正文只能写在命令行上，多行和 Markdown 要和 shell 的引号较劲；单个换行在网页上被并成一行。
- 工具折叠行展开以后，行上的摘要和下面每一行说的一样。
- 宽屏上对话栏固定 48rem，表格、代码多时窄。长对话里找自己说过的一句话只能往上翻。

## 方案

- 发给你的整条显示在那次调用所在的折叠行下面，前面带铃铛，排版和 agent 的回复一样，单个换行照原样换行。
- `rh send` 的正文可以从标准输入给。系统提示改成：内部回合里要你看的走 `rh send me`，最终回复只写一句现状。
- 工具折叠行和其中每一步展开后，行上只留名字或步数。
- 对话页的“⋯”里加三档宽度。对话右边一条刻度条，一条短横对应你的一句话。

## 用户故事

### 发给你的

701. 作为用户，我想要 agent 用 `rh send` 发给我的话整条显示在折叠行下面，前面带铃铛，排版和 agent 的回复一样，单个换行照原样换行，以便和 IM 里看到的一致。

### 折叠行

703. 作为用户，我想要工具折叠行展开后，行上只写“N 步”，只有一步的只写名字；里面每一步展开后也只留名字，以便不重复下面写着的东西。

### 宽度

704. 作为用户，我想要在对话页的“⋯”里选对话栏的宽度：标准、宽、铺满，这台设备记住，以便表格和代码多时看得宽一点。
705. 作为用户，我想要三档看起来一样宽时（例如手机上），菜单里没有这一行，以便不出没用的选项。

### 刻度条

706. 作为用户，我想要对话右边有一条刻度条：我的每句话一条短横，屏幕上正看着的那条更长更深，以便知道自己在长对话的哪里。
707. 作为用户，我想要电脑上用鼠标指着短横时看到预览，点了跳过去，以便快速找回某句话。
708. 作为用户，我想要窄屏或触屏上刻度条是一条细线，点开是列表，点一项跳过去，以便手机上也能用。

### agent 那边

709. 作为用户，我想要 agent 能用 `rh send me -` 从标准输入给正文（例如 heredoc），以便多行和 Markdown 不受命令行引号限制。
710. 作为用户，我想要内部回合里 agent 要我看的只走 `rh send me`，最终回复只写一句现状、称我为“你”、不重复 `rh send me` 说过的，以便不重复发。
711. 作为用户，我想要没推送到 IM 时，回执告诉 agent 这条已在网页上整条显示、回复里不用再写一遍，以便它不重复。

## 实现决定

### 发给你的

- 前面一个铃铛图标（灰色，和第一行对齐），后面一条竖线，再后面是正文。
- 正文按 Markdown 显示，用和 agent 的话同一套样式（`MARKDOWN`）。
- 单个换行照原样换行，代码块里不动。agent 的话照旧按 Markdown 的规矩，单个换行不换行。
- 带的图和文件照现在的样子跟在正文后面。
- 铃铛的 `aria-label` 写“发给你的”。
- 位置：照旧在那次调用所在的折叠行下面。

### 折叠行

- 工具折叠行展开后，行上的摘要隐去但留着位置，换成“N 步”（N 是里面的行数）；只有一步的，只写这一步的名字，不写参数。图标和箭头不动，行高不变。
- 里面每一步展开后，只留名字（工具名，或“思考”），参数和思考的开头隐去。

### 宽度

- 在对话页顶栏“⋯”菜单的第一行：左边一个左右箭头图标和“宽度”，右边三个并排的选项“标准”“宽”“铺满”，当前的高亮。点了就换，菜单不关，好让你看着对话选。样子同终端的“字号”那一行。
- 三档：
  - 标准：对话栏最宽 48rem，就是现在的样子。
  - 宽：最宽 64rem。
  - 铺满：不限宽，两边留 1.5rem；对话栏是宽的时，右边多留出刻度条的地方。
- 跟着变宽的：消息、输入框、待发队列、提问卡片、信息卡，现在都是 48rem 的那些。终端那一面不变。
- 记在这台设备的 `localStorage` 里，键名 `chat-width`。标准是默认，不存。
- 对话区不比标准宽（48rem 加两边的空）时，三档看起来一样，菜单里没有这一行。按对话区的宽度算，不按设备：分栏、放大、侧栏收起都会变。
- 只在对话那一面有。槽位在终端里时菜单里没有这一行。

### 刻度条

- 一条短横对应你的每句话：没有 `source`、或者 `source` 不是别的槽位（`槽位 …，经 rh send`）也不是 `Rhodium：…`（子槽位汇报、确认结果）的 `user` 块。
- 当前那条：屏幕顶下 100px 那条线以上的最后一项；滚到底时是最后一项。点选一项后，目标进入视野就高亮这一项，直到你下次手动滚动再按位置判断。当前那条更长、颜色更深。
- 少于两项时不显示。只算已经取到的块：往上翻得越多，项越多。
- 宽、而且用鼠标时：
  - 一列短横贴着对话区右边，竖着居中，最高占对话区的 70%。
  - 短横之间 9px。放不下时间距缩小，最小 3px；还放不下，只画以当前那条为中心、放得下的那一段。
  - 指着一条，它变长，左边弹出预览：第一行是你的 Bot 头像、“你”和时间；下面是开头两行，再加下一条回复的开头两行，前面一条竖线。
  - 点一条，平滑滚到那一项，顶上对齐。下方内容不足一屏时停在底部。
  - 预览用 Base UI 的 `Tooltip`。
- 窄、或者触屏时：
  - 贴着右边一条细线，短横更短更密，不能单独点。
  - 点细线弹出列表（Base UI 的 `Popover`）：每项一行字头（同上面预览的第一行）和一行开头，当前那项高亮并滚到中间。
  - 点一项，滚过去，列表关掉。
- 每条短横是一个按钮，`aria-label` 写“你：开头”。整条的 `aria-label` 写“刻度条”。
- 只在对话那一面有，终端那一面没有。

### `rh send` 从标准输入读

规则写在[产品说明](../product.md) §5.9，`rh` 怎么读写在[架构](../architecture.md) §9.1，页面怎么从命令里读正文写在[架构](../architecture.md) §7.7。这里只补：

- `-` 前后还有别的字时，`-` 当普通文字。
- 提示词只教 heredoc。别的给法（例如 `echo … | rh send me -`）照发，页面读不出正文，那一条只显示文件，没有文件就不显示。

### 提示词和回执

只改根槽位的两份系统提示（无头、TUI）、`rh send` 的帮助和一条回执。子槽位的不改：它的最终回复随汇报交给父槽位，本来就不用写成一句现状。

`src/prompt.ts` 无头那一份：

- 讲 `rh send me` 是什么的那条，最后一句“网页不算去处：你说的每一句话，网页上本来就看得到。”改成：
  > 网页不算去处。它发的话网页上整条显示，和你的回复一样排版。
- 讲推到哪的那条，“这一次发的内容网页上看得到，不用再写一遍；之后要说的话写在回复里就行。”改成：
  > 这时这条消息已在网页上整条显示，回复里不用再写一遍。
- 新加一条，紧跟在上一条后面：
  > - `rh send` 的正文用 Markdown 写，单个换行照原样换行。多行或带排版的，文字写成 `-`，从标准输入给正文，例如：
  >   ```
  >   rh send me - <<'EOF'
  >   正文
  >   EOF
  >   ```
- “别的消息开始的回合，最终回复不发回 IM。要让用户知道，用 `rh send me`。”改成：
  > - 别的消息开始的回合（内部回合），最终回复不发回 IM。要用户看的内容只走 `rh send me`。最终回复只写一句现状，例如在等什么，称用户为“你”；发过 `rh send me` 的，最终回复不再说一遍它的内容。

TUI 那一份照旧从无头那一份里挑几条拼起来（`headless.slice(...)`）。新加的那条也要进 TUI 那份；“别的消息开始的回合”那条照旧不进。

`src/commands.ts` 里 `rh send` 的帮助：

- 用法写成 `me|<平台>|<Bot 名> [--file <路径>]... [<文字>|-] | <工作区/槽位> <文字>|-`。子槽位那份写成 `me --file <路径>... | <工作区/槽位> <文字>|-`。
- “这一次发的内容网页上看得到，之后要说的话写在回复里就行。”改成“这时这条消息已在网页上整条显示，回复里不用再写一遍。”
- 加一句：“文字写成 - 时从标准输入读正文，例如 heredoc，多行和排版不受命令行引号限制。”两份帮助都加。

`src/router.ts` 没推送时的回执改成：

> 用户正在网页上看，没推送到 IM。这条消息已在网页上整条显示，回复里不用再写一遍。

## 测试决定

照 [v1 规格](v1.md#测试决定)的规矩：只测外部看得到的行为，测试名带故事编号。不用真对话做夹具：真对话里有私人内容，测试用手写的块和 `test/fixtures/transcripts/` 里现有的录制。

- 消息块（`test/transcript.test.ts`）：`send` 的 `-` 加 here-document，以及同一命令里发给槽位后再发给你的 `rh send`（701、709）。
- `rh`（`test/rh-send.test.ts`）：
  - `rh send me -` 读标准输入，去掉末尾一个换行；多行原样到 IM（709）。
  - 没有 `-` 时不读标准输入：给一个一直不关的标准输入，调用照样返回。
  - `-` 读到空的：只带文件的照发，什么都没有报用法错误。
- 系统提示和回执（`test/agent-prompt.test.ts`、`test/rh-help.test.ts`、`test/send-to.test.ts`）：新措辞在；TUI 那份有标准输入那条、没有内部回合那条；子槽位那份没变（710、711）。
- 刻度条单测（`test/ticks.test.ts`）：`ticksOf(folded(...))` 只收你的话（跳过槽位 `rh send`、子槽位汇报和 Rhodium 通知）并配上各自下一句回复，及 `visibleTicks` 窗口计算（706）。
- Playwright 冒烟（`test/board-smoke.test.ts`），手机和宽屏各一：
  - 发给你的那条带铃铛，单个换行是换行；折叠行展开后写“N 步”（701、703）。
  - 宽屏“⋯”里有宽度那一行，换成“宽”以后对话栏变宽，刷新后还是“宽”；手机上没有这一行（704、705）。
  - 宽屏用鼠标指着短横出预览，点了滚过去；手机上点细线出列表，点一项滚过去；内部消息不算刻度（706–708）。
- 对话页那一包的大小照旧由 `test/build.test.ts` 守着。

## 你来验收

在开发环境上，手机和电脑宽屏都看，浅色和深色各一遍：

- agent 用 `rh send me - <<'EOF'` 发一条多行 Markdown：网页上带铃铛、排版和回复一样、单个换行是换行；IM 里也是多行。
- 网页开着时 agent 在内部回合里 `rh send me`：回执是新措辞，最终回复只有一句现状，没有把通知再讲一遍。
- 工具折叠行展开后写“N 步”。
- 宽度三档在宽屏上都试一遍，刷新后记得；手机上菜单里没有。
- 刻度条：电脑上指着出预览、点了跳；手机上点开列表、点了跳；槽位之间 `rh send` 不算刻度。
