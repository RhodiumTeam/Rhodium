# 网页图片、复制和引用规格

这篇回答：网页上怎么看图（你发的、agent 发的、agent 在工具里读的）、网页拿到什么、交给 agent 的图怎么缩、收发的图留多久，以及整条消息的复制和引用，要做成什么样、怎么测、怎么验收、明确不做什么。

前置阅读：[术语表](../../GLOSSARY.md)、[产品说明](../product.md)、[架构](../architecture.md)、[IM 文字与交互规范](../im-style.md)、[v1 规格](v1.md)、[网页对话界面规格](web-chat.md)、[网页拓扑图规格](web-topology.md)、[网页能写规格](web-write.md)

这些在 2026-11-06 的第 35、36 轮拷问里定下，起因是一批用户反馈。网页这次先专注图片，整条消息的复制顺带做，再做工具结果里的图和引用某条消息。同一批里 `rh send` 的去处和汇报写在[产品说明](../product.md) §5.9、§6.1，设置和终端入口写在网页放大模式规格和[网页能写规格](web-write.md)。

这篇用到几个词：

- 媒体目录：状态目录下的 `media/`，收发的图片和文件按内容的 SHA-256 存在这里（[架构 §8.3](../architecture.md#83-媒体)）。
- 内容地址：一张图在网页上的地址，由它内容的哈希构成。内容不变，地址就不变。
- 预览：对话里先显示的那张小图，长边 800 的 WebP。
- 看图版：原图太大时，点开看的那张 JPEG，长边不超过 2576。
- 看图器：点开预览后，页面里铺满屏幕的那一层。

## 问题

**发出去的图，网页上只剩一行路径。**

- 网页上传图时，输入框里有一张小缩略图。对话记录接上之后，气泡里只剩 `[图片] <状态目录>/media/<哈希>` 这一行字。
- 从 IM 发来的图也一样。
- 首页列表和侧栏的最后一句话写成“你：[图片] /一长串路径”。

**哪里都看不到大图。**

- 看板没有能取媒体目录里文件的接口。

**agent 发的图和读的图，网页上都看不到。**

- agent 用 `rh send me` 发的话和图，网页上只是一行折起来的 Bash 调用，和别的工具一起折成“Bash ×2”这样一行，要点开才看得到。
- agent 用 Read 看截图，Claude 和 pi 的记录里存着这张图，网页上是一个空框。Codex 的 `view_image` 在记录里只有一个路径。

**对话记录越来越大。**

- Claude 的记录里一半是图片的 base64，多数来自 agent 自己用 Read 看截图。手机拍的照片原样交给 agent，记录里存的也是原图。
- 媒体目录从不清理。

**整条消息不能复制，也不能引用。**

- 网页上只有代码块能复制。手机上只能长按选字。
- IM 里能引用一条消息，网页上不能。IM 里的引用把原文整条（最多 1000 字）放在你的话前面，被引用的往往是 agent 自己刚说的话，它本来就有。

## 方案

```
你                                         11:22
┌────────────┐
│  [预览图]   │  这张截图里的报错是什么？            ← 你发的图，长边 800 的预览
└────────────┘
agent：是一个类型错误……
                                       ⧉  ❝   ← 复制、引用；手机上一直在
▸ Read                                         ← 点开，结果里是 agent 读到的那张图
```

点开预览：

```
┌──────────────────────────────────────────┐
│                                        ⤓ │  ← 下载原图
│                                          │
│          [原图从上往下盖住预览]           │  ← 双指缩放；点一下或按返回关
│                                          │
└──────────────────────────────────────────┘
```

引用一条回复：

```
┌──────────────────────────────────────────┐
│ ❝ 引用：是一个类型错误……             ✕ │  ← 点 ✕ 取消
│ 那第二处呢                               │
│ [✳ v] [Opus 4.5 high v] [>_]     [+] [↑] │
└──────────────────────────────────────────┘
```

这一步包含：

- 看板加一个只读的媒体接口，按内容地址给原图、预览和看图版。
- 对话里显示你发的图、agent 用 `rh send` 发给你的话和图、文件，agent 在工具里读的图。
- 看图器。
- 列表行写“你：[图片]”。
- 交给 agent 前把太大的图缩小；媒体目录留 90 天。
- agent 每段话下面的复制、引用，你的消息下面的复制；IM 和网页的引用都只带开头。

## 用户故事

“用户”就是你本人。编号接着已有的规格，从 561 开始。

### 看图

561. 作为用户，我想要我发的图，网页上传的和 IM 发来的，在对话里显示成图，不是一行路径，以便回头看得到我给了 agent 什么。
562. 作为用户，我想要 agent 用 `rh send` 发给我的话、图和文件，在对话里那次调用的位置直接看得到，不用点开，发的文件能下载，以便留在网页上的话不会藏起来，也不用去 IM 里找。
563. 作为用户，我想要 agent 在工具里读的图显示在那次工具调用的结果里：Claude 和 pi 记录里带着的图照样显示；Codex 的 `view_image` 只在那个文件在槽位目录里、文件头确实是图片时显示，不然只显示路径，以便看到 agent 看到了什么，网页又不会变成能读任意文件。
564. 作为用户，我想要对话里先显示长边 800 的预览，滚到了才下载，以便网不好时对话照样快。
565. 作为用户，我想要点开预览就在页面里全屏看：先铺着预览，原图从上往下一点点盖上去；双指缩放；点一下或按返回关；角上一个下载键，以便不离开页面，弱网时也先看到整张图。
566. 作为用户，我想要原图超过 2MB 或长边超过 2576 时，点开看的是长边不超过 2576 的 JPEG，约 1MB，小图不放大；下载键照旧给原图，以便手机拍的大照片点开也快，看到的和 agent 看到的一样清楚。
567. 作为用户，我想要首页列表和侧栏里的最后一句话写成“你：[图片]”，有文字时写文字再跟“[图片]”，不再显示路径，以便列表行干净。
568. 作为用户，我想要网页加载对话时不带任何图片数据，只带地址；看过的图浏览器缓存着，不再下载，以便图再多的对话打开也一样快。

### 交给 agent 的图和留多久

569. 作为用户，我想要交给 agent 的图长边超过 2576 时先缩到 2576 再交，消息里的路径照旧指原图，以便 agent 看到的不变，它的对话记录小很多。
570. 作为用户，我想要收到和发出的图片、文件和收发记录一样留 90 天；清掉的图，网页上那里写“图片已清理”，以便媒体目录不一直涨，旧对话里也知道图去哪了。

### 复制和引用

571. 作为用户，我想要 agent 的每段话下面一排图标“复制”“引用”，我自己的消息下面只有“复制”；手机上一直显示，电脑上鼠标移上去才显示，最后一条一直显示，以便一眼找到，又不占地方。
572. 作为用户，我想要复制出来的是 Markdown 原文，粗体是 `**粗体**`，代码块带围栏，以便贴回给 agent、贴进文档都不丢格式。
573. 作为用户，我想要点“引用”后，输入框上方出现一条“引用：开头几个字”，点 × 取消；发出去以后 agent 看到的和 IM 里引用一样，以便指着某条回复接着说。
574. 作为用户，我想要引用整条消息时只带开头约 100 字加“…”，IM 和网页一样；Telegram 里我选中的那一段照旧整段带上，以便引用一条长回复，我发出去的话不会也变得很长。

## 实现决定

### 已定的大方向

- 对话记录里不放图片数据，只放内容地址。这是“不让 base64 到处跑”在网页这一侧的做法。
- 预览和看图版在服务端按需生成：第一次被要时用 Bun 自带的 `Bun.Image` 生成，存盘复用。不加依赖，程序不变大。
  - 2026-11-06 实测：Bun 1.4.4 的 `Bun.Image` 能解码、缩放、重新编码 JPEG、PNG、WebP，GIF 只取第一帧。编进单文件后照样能用，程序大小不变。
  - 一张长边 800 的 WebP 约 50–100KB，生成约 0.16 秒；长边 2576 的 JPEG 约 1MB，约 0.4 秒。
- 不借 IM 平台的缩略图，也不让浏览器上传时出预览：那样只覆盖一部分来源，要写几套。
- 看图器先铺预览，再把原图（或看图版）的 `<img>` 叠在上面。普通 JPEG、PNG、WebP 浏览器本来就边下边从上往下画，还没画到的部分是透明的，下面的预览透出来。不自己写流式加载。
  - 2026-11-06 在 Chromium 和 Firefox 上实测过。iPhone 的 Safari 没测，验收时看。
- 不加表。媒体目录照旧按哈希存文件。

### 媒体接口

`GET /api/media?h=<64 位十六进制>[&v=preview|view]`

- `h` 只认 64 位小写十六进制。路径由服务端拼成媒体目录下的这个文件，不接受别的写法。
- 不带 `v`：原图或原文件。
- `v=preview`：预览，长边 800 的 WebP。原图长边本来就不超过 800 时，回原图。
- `v=view`：看图版。原图超过 2MB 或长边超过 2576 时，回一张 JPEG：长边超过 2576 的缩到 2576；不超过的不放大，只转成 JPEG。都不超过时回原图。
- 生成的预览和看图版存在媒体目录下自己的子目录里，按原图的哈希命名，之后直接回文件。
- 同一时间只生成一张，免得小服务器上内存一下涨上去。像素多到解不了的图，不生成，回原图。怎么限由实现的人定。
  - 实现时定的：超过 2²⁶（约 6700 万）像素的不生成。解开约 256MB，6400 万像素的手机照片还能生成。
- 只认图片的地方（预览、看图版）只对图片生效。不是图片的，`v` 不起作用，照原文件当下载回。
- 缓存头 `private, max-age=31536000, immutable`，和头像一样：地址就是内容，永远不变。
- 文件不在了（被清理了，见[留多久](#留多久)）：回 404。页面在那里写“图片已清理”。

### 安全

这个接口回的是 agent 和你传进来的任意文件，看板又是一张能写的页面。所以：

- 只回媒体目录里按内容哈希命名的文件。不按路径、文件名取任何东西。
- 图片只按文件头认：PNG、JPEG、GIF、WebP 四种，用 `src/media.ts` 里那张文件头的表（`MAGIC`）。只有它们按图片的 `Content-Type` 回。
  - 不用交给 agent 时的 `imageType()`（[架构 §8.3](../architecture.md#83-媒体)）：它还把超过约 3.75MB、边长超过 8000 的算成不是图片。拿它来认，手机拍的大照片就没有预览，只能下载。
- 别的一律当下载：`Content-Type: application/octet-stream`，`Content-Disposition: attachment`，不带文件名。
  - 接口只收 `h` 和 `v`，媒体目录里也只有哈希，服务端不知道名字。
  - 名字由页面给：下载链接带 `download` 属性，名字从消息块里来。同源的链接，响应头又没写名字，浏览器就用这个属性。
- 每个回复都带 `X-Content-Type-Options: nosniff`，浏览器不自己猜类型。
- 所以存下的 HTML、SVG 永远不会在看板的源下被当成页面打开。那样的页面能调写接口，也能开网页终端。
- 和 `/api/dirs` 一样，只认看板自己的页面发来的请求（[网页能写规格](web-write.md#只认看板自己的页面)）。页面里的 `<img>` 和下载链接都是同源请求，照常能用。
- Codex 的 `view_image`：只认槽位目录里的文件（取真实路径以后再比，符号链接指出去的不算），而且文件头是上面四种图片之一。符合的才复制进媒体目录、给内容地址；不符合的只显示路径。

### 消息块里的图和 `rh send` 的话

消息块怎么整理，见[架构 §7.7](../architecture.md#77-对话记录)。这里加三样，图和文件都只带内容地址，不带数据：

- 你的消息：正文末尾的 `[图片] <路径>`、`[文件] <名字>：<路径>` 行（[架构 §8.3](../architecture.md#83-媒体)），路径是媒体目录里按哈希命名的，就从正文里拿掉，换成这条消息的附件：种类、内容地址、文件名。现成的 `withoutMedia()` 已经认这种行。
  - 网页上传的和 IM 发来的都是这样，不另分。
  - 对不上这种行的（例如“没收到”的那句），照旧留在正文里。
- 工具结果里的图：Claude 和 pi 的记录里，工具结果带着 base64 的图。服务端整理这一页时解出来，按内容哈希存进媒体目录（已经有了就不再写），块里只放内容地址。
  - 不必每次都重新解：这一行写完就不会变，按（文件，位置）记住算过的地址就行。怎么记由实现的人定。
    - 实现时定的：记在内存里，键是记录文件的路径加块的位置，Codex 的 `view_image` 也一样。不进库、不写盘；进程重启后第一次读到再算一次，存进媒体目录时已经有了就不再写。
  - Codex 的 `view_image`：照上面[安全](#安全)那条处理。
    - 实现时定的：下载时用这个文件原来的名字。
    - 实现时加的：超过 50MB 的文件不读，只显示路径。
- agent 用 `rh send` 发给你的（`me`、平台名或 Bot 名，[产品说明](../product.md) §5.9）：
  - 文件：`rh` 返回前已经复制进媒体目录（[架构 §8.3](../architecture.md#83-媒体)）。`send_me` 事件的数据里记下每个文件的种类、内容地址、文件名，网页按它显示。
  - 文字：也在网页上直接显示。它不进 `send_me` 事件（聊天正文不进库，[架构](../architecture.md) §1），从对话记录里那次调用取。
  - 文字、图和文件都显示在对话里这次 `rh send` 调用的位置，不点开那一行也看得到。那次调用和别的工具折成一行时也一样。留在网页上、没往 IM 发的，只有这里看得到。
  - 怎么和那次 Bash 调用对上、怎么取出文字、画成什么样，由实现的人定。实现时定的：
    - 认调用：Claude 的 `Bash`、pi 的 `bash`、Codex 的 `exec_command`，命令里第一个 `rh send <词>`，这个词不带 `/`、也不是槽位 ID，就是发给你的。#593 的平台名、Bot 名照样认。
      - `rh` 要在命令开头：一行开头，或 `&&`、`;`、`|`、`then`、`do` 这类后面。`echo rh send me 好` 这样别的命令的参数不算。
      - here-document 里的行是别的命令读的内容，不算。
    - 结果到了才知道：页面先拿到调用那一行、`rh send` 还没跑时，块里还没配上事件，也可能配上了别的调用的事件。等它的结果到了，页面从调用那一行重读一次，换上重读出来的这一块。只带文字的也一样。
    - 取文字：照 shell 的写法读命令，认引号和反斜杠，`"$(cat <<'EOF' … EOF)"` 整段算一个词。`--file` 后面的是文件，余下到 `&&`、`;`、换行这类为止的词连起来是文字。变量不展开。
      - 不在引号里、在一个词开头的 `#` 到行尾是注释，不算。`a#b`、`"#"`、`\#` 照原样算字。
    - 发没发出去，看事件，不看整条命令成没成：
      - 每次发成的 `rh send` 都有一个 `send_me` 事件。只带文字的也有，只是不带数据。
      - 页面只显示配上了事件的调用，文字也一样。
      - 整条命令成没成和 `rh` 发没发是两回事：`rh send me 好; false` 发了，命令却报错；`if false; then rh send me 好; fi` 没跑，命令却成功。
      - 一条命令里写了两次的，例如 `a && rh send me 过了 || rh send me 挂了`，只读第一次的文字。事件里不带文字，分不出发的是哪一句，挂了时页面照样显示“过了”。这种很少见，先不管。
    - 对上事件：在这个槽位的 `send_me` 事件里找文件数一样的（只带文字的算 0），取离这次调用最近的，一个事件只配一次调用。调用报没报错都一样配。
      - 离调用多远，按从调用那一行到它结果那一行的这一段算，落在这一段里的算 0。`rh send` 等你审批、或排在一条慢命令后面，事件会比调用那一行晚几分钟，但一定在结果之前。
      - 落在这一段里的不止一个时，取离结果最近的：`rh` 返回以后才写结果，它自己的事件紧挨在结果前面。
      - 比调用早的事件不配，结果在不在这一页都一样。调用的时间是命令开始的时间：
        - Claude 和 pi 先写调用那一行再跑命令，按这一行的时间算。
        - Codex 的调用和结果在命令跑完时一起写，按结束的时间减去它记下的 `duration` 算。
        - 不然没跑的 `rh send` 会拿走前面一次真发出去的事件。例如先 `rh send me 开始跑测试`，半分钟后 `bun test || rh send me 测试挂了`，测试过了。网页开着时接着往后读，这一段从第二次调用那一行开始，第一次的调用不在这一页上，第二次就会配上第一次的事件，显示一句没发过的“测试挂了”。
      - 结果不在这一页的，只按调用那一行往后算。
      - 超过两分钟的不配。
    - 画成：折叠的那一行下面一段，左边一条细竖线；文字照 agent 的话那样画，图和文件行跟在下面。

块里每个附件带宽高，页面先按比例留好位置，图到了不跳。读不出宽高的，留一个固定大小的灰框。

### 页面

- 预览：`<img loading="lazy">`，滚到了才下载。宽度不超过对话那一栏，长边最多 800 个 CSS 像素以内按比例缩。高也不超过屏幕高的六成（实现时加的），竖着的手机截图不会占满一屏。
- 文件：一行，图标、文件名，点了下载。
- 看图器：
  - 点预览打开。铺满屏幕，深色底，图按比例放进屏幕。
  - 先铺已经加载好的预览，看图版（不需要缩的就是原图）叠在上面。
  - 双指缩放、拖动。缩放用浏览器自己的就行，不另写手势。
  - 点一下（没在缩放时）、按返回键，都关掉；电脑上按 Esc 也关。打开算一步历史，所以返回键关的是看图器，不是离开对话。
  - 右上角一个下载键，给原图，文件名用发它时的名字，没有就用哈希加扩展名。
  - 读屏念“图片”，下载键念“下载原图”，关闭键念“关闭”。
- “图片已清理”：媒体接口回 404 的，预览的位置换成一个灰框，写“图片已清理”，不能点。
- 列表行和侧栏的最后一句话：你的消息里的附件行不进这一行。有文字时写“你：<文字> [图片]”，只有图时写“你：[图片]”；是文件就写“[文件]”。
- 复制和引用：
  - agent 的每段话下面一行，靠左两个图标按钮：复制（lucide `Copy`）、引用（lucide `Quote`）。一次回复里夹着工具调用的，被拆成几段，每段各有一行。你的消息下面只有复制，靠右。
  - 手机（不能悬停的指针）上一直显示。电脑上鼠标移到这条消息上才显示，对话里最后一段 agent 的话一直显示。键盘聚焦到按钮时也显示。
  - 电脑上这一行压进段与段之间的空隙，不另占一行：每段下面只比工具那一行下面多空约 8px。
  - 只有图片或文件、没有文字的消息，下面不放复制。
  - 复制：复制这段的 Markdown 原文，就是消息块里的 `text`，不截断。你的消息复制正文，不带来源行和附件行。图标短暂变成对勾；失败时弹提示“没能复制。”，和代码块的复制键一样。
  - 引用：在输入框上方加一条，图标、“引用：”、被引用那段的开头，一行放不下截断，右边 ×。再点别的引用，换成新的。发出去以后这条消失。
  - 发出去时，正文前面加上引用，写法和 IM 里的引用一样：被引用的原文截到开头约 100 字，后面加“…”，每行前加 `> `，空一行接你的话（[产品说明](../product.md) §5.4）。
  - 引用在页面里拼（#591 定），拼好的正文照常发给看板，服务端不另分。待发的气泡按正文开头认出对应的那条消息（[网页能写规格](web-write.md#待发队列)），用的是拼好以后的正文。
  - 命令不带引用，排着的也一样，引用条留着：`/` 开头的（Rhodium 的、交给 agent 的都算），只有 `!` 的。开头的 `!` 照旧放在最前面。
  - 没发的引用和没发的附件一样按槽位留着：切到别的槽位再回来，引用条还在；页面重新加载就没了。
  - 页面上显示引用的地方，都是一行、去掉 Markdown 记号（`*`、反引号、围栏、行首的 `#` 和 `>`），放不下截断：引用条，你的气泡开头的引用（IM 里引用的也一样，浅色，前面一个引用图标）。IM 引用里附件那几行只显示“[图片]”“[文件]”，不显示存放的路径。待发队列里带引用的那一行，和列表行、侧栏的最后一句话，只显示你的话，前面一个引用图标；只带引用、没有你的话的，显示引用的开头（#607）。列表行和侧栏里，带附件、没有你的话的，照旧写附件（“你：❝ [图片]”），不写引用。发给 agent 的照旧是原文。

### 交给 agent 前缩小

- 能直接给 agent 看的图（[架构 §8.3](../architecture.md#83-媒体)），长边超过 2576 的，交之前缩到长边 2576。缩过的那份只用来交给 agent，存在媒体目录下自己的子目录里。
- 消息里的 `[图片] <路径>` 照旧指原图。agent 要原图，自己去读。
- 2576 是 Claude 看图的长边上限，再大它的服务器也会缩，所以 agent 看到的不变。
- 原来因为太大只给路径、不直接给看的图，缩完是不是改成直接给看，由实现的人定。
  - 实现时定的：不改，照旧只给路径。给不给看，照旧在收下时按原图定（[架构 §8.3](../architecture.md#83-媒体)），这次只动交给 agent 的那份有多大。
- 实现时定的：
  - 缩过的那份照原图的格式存，GIF 只取第一帧，存成 PNG。照片里记的方向先转正。
  - 缩完不比原图小的，照旧交原图。
  - 像素超过 2²⁶ 的不缩，照旧交原图，和看图版的上限一样（见“媒体接口”）。
  - 缩图和生成网页的预览、看图版排同一条队，同一时间只生成一张。
- 只缩 Rhodium 交给 agent 的图。agent 自己用 Read 看的图，Rhodium 管不到。

### 留多久

- 媒体目录里的文件，连同生成的预览、看图版和交给 agent 的缩小版，和收发记录一样留 90 天（`durations.inboundKeep`），在每天的保留期清理里一起删（[架构 §7.8](../architecture.md#78-备份与磁盘)）。
- 90 天从这个文件最后一次被存进来算。同一张图又收到、又发出一次，从那次重新算。
- 删了以后：网页上那里写“图片已清理”；agent 再按路径读，读不到。
- 媒体目录照旧不算进总量上限。
- 实现时定的：
  - 预览、看图版和缩小版在媒体目录下各自的子目录里，和原图同名。子目录里同名的原图已经不在的，每天清理时都删，生成的文件就是这样跟着删的。
  - `state_pruned` 事件的 `media` 是删了几个原文件，删掉的字节数算进 `bytes`。

## 测试决定

照 [v1 规格](v1.md#测试决定)的规矩：只测外部看得到的行为，测试名带故事编号。

- 媒体接口（`test/board.test.ts` 那一层）：
  - 不是 64 位十六进制的 `h`、带 `/` 和 `..` 的，都 400 或 404，不读任何文件。
  - PNG 按 `image/png` 回；一个内容是 HTML 的文件、一个 SVG，都回 `application/octet-stream` 加 `attachment`；每个回复都带 `nosniff`。
  - 别的源发来的请求 403。
  - `v=preview` 回 WebP，长边 800；小图回原图；第二次请求不再生成（看文件的修改时间）。
  - `v=view`：4000×3000、3MB 的图回长边 2576 的 JPEG；2000×1500、3MB 的 PNG 回 2000×1500 的 JPEG，不放大；1MB、长边 1200 的回原图。
  - 文件被删了，404。
- 消息块：从 `test/fixtures/transcripts/` 挑带图片的记录，加几段手写的：你的消息带两张图和一个文件、Claude 的 Read 结果带图、pi 的工具结果带图、Codex 的 `view_image` 指着槽位目录里的 PNG、槽位目录外的 PNG、槽位目录里一个改了扩展名的文本文件。块里没有 base64，地址对得上。
- `rh send`：`send_me` 事件里有内容地址；发到网页的也有。一个回合里先 `rh send me 测试过了` 再调一次别的 Bash，两次折成一行时，不点开也看得到“测试过了”和带的图。
- 交给 agent：一张 4000×3000 的 PNG，交给假 agent 的 base64 解出来长边 2576；消息里的路径是原图的。
- 留多久：用假时钟，91 天前存的文件被删，89 天前存的留着；91 天前存、昨天又收到一次的留着。
- 引用：IM 引用一条 300 字的消息，agent 收到的是开头约 100 字加“…”；Telegram 选中一段 300 字的引用，整段带上。网页引用同样截到约 100 字，待发的气泡照常换成正式的。
- 列表行：最后一条是带图的消息，写“你：[图片]”；带字的写“你：<文字> [图片]”。
- 冒烟测试（Playwright，手机尺寸）：发一张图，对话里出现预览；点开是看图器，下载键的链接是原图；按返回关掉，还在对话里。agent 的话下面有复制和引用；点引用，输入框上方出现引用条，点 × 消失。电脑尺寸：鼠标不在消息上时，只有最后一段有图标。
- 对话页那一包的大小照旧由 `test/build.test.ts` 守着。看图器的代码点开时才加载。

## 你来验收

在手机上：

- 在网页上发一张截图：对话里是预览，不是路径。首页列表那一行写“你：[图片]”。
- 在 QQ 里发一张照片给同一个槽位：网页上同样是预览。点开，先看到模糊的整张，清楚的部分从上往下盖上来。双指放大看细节。按返回关掉。
- 用手机拍一张大照片发过去，点开：很快看清；按下载键存到手机，是原图大小。
- 让 agent 用 `rh send me --file` 发一句话、一张图、一个文件：网页上不点开就看得到这句话和图，文件能下载。
- 让一个 Claude 槽位用 Read 看一张截图：点开那次 Read，结果里是那张图。让 Codex 槽位看一张它目录里的图，同样看得到。
- 复制 agent 一段带代码块的回复，贴进备忘录：是 Markdown 原文。
- 点一段长回复的“引用”，写一句发出去：agent 读到的是那段的开头和你的话。在 QQ 里引用一条长回复也一样。

在电脑上：

- 鼠标移到一段回复上，出现复制和引用；移开就没了，最后一段一直在。
