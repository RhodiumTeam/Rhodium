# 网页终端规格

这篇回答：网页第 5 步“终端嵌入”要做成什么样、满足哪些需求、怎么测、怎么验收、明确不做什么，以及怎么拆工单。

前置阅读：[术语表](../../GLOSSARY.md)、[产品说明](../product.md)、[ADR-0010](../adr/0010-herdr-hosts-tui.md)、[ADR-0012](../adr/0012-web-terminal-ghostty-web.md)、[架构](../architecture.md)、[IM 文字与交互规范](../im-style.md)、[v1 规格](v1.md)、[网页对话界面规格](web-chat.md)、[网页能写规格](web-write.md)

这一步怎么做，在 2026-10-24 的拷问里定下，行为写进了[产品说明 §7](../product.md#7-网页界面) 第 5 步。Herdr 那条命令的形状和实测结果在[架构 §10.4](../architecture.md#104-网页终端)。这里不重复，只写需求、页面和看板之间怎么说话、测试和交付。

这篇用到几个词：

- [网页终端](../../GLOSSARY.md)：见术语表。
- 操作者：此刻能往这个终端打字、决定它多大的那一处。
- 接管：新来的操作者把原来的挤掉。Herdr 的说法是 takeover。
- 放手：操作者自己退出，pane 回到 Herdr 布局给的大小。
- 特殊键：手机上终端下面那一排键。

## 问题

**TUI 槽位在网页上只看得到对话记录。**

- 对话页底部一条横幅，写着 pane 名，带一个 herdr-web 的链接。
- Claude 弹出的菜单、权限确认、正在跑的进度条，网页上都看不到。

**要动手就得跳走。**

- herdr-web 不能按 pane 打开，跳过去还要自己找到那个 pane。
- 它不认你的 Tailscale 账号。tailnet 上任何能连到这台机器的设备，都能往你自己在用的 Herdr 会话里打字。

**手机上的终端难用。**

- Shift+Tab、Esc 这些键，手机键盘按不出来。
- 中文要靠输入法，直接往终端里打不稳。

## 方案

槽位在 TUI 模式、已经有了 pane，对话页整页换成这个 pane 的终端。打开就接管，按页面的大小排，手机上有一排特殊键和一个输入框。

手机上大致是这样：

```
← ✳ Rhodium/dev                       ▢  ⋯      ← ▢ 切到对话记录；⋯ 里有字号、改名、收回终端
    TUI 模式
┌──────────────────────────────────────────────┐
│ ✻ Claude Code   Sonnet 4.6                    │
│ > 把终端嵌进看板，先写探针                       │
│ ● 好，先看 herdr 的 terminal session control   │  ← Herdr 里那个 pane，按手机的宽度排
│ ✻ 思考中… (12s  esc 打断)                      │
│ ──────────────────────────────────────────── │
│ > █                                           │
│ ⏵⏵ accept edits on (shift+tab)                │
└──────────────────────────────────────────────┘
 [Esc] [Tab] [⇧Tab] [^C] [↑] [↓] [←] [→] [⏎]      ← 特殊键
┌──────────────────────────────────────┐ [发送]
│ 发给终端                              │
└──────────────────────────────────────┘
```

另一台设备打开了同一个槽位，这一页变成：

```
┌──────────────────────────────────────────────┐
│                                              │
│              已在别处打开                       │
│              [在这里继续]                       │
│                                              │
└──────────────────────────────────────────────┘
```

这一步包含：

- 看板：`/api/terminal` 这条 WebSocket，握手的检查，起停 `terminal session control`，转发，每个槽位只开一个。
- 页面：按需加载的 ghostty-web 终端；特殊键和输入框；“已在别处打开”；藏到后台就放手；断线重连。
- 顶栏：终端和对话记录的切换；“⋯”里的字号和收回终端。
- 去掉原来的 TUI 横幅和 herdr-web 链接。

## 实现决定

### 已定的大方向

- Rhodium 自己画终端，接 Herdr 的 `terminal session control`，不用 herdr-web。画终端用 ghostty-web。为什么见 [ADR-0012](../adr/0012-web-terminal-ghostty-web.md)。
- 转发不进主循环，不加表，不加配置，不加事件（[架构 §10.4](../architecture.md#104-网页终端)）。
- 页面不存回滚。Herdr 发的是整屏的画面，不是一行行的输出；翻回滚由 Herdr 来滚。
- 收回终端照旧走 `rh release`，给 pane 发 Ctrl+C。网页在操作时这条照样有效（实测）。
- 切到终端时，pane 里直接跑 agent，等它报告了会话才算开好（[架构 §10.3](../architecture.md#103-herdr-桥用到的接口)“启动命令”）。页面接上时第一帧就是 agent 的界面，没有 shell 和启动命令。

### 握手

页面连 `GET /api/terminal?slot=<槽位 ID>&cols=C&rows=R&page=P`，`page` 见[一处在操作](#一处在操作)。地址用页面自己的主机：`https:` 的页面连 `wss:`，`http:` 的连 `ws:`。

升级成 WebSocket 之前，照 `route()` 现有的顺序查。要查哪几条、为什么，见[架构 §11](../architecture.md#11-安全与访问)，这里只写顺序和回什么：

1. 主机名、身份头、同源，和写请求同一套（见[网页能写规格](web-write.md#只认看板自己的页面)）。查不过回 403，不升级。
2. 请求带 `Upgrade: websocket`，`slot` 的格式对。不对回 400。

[架构 §11](../architecture.md#11-安全与访问) 里那条当时没实测的，是第一张工单的第一条验收（2026-10-25 验过：身份头带过来、假的被删掉）：

- 用一个空闲的 tailnet 端口，从源码另起一个看板，接 Herdr 的 `rhodium-test` 会话，经 `tailscale serve` 从手机打开。验完撤掉 serve 的这一条。
- 另从 tailnet 上的电脑用 curl 发一个带 `Upgrade: websocket` 的握手，自己写一个假的 `Tailscale-User-Login`。看板收到的应该是你的真账号，或者没有这个头。
- 身份头带过来、假的被删掉：照上面做。
- 不带：握手就是 403，不会悄悄放行。工单停下来回来问用户，不自己放宽检查。到时候的办法例如：页面先用写请求（它带着身份头）拿一张一次性的票，30 秒内有效，只认这个槽位，握手时带上。
- 假的没被删掉：同样停下来问用户。

升级以后再查槽位：在 TUI 模式、有 pane、Herdr 没在重启。不是就用 4000 关掉，页面照常显示对话。放在升级以后查，是因为浏览器看不到握手失败的状态码，只有关闭的代码它分得清。

### 看板和 Herdr 之间

- 每条连接起一个子进程：`<programs.herdr> --session <herdr.session> terminal session control <herdrPane> --takeover --cols C --rows R`。行列数来自地址，夹在下面的范围里；没给就是 80x24。
- 起完子进程，叫醒 Herdr：每 10 ms 经 Herdr 的 JSON socket 问一次这个 pane（`pane.get`，只读）。子进程第一次输出，或者过了 250 ms，就停。
  - 为什么：Herdr 空闲时每 250 ms 才接一次新的客户端，任何一条请求都会叫醒它（[架构 §10.4](../architecture.md#104-网页终端)）。不叫醒，切槽位时第一帧要多等两三百毫秒。
  - 只每 10 ms 一条，是因为不知道子进程什么时候连上 Herdr：太早问的那几条没用。
  - socket 的路径第一次用时问 `herdr session list --json`，之后记着；没问到下次再问。
- 同一个槽位来了新的连接：先用 4001 关掉旧的连接，写放手，等它的子进程退出（最多 2 秒，过了就杀），再起新的。
  - 为什么等：旧的放手要是晚于新的接上到达 Herdr，会不会把新的也放掉，没有实测。等一下就碰不到。
- Herdr 来的：
  - `terminal.frame`：解开 base64，压缩后作为二进制帧发给页面。
  - `terminal.closed`：照原因关掉连接，见下面的关闭代码。
  - 子进程没发 `terminal.closed` 就退出了（起不来、Herdr 断了）：用 4002 关掉，原因是它 stderr 的第一行。Herdr 把出了什么错写在第一行，最后一行是 socket 路径（[架构 §10.4](../architecture.md#104-网页终端)）。
- WebSocket 关了：写 `terminal.release`，关 stdin，2 秒后还在就杀掉。
- 日志：开、关（带原因）、被挤掉，各一行。

### 页面发来的消息

页面只发文本帧，一帧一个 JSON。看板只认四种，照写成 Herdr 那头的一行：

| 页面发的 | 写给 Herdr 的 | 上限 |
|---|---|---|
| `{"t":"in","d":"<字>"}` | `terminal.input`，`text` 是这些字 | 一帧最多 64KB，页面会切开 |
| `{"t":"size","c":列,"r":行}` | `terminal.resize` | 列夹在 2 到 500，行夹在 2 到 200 |
| `{"t":"scroll","up":true,"n":行数,"c":列,"r":行}` | `terminal.scroll`，`direction` 是 `up` 或 `down`；`c`、`r` 可选，写成 `column`、`row` | 行数夹在 1 到 200；列、行同下 |
| `{"t":"mouse","a":"down"\|"drag"\|"up","c":列,"r":行}` | `terminal.mouse`，`action` 是 `a`，左键 | 列、行从 0 数，列夹在 0 到 499，行夹在 0 到 199 |

- 别的形状、看不懂的 JSON：丢掉，不关连接。
- 二进制帧：关掉连接（1003）。
- 一帧超过 64KB：Bun 自己关掉连接（WebSocket 的 `maxPayloadLength`）。
  - 所以页面发 `in` 前先切开：每帧编码后不超过 64KB，依次发，不把一个字切成两半。电脑上粘贴一大段日志、手机输入框发长文都走这条。括号粘贴的标记分在几帧里没关系。
- 看板发给页面的帧压缩（WebSocket 的 permessage-deflate），页面发来的不压。
  - 每条连接一个压缩器（Bun 的 `dedicated`）：它记着这条连接上刚发过的，滚动时的一帧和上一帧很像，压得多。Claude 全屏滚动的帧压到五分之一左右。
  - 浏览器都支持，握手时自己商量，页面不用改。
  - Bun 的 `sendBinary` 要带上压缩的参数，不带就不压，商量好了也一样。
- 页面读得慢（手机信号差），发给它的攒到 1MB（压缩后的）：Bun 自己关掉连接（`backpressureLimit` 加 `closeOnBackpressureLimit`）。页面重连，拿到一整屏。
  - 为什么不攒着：画面帧是增量，丢一帧画面就乱。herdr-web 也是这么处理的。

### 关闭代码

关闭的原因按 WebSocket 的规矩最多 123 字节，超了截断。

| 代码 | 什么时候 | 页面怎么办 |
|---|---|---|
| 4000 | 槽位不在终端里了：pane 里的进程退出或 pane 被关掉、连上时 pane 已经没了（agent 刚退出，槽位还没切回无头）、槽位切回无头、Herdr 在重启、握手后发现不在 TUI | 重取槽位。槽位还在终端里就过一会儿再连，不在就显示对话 |
| 4001 | 在别处打开：同一个槽位来了新的连接，或者 Herdr 说 `terminal attach taken over`（例如 `herdr agent attach`）；回前台重连时别的网页已经连着（见[一处在操作](#一处在操作)） | 显示“已在别处打开”和“在这里继续”，不自己重连 |
| 4002 | 别的毛病：Herdr 给的别的原因、子进程起不来 | 终端下面一行小字写原因，过一会儿再连 |
| 其他 | 断网、Rhodium 重启、读得太慢被关 | 过一会儿再连 |

“过一会儿再连”：第一次马上连，之后 1 秒起，每次翻倍，最多 30 秒。连上并收到第一帧后重新算。

- 为什么第一次马上连：读得太慢被关的，马上重连就拿到一整屏，不用白等 1 秒（#381）。
- 为什么之后翻倍：Herdr 升级时新的 `herdr` 程序配旧的 server 可能一直连不上，这样不会重试个没完。

### 一处在操作

- 打开就接管：连接都带 `--takeover`。herdr-web 正连着也挤掉它，它那边写着被接管。
- 页面藏起来（`visibilitychange` 到 `hidden`）就关掉连接，看板让 Herdr 放手。回到前台自己再连。
  - 为什么：电脑上开着一个忘了关的标签，会一直占着这个 pane，你电脑上 Herdr 里的 pane 也一直是手机的大小。
- 回到前台的重连不抢（2026-10-24 定）：
  - 地址多带一个 `resume=1`。看板发现这个槽位已经有别的网页连着，就用 4001 关掉这条，不接管，原来那条不动。
  - 没有别的网页连着，照常带 `--takeover` 接上。看板只知道自己的连接，herdr-web 和 `herdr agent attach` 照旧被挤掉。
  - 只有在前台打开页面、按“在这里继续”才一定接管。断线后“过一会儿再连”也带 `resume=1`。
  - 在后台打开的页面（例如中键开的标签）先不连，切到前台时当作回到前台。
  - 为什么：手机藏到后台放了手，你在电脑上接着用。手机一亮屏，不这样就会抢走电脑上的终端，pane 也缩回手机的宽度。断网的手机重连时同理。
  - 地址还带 `page`：页面打开终端时随机取的一串字。连着的那条和带 `resume=1` 来的是同一个页面，照常接管。
    - 为什么：手机换了网络，旧连接断了，看板可能过一两分钟才发现。不认页面，手机重连时会以为别处在用，写着“已在别处打开”。
- 显示着“已在别处打开”的页面，回到前台也不自己连。按了“在这里继续”才连。不然两台设备一切回来就互相抢。
- 切到对话记录不放手：页面还在前台，手机上的输入框还往终端里送。
- 你 ssh 里的 Herdr 不算操作者，网页挡不住你在那边打字，也不用挡。

### 尺寸和字号

- 页面用 ghostty-web 的 FitAddon 量出放得下几列几行，连接时带在地址里，之后变了就发 `size`。转屏、拉宽窗口、手机键盘弹起（`visualViewport` 变了）都重量一次，停下来 100 毫秒后才发。
- 终端被藏起来（切到对话记录）时不量，不发。量出来是 0，会把 pane 改成 2 列。
- ghostty-web 把字画在一块 canvas 上。canvas 的像素数按此刻的设备像素比（`devicePixelRatio`，一个 CSS 像素占几个屏幕像素）取整，CSS 尺寸是这些像素除以比例，一个像素正好对一个屏幕像素。
  - 浏览器缩放、窗口挪到缩放不同的屏上，比例就变了。页面用 `matchMedia` 的 `(resolution: …dppx)` 盯着，变了就按新比例重排 canvas，整屏重画。
  - 为什么：ghostty-web 0.4.0 只在打开时读一次比例，canvas 的像素取 CSS 尺寸乘比例后截断。比例带小数时（132.5%、150% 的屏，浏览器缩放），浏览器把 canvas 拉伸到它实际盖住的屏幕像素上，字就糊了。打开后再缩放，canvas 还停在旧比例，从 100% 到 150% 就拉伸 1.5 倍。herdr-web 用的是同一个渲染器，也一样。
- 字号：默认 13px，9 到 20px，一次 1px。改了就重量一次、发 `size`。
- 这台设备记住字号，存在 `localStorage`，读写都包在 try 里，取不到就用默认。
- 等宽字用系统的，中文才显示得好。Linux 上的 Chrome 没有 ui-monospace、SFMono-Regular 和 Menlo，用装了的 Consolas，没有就用 DejaVu Sans Mono。光标不闪：ghostty-web 的光标闪烁在高分屏上很费。
- 系统字里都没有的几个符号由页面自带的小字体补上：⏴ 到 ⏺ 这 7 个字（Claude 权限模式那行的 ⏵⏵、计划模式的 ⏸）。
  - 为什么：安卓的字体里没有 ⏵，会显示成方框；⏸ 只有彩色 emoji，会画得比一格宽。
  - 这 7 个字从 Noto Sans Symbols 2 截出来（SIL OFL 1.1，版权和许可写在字体文件里），不到 1KB，内嵌在网页终端那一包里。
  - 它排在系统等宽字后面，只补别的字体都没有的字。画终端前先加载好。

### 电脑上的输入

电脑上不显示特殊键和输入框，点一下终端直接打。

- 字都打进 ghostty-web 自带的隐藏输入框，手机上点终端也是它。终端那块本身不可编辑。
  - 为什么：ghostty-web 0.4.0 把终端那块设成可编辑，焦点落在它上面。浏览器的光标就闪在终端左上角，选字时拼音显示在最后一行下面。
- 点终端任何地方都开始打字，包括画出来的行旁边的空白。
- 能打出字的键，发浏览器真正插入的字（`beforeinput` 的 `insertText`），不发按的哪个键。别的键（回车、Tab、Ctrl、Alt 的组合、Shift+Tab）照旧由 ghostty-web 编码。
  - 为什么：中文输入法的全角标点不经过选字。Windows、Linux 上先来一个 229 的按键，再插入 ，；Mac 上 ，跟着 `,` 这个键来。ghostty-web 0.4.0 前一种丢掉，后一种发成 `,`。
- 选字的词上屏时才发，选字时的拼音不进终端。
- 隐藏输入框跟着 pane 的光标走，输入法的选字窗开在那里，例如 Claude 的输入框里。每画一帧、选字时每打一个字母，都把它放回光标处、放在最上面。
  - 为什么：右键菜单收起时，ghostty-web 把它留在页面左上角、压在终端底下。不放回来，选字窗开在左上角，拼音看不见。
- 选字时拼音用终端的字体显示在光标处。浏览器自己的光标不显示。
- 光标右边放不下拼音时，输入框往左长，最宽到终端那么宽，再长就在框里滚。
  - 为什么：伸出终端右边，浏览器会把整个终端横着滚过去。

### 手机上的输入

“手机上”指 `(pointer: coarse)` 的设备。

- 输入框：多行，回车换行，按“发送”送出。
  - 整段走终端的粘贴：Claude 和 pi 打开了括号粘贴模式，就按一次粘贴收，多行的字不会被当成一行行回车。
  - 粘贴完，隔 35 毫秒左右，回车单独发一条 `in`。herdr-web 也是这么发的。
    - 为什么：Claude 的输入框按时间猜哪些字是粘贴进来的。回车紧跟着粘贴一起到，可能被当成粘贴里的换行，不会提交。
  - 送完清空。没连上时“发送”按不了，字留着。
- 特殊键：Esc、Tab、Shift+Tab、Ctrl+C、↑、↓、←、→、回车。按下就把这个键送进终端。
  - 编码用 ghostty-web 自己的键位编码，和在电脑上按这个键送出去的一样。
- 点终端本身也能用系统键盘直接打，收字照[电脑上的输入](#电脑上的输入)，只当补充。安卓上一些输入法往里面打不稳，所以以输入框为主。
- 在终端上滑动、滚轮：换成 `scroll` 发给 Herdr。页面自己不滚。

括号粘贴、方向键的模式要靠 Herdr 的画面帧把 pane 的终端模式带过来，页面这边才知道。带不带要实测，见[要先实测的](#要先实测的)。

### 鼠标

- 电脑上，只发指针是鼠标的事件：左键按下、拖动、松开，带指针下的那一格。拖动只在换了格子时发。
  - 左键先松开、右键还按着，也算左键松开。不然 pane 里的程序收不到松开，之后光移动鼠标也一直在拖。
- Herdr 看 pane 里的程序打没打开鼠标。打开了，照它的模式编码送进去；没打开、格子在 pane 外，就丢掉。页面不知道程序的模式，也不用知道（[架构 §10.4](../architecture.md#104-网页终端)）。
  - Claude 的全屏界面和 pi 默认的全屏界面都打开了鼠标。经典模式的 Claude、shell 没打开。
- 不从 `in` 发鼠标的字节：Herdr 原样送进去，没打开鼠标的程序会当成打的字。
- 发鼠标不改点击原来的效果：点一下照样开始打字（见[电脑上的输入](#电脑上的输入)），本地选字照旧。在 Claude 或 pi 的全屏界面里拖一下，两边都会高亮：程序自己的，和页面的。复制到浏览器靠页面的高亮。
- 滚轮和滑动带上指针下的格子，滑动是手指落下的那一格。Herdr 自己分：程序打开了鼠标就给它滚轮事件；程序在全屏画面上打开了“滚轮当方向键”（模式 1007）就给方向键；别的滚 Herdr 自己的回滚。
  - 为什么带格子：pi 按位置分滚轮，例如先给打开的浮层。不带格子就总落在左上角。
- 手机上点一下照旧是打字，不当点击。
- 点击要 Herdr 0.9.2 以上，见[要先实测的](#要先实测的)。2026-10-26 在 Herdr 0.9.1 和 0.9.5 上测过。

### 页面

- 新文件 `web/src/terminal.tsx`，按需加载 ghostty-web（写死 0.4.0）。网页终端那一包压缩后不超过 250KB，见[架构 §2](../architecture.md#2-组件和职责)。
- 空闲时不画。ghostty-web 0.4.0 自己有一个常驻的动画帧循环，空闲时也一直在画。照 herdr-web 的办法（`terminalRenderer.ts` 的 `suspendGhosttyIdleRenderLoop`）去掉它：
  - 只在来了画面帧、滚动、选字时画一次。
  - 终端藏起来（切到对话记录）时不画。
- HTML 的 CSP 在 `script-src` 里加 `'wasm-unsafe-eval'`，别的不加：`frame-ancestors 'none'; script-src 'self' 'wasm-unsafe-eval'`。
- 什么时候画终端：槽位在 TUI 模式、有 pane、Herdr 没在重启。
  - 还在切换中、Herdr 在重启：照旧显示对话记录，顶栏写状态。槽位一变（事件流照旧让页面重取），页面自己连。
  - `/api/slot` 加一个 `herdrLost`（布尔），页面据此知道 Herdr 在重启。
  - 第一次打开一个槽位，不等 `/api/slot`：看板列表里这个槽位的 `terminal` 有 pane，页面就先画出顶栏和终端，开始连；`/api/slot` 回来再补齐别的（#381）。
    - 为什么：慢网络上 `/api/slot` 要一个往返，这期间对话页只有顶栏，下面是白的。
    - 列表里没有这个槽位（例如直接打开地址）：照旧等 `/api/slot`。
- 连接还没收到第一帧时，终端那块转圈。
- 新建的终端量完尺寸先清一次屏，再画（#381）。
  - 为什么：ghostty-web 0.4.0 的新终端一量尺寸，就长进上一个终端刚释放的内存，那块内存没清过。不清，换槽位时先画出上一个槽位没颜色的字，等第一帧到了才换掉。
  - 清在量尺寸之前没用，实测照样有旧字。
- 顶栏：返回、logo、名字、状态，右边一个切换按钮、“⋯”。
  - 切换按钮：在终端时是对话的图标，按下显示对话记录；在对话记录时是终端的图标。图标用 lucide。不记上次看的哪个，打开总是终端。按下不弹框：两边都还在终端里，什么也不打断。
  - 无头时把槽位切到终端的按钮（输入框下面的终端按钮、拓扑图菜单里的“切到终端”）先弹框确认，见[网页能写规格](web-write.md#槽位上的操作)（故事 476）。
  - 这些入口什么时候出现（设置里的“终端入口”开关、没装 Herdr），见[网页能写规格](web-write.md#终端入口)（2026-11-06）。已经在终端里的槽位，上面的切换按钮和“收回终端”不受影响。
  - 对话记录就是现在那页，照[网页对话界面规格](web-chat.md)，不新做。手机上它下面照样有输入框，没有特殊键。
  - “⋯”：字号一行（缩小、放大两个图标，菜单不关，看得到效果），改名，收回终端。收回终端照旧弹框确认、带 `sure: true`。确认的同时页面换成对话记录，和按顶栏的切换按钮一样，看不到 agent 退出时的提示和退出后打的字。终端留在下面接着，直到槽位切回无头。
- 原来的 TUI 横幅连同 herdr-web 链接去掉。顶栏的状态照旧不写 pane 名。
- 文字照 [IM 文字与交互规范 §1](../im-style.md#1-原则)：安静克制，不用 emoji，不用中间点拼几组字，不写说明文字。

  - 收到的每一行记进 `fake.calls`。
  - 新的 `terminal session control` 等 250 ms，或者等到 socket 上来了别的请求，才接上，和空闲的 Herdr 一样。这之前它发的行先攒着。

  - `/api/slot` 一直不回：从列表点一个在终端里的槽位，顶栏有它的名字，终端照样接上。
  - 收回终端，确认后槽位还在 TUI 时，页面已经是对话记录。
  - 终端用的字体画得出 ⏵ 和 ⏸，不是缺字的方框，也不比一格宽（量 canvas 上的字形，和一个所有字体都没有的字比）。
- 终端按钮的确认（故事 476），电脑尺寸和手机尺寸各一遍：空闲的槽位按终端按钮，框里是“取消”“切换”；取消什么也不发，切换发 `rh tui`。回合在跑时框里是“取消”“跑完再切”“打断，马上切”，各发对应的那条。框开着时回合开始，“跑完再切”就在原来“切换”的位置。拓扑图右键的“切到终端”也弹同一个框。TUI 槽位按顶栏的切换按钮不弹框。
- Playwright 在电脑尺寸上：在终端的格子上按下、拖、松开，假 Herdr 依次收到这几格的 down、drag、drag、up；右键不发；滚轮带上指针下的格子。按着左键再按右键、先松左键，收到 down 和 up，之后移动不再发 drag。手机尺寸上点一下不发 `terminal.mouse`，滑动带上手指落下的格子。
- Playwright 在电脑尺寸上，比例 1.325（4K 屏缩放 132.5%）：canvas 的像素数等于它的 CSS 尺寸乘比例。页面收到比例变成 1.9875（再放大到 150%）、再变成 2：每次还是等于，字整屏重画了，不是只剩光标。
  - 模拟的比例变化不触发媒体查询，测试替浏览器发 `change`。
- 网页终端那一包的大小由 `test/build.test.ts` 守着；首屏、对话页那一包不含 ghostty-web。

### 之后：换掉 herdr-web

机器上另跑着 herdr-web（一个第三方的 Herdr 网页终端）的，网页终端验收通过后，可以用它换掉 herdr-web。

- 原因：herdr-web 不认人，tailnet 上任何能连到这台机器的设备，都能往你自己在用的 Herdr 会话里打字。
- 不在这一步的工单里。
- 四张工单都验收过以后，开发用的 agent 先问用户，用户同意了再停 herdr-web 的服务和它在 `tailscale serve` 里的那一条。
- herdr-web 的安装留着，要用时自己再起。
