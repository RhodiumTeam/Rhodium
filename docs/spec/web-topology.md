# 网页拓扑图规格

这篇回答：网页看板的拓扑图（只读的那一部分）要做成什么样、满足哪些需求、怎么测、怎么验收、明确不做什么。对话页上跟着改的头像和气泡、重新设计的详情抽屉也写在这里。

拓扑图原来排在网页第 4 步，叫“关系图”。2026-10-23 决定先把只读的部分提前做，并改名拓扑图。交互、头像和开工顺序都在那天的拷问里定下。最后一版原型看过后，反馈是“可以做了”。这篇照那版原型写，去掉了只有原型才有的东西（换数据的开关、仿的对话页、存成文件的快照）。

2026-10-24 拓扑图改绑定那一轮拷问，提了一种新画法，照它做了原型，看过后反馈基本可以。平时的画法跟着改了：跟着默认的窗口接进 Bot 自己的终点，Bot 画一条线到默认目标，只有单独选过槽位的窗口自己画线；收着的工作区露出有线指着的槽位；线能点。这篇已经照它改好，换掉的故事写明换成了哪条。

网页的整体规则见[产品说明](../product.md) §7。页面、构建和传输见[架构](../architecture.md) §2。消息块见[架构](../architecture.md) §7.7。看板的访问控制见[架构](../architecture.md) §11。

这篇用到几个词：

- 焦点：你当前停着的那个节点或那条线。节点外面一圈框。
- 点亮：和焦点有关的节点和线保持清楚，其余变淡。
- 路径：图顶上那一行，从“总览”一格一格排到焦点。
- 镜头：画面的位置和缩放。
- 详情：一个节点的详细信息。手机上在底部面板里，电脑上在详情卡片里。
- 详情抽屉：对话页右上“详情”打开的那一栏，放进程和事件。和拓扑图的详情是两样东西。
- 起点：一条线出发的圆点，实心。每个聊天窗口右边一个，每个 Bot 标题行的右边一个。
- 终点：一条线落下的圆点，空心。每个槽位左边一个，几条线落在这个槽位都落在这一个点上；每个 Bot 标题行上也有一个，在它的起点左边。起点、终点只是图上的圆点，不是“目标”的别名（[术语表](../../GLOSSARY.md)）。
- 单独选的：用 `/rh_use`、`rh use` 给窗口选的槽位，盖过 Bot 的默认目标。没有单独选的窗口跟着默认。
- 连线：跟着默认的窗口从它的起点接进它 Bot 的终点的那一小段线。
- 落点：一条线最后到的槽位。跟着默认的窗口，落点是它 Bot 的默认目标。

## 问题

**看不出谁连着谁。**

- 看板的列表按工作区列出槽位，但不画聊天窗口和 Bot。
- 哪个窗口的话交给哪个槽位，要在 IM 里发 `/rh_ls` 或在终端里跑 `rh ls` 才知道。
- 派生出来的子槽位可能落在别的工作区。列表上只看得到缩进，跨工作区的就断了。

**看不出一个槽位用过哪些对话。**

- 对话页只显示槽位当前那段对话。以前的对话在网页上看不到。

**头像和名字都没有。**

- 看板和对话页上，Bot 和聊天窗口都只是一行字，例如“QQ Bot main 的私聊”。
- 对话页上你的话的来源是一个文字小标签。几个 Bot 混在一起时，要读字才分得清。

**对话页的详情抽屉简陋。**

- 事件新的在上，和对话的读法相反，只有最近 50 个。
- 每个事件都是一样的灰框一行字，崩溃和普通的状态变化长得一样。
- 进程写着 unit 名、子状态这类细节，错误输出空的时候也占一块。

**按原来的设计，点起来乱。**

- 点一下同时做五件事：展开、设焦点、点亮、换详情、挪画面。再点一下，意思看情况。
- 返回键退的一步和你想的对不上。
- 底部面板自己升起收起，你拉开的又被收回去。
- 时间线在图上一份，详情里又一份，两份不一样。
- 画面每点一下都重新对准，你拖好的位置留不住。
- 字太多：说明文字、“没有”这类空项、写成字的 agent 名和模式。

## 方案

这一步做完后，看板首页顶上能在“列表”和“拓扑图”之间切换。拓扑图左边是每个 Bot 和它的聊天窗口，右边是工作区，绑定画成线。点一个工作区，它展开成一棵槽位的树。点一个节点或一条线，它成为焦点，有关的保持清楚，其余变淡。详情在手机的底部面板里，电脑上在图右边的一张卡片里。

手机上大致是这样（打开了 dispatcher，焦点在槽位 main）：

```
Rhodium ●  [列表|拓扑图]                   状态
⌂ 总览 › dispatcher › main              ⇕  ▥   ← 路径；右边是“全部展开”“已归档”开关

 ┌▣ (QQ头像) main ★    ○ ●━━━━┓
 │(你的头像) 匿名用户 ★ ●━┛     ┃       ┌▢ dispatcher────┐
 └─────────────────────────┘   ┣━━━━━━○┃✳ main        │ ← 焦点，外面一圈框
 ┌▣ (TG头像) telegram  ○ ●━━━━┛       │└┃✳ cat-or-dog ▥│ ← 子槽位，像目录树
 │(你的头像) 你的名字   ●━┛             └────────────────┘
 │(私聊标志) 匿名用户   ● ─ ─ ─ ─ ┐    ┌▢ Rhodium ───────┐（淡）
 └─────────────────────────┘     └ ─ ○┃✳ dev          │ ← 收着，只露出被指着的槽位
 ┌▣ (QQ头像) Echo      ○ ●…（淡）       └────────────────┘
 └─────────────────────────┘
────────────────────────────────────────────
 ✳ dispatcher/main              [打开槽位 ›]   ^  ← 底部面板，平时只有这一行
   ● 未运行
```

图例：

- `▣` 是 Bot 外框的机器人图标，`▢` 是工作区的文件夹图标，`▥` 是已归档，`⇕` 是全部展开。
- 头像右下角有一个小标志：Bot 的是平台，聊天窗口的是私聊或群聊。
- `★` 是主 Bot 和主窗口，`✳` 是 Claude 的 logo。
- `┃` 是槽位左边表示状态的色条。
- `●` 是起点，`○` 是终点。粗线是 Bot 到默认目标的线和跟着默认的窗口的连线，细虚线是单独选的。
- telegram 下的“匿名用户”是一个陌生人的私聊，单独选过 dev，所以画出来。陌生人的窗口不取名字和头像。
- 和焦点无关的都变淡，图里只标了几处。

把底部面板拉上来，是这个槽位的详情：

```
 ✳ dispatcher/main              [打开槽位 ›]   v
   ● 未运行
 ┌(你的头像) 你的名字        (TG标志) telegram┐  ← 绑着它的聊天窗口
 ├(你的头像) 匿名用户 ★      (QQ标志) main    ┤
 ┌✳ main                                     ┐  ← 它在派生树里的位置
 └─✳ cat-or-dog                         ▥ › ┘
 ┃ ✳ 现在运行的 Rhodium 是哪个版本？      v  ← 时间线，标题为主
 ┃   1b81e569                    10/23 10:46     竖线是当前那段
   ✳ 一次性子槽位多久会自动归档？         v
   …
   [还有 1 段]
```

这一步包含：

- 服务端给拓扑图的数据：Bot、聊天窗口、工作区、槽位、绑定、派生和各自的状态。
- 头像：服务端取 Bot 和你在各平台的头像，存在本机，经看板给网页。网页看不到任何令牌和平台 ID。
- 拓扑图页面：图、点亮、镜头、路径、返回、底部面板和电脑上的详情卡片。
- 入口：首页顶上的切换，对话页顶上的拓扑图按钮。
- 对话页：你的话用看得清的气泡，旁边是你的头像；来源标签换成 Bot 头像加平台小标志加 Bot 名。
- 对话页的详情抽屉：事件从旧到新、停在最新、往上翻接上更早的；每种事件有自己的图标和颜色；字少。

## 用户故事

“用户”就是你本人。编号接着[网页对话界面规格](web-chat.md)，从 212 开始。2026-10-24 改画法时补的几条从 370 起，前面的编号留给同时写的几篇规格；换掉的旧故事留着编号，写明换成了哪条。

### 看全局

212. 作为用户，我想要打开拓扑图先看到总览：左边是每个 Bot 框着它的聊天窗口，右边是工作区，绑定画成线，以便一眼看出每个窗口的话交给哪里处理。
213. （2026-10-24 换成 370、371、372。）
370. 作为用户，我想要每个 Bot 从它的起点画一条粗线到它的默认目标；跟着默认的窗口不各自连到槽位，而是用粗的连线接进 Bot 自己的终点；只有单独选了槽位的窗口自己画一条细虚线到那个槽位，以便平时线少，一眼分出谁跟着默认、谁单独选过。
371. 作为用户，我想要一个 Bot 框里跟着默认的窗口排在前面，单独选过的排在后面，以便接进 Bot 终点的连线短，不和别的线交叉。
372. 作为用户，我想要每个槽位左边只有一个终点，几条线都落在这一个点上，不标数字，以便槽位左边干净，一眼看出哪个槽位被指着。
214. 作为用户，我想要每个节点带着它现在的状态：工作区上有几个需要你、几个在运行；槽位左边的色条和右边的小图标表示需要你、运行中、崩溃、等额度、TUI 模式；Bot 掉线时头像角上有个点，以便不点开就知道哪里有事。
215. 作为用户，我想要拓扑图随状态实时变化，以便不用刷新。
216. 作为用户，我想要已归档的槽位平时不画，没有在用槽位的工作区也不画，点路径那一行右边的开关才画出来，以便图干净。
373. 作为用户，我想要收着的工作区只露出有线指着的槽位，按列表页的排法：需要你的在前，然后是运行中的，其余在后；工作区上的个数只数没露出来的，以便拓扑图专注于关系，要看在等我、在跑的去列表页。
374. 作为用户，我想要路径那一行右边有一个“全部展开”开关，打开后所有工作区都展开，这台设备记住它，以便宽屏上或者要看全貌时不用一个一个点开。
375. 作为用户，我想要鼠标停在“全部展开”“已归档”两个开关上时显示它们是做什么的，以便图标认不出时不用猜。
217. 作为用户，我想要图和详情里字少：agent 用 logo，状态和种类用图标，无头模式不标、只标 TUI，没有说明文字，空的项不显示，以便一眼看懂。

### 点节点

218. 作为用户，我想要点一下工作区或槽位就进入它：它所在的工作区展开出槽位，它成为焦点，和它有关的节点和线保持清楚，其余变淡，以便只看我关心的那一块。
219. 作为用户，我想要再点一下焦点就取消焦点：什么都不淡了，展开的保持展开，以便看全图又不丢位置。
220. 作为用户，我想要点一个 Bot 只点亮它、它的聊天窗口和线的落点，别的 Bot 和工作区都变淡，展开的工作区收起来，以便看清这个 Bot 管着哪些窗口。
221. 作为用户，我想要点一个聊天窗口就等于点它绑着的槽位，以便从窗口直接找到处理它的槽位。
222. 作为用户，我想要点空白处什么都不变，点路径里的“总览”回到全图，以便手指碰到空白不会把我弄丢。
223. 作为用户，我想要顶上的路径从“总览”排到焦点：工作区，再一级一级的父槽位，点哪一格回到哪一格，以便知道自己在哪、随时往上走。
376. 作为用户，我想要不在编辑时点一条线，它就成为焦点：这条线和它接着走的那一段点亮，两头的节点保持清楚，详情写着从谁到哪个槽位，带“打开槽位”，以便直接看一条线是谁的、去哪里。

### 派生

224. 作为用户，我想要子槽位紧挨着排在父槽位下面，往右缩进一点，用像目录树那样的细线连着，不写“由 X 派生”，以便一眼看出谁派生了谁。
225. 作为用户，我想要父子不在同一个工作区时，槽位上有一个分叉的小图标，选中它时另一个工作区也亮起来，以便跨工作区的派生也看得到。

### 详情

226. 作为用户，我想要手机上详情在底部面板里：平时只有一行，写着名字和状态，槽位还带一个“打开槽位”，以便图占满屏幕。
227. 作为用户，我想要点这一行或者拖它就能把底部面板升起来，拖到哪停哪；换节点时它保持我留下的高度，下次打开拓扑图还是这个高度；没有可以展开的内容时只有这一行，拉不开，以便面板不自己跳，也不会拉出一块空白。
228. 作为用户，我想要电脑上详情是图右边的一张卡片，一直开着，内容多高卡片多高，以便不用拉。
229. 作为用户，我想要槽位的详情里有：绑着它的聊天窗口（私聊在前，联系窗口带一个标记）、它在派生树里的位置（父槽位、它自己、子槽位，点了去那个槽位）、它的时间线；没有的项整块不显示，以便详情短而且有用。
230. 作为用户，我想要时间线里每段对话以标题为主，短 ID 和时间是下面一行小字，agent 用 logo，当前那段用左边一条竖线标出；先显示最新的 5 段，点“还有 N 段”看全部，以便一眼认出是哪段对话。
231. 作为用户，我想要点时间线里的一段，就在详情里展开一个能滚动的预览框，看起来和对话页几乎一样，只是只有最近几句；打开时停在最新，有新消息跟着往下走，我往上翻就停下，翻回最底又跟着走；再点一下收起，以便看一段对话说了什么，不离开拓扑图。2026-11-06 改：往上翻能一路翻回第一句（故事 588）。
588. 作为用户，我想要在时间线里预览一段对话时，往上翻到顶自动接上更早的，一路能翻回第一句，以便读完一段旧对话不用 `/resume` 回去。2026-11-06 加的。
232. 作为用户，我想要 Bot 的详情列出它的聊天窗口，每个写着它的目标槽位，点了去那个槽位；工作区的详情列出绑进这个工作区的聊天窗口和各自的目标槽位，以便从 Bot 或工作区一步找到槽位。
233. 作为用户，我想要没选中任何节点时，详情写着“总览”和需要你、运行中的个数，拉开是这两类槽位，点了去那个槽位；两类都没有时只有“总览”这一行，以便先看到要我管的。

### 头像和名字

234. 作为用户，我想要每个 Bot 用它在平台上的头像，头像右下角有平台的小标志，外框左上保留机器人图标，以便一看就知道是哪个平台的哪个 Bot 号。
235. 作为用户，我想要每个私聊窗口用我在那个平台的头像，头像右下角标出私聊还是群聊，名字写我在那个平台的用户名；平台不给名字的（QQ），写淡色斜体的“匿名用户”，以便认得出是哪个号，又不编名字。
236. 作为用户，我想要同一个 Bot 下私聊排在群聊前面，以便最常用的在上面。
237. 作为用户，我想要槽位和工作区的详情里，聊天窗口那一行的 Bot 名前面带平台小标志，以便不在 Bot 框里时也分得清是 QQ 还是 Telegram。
238. 作为用户，我想要取不到头像时显示平台的标志（Bot）或私聊、群聊的标志（窗口），头像和 Telegram 上的名字一天更新一次，以便换了头像、改了名都不用管，取不到也不难看。
239. 作为用户，我想要网页上看不到任何 Bot 令牌、平台的用户 ID 和平台的文件地址，以便这些不出本机。

### 镜头

240. 作为用户，我想要点了的节点留在手指下：布局变了，画面只做补偿，缩放不变；只有它被挡住或者出了屏幕，画面才挪最短的距离，以便画面稳，我拖好的位置不丢。
241. 作为用户，我想要拖动和缩放有边界：拖不出图外，缩小到全图放得下为止，放大有上限，以便不会在空白里迷路。
242. 作为用户，我想要打开拓扑图时手机上按宽度放下全图，Bot 那一栏不出屏；从某个焦点打开时，先看到焦点和它周围的节点，以便第一眼就有用。

### 返回

243. 作为用户，我想要返回键回到上一个我真的停过的地方：往深处走或跳到别处算一步；在同一层之间换（几个 Bot 和工作区之间、同一个工作区的几个顶层槽位之间、同一个父槽位的几个子槽位之间）只替换当前这一步；点空白、开合底部面板、展开预览、取消焦点、开关已归档都不算一步，以便返回和我想的一样。

### 入口

244. 作为用户，我想要看板首页顶上有“列表”和“拓扑图”两个标签，这台设备记住我上次用的那个，从手机桌面图标打开也停在那里，以便常用哪个就直接看到哪个。
245. 作为用户，我想要在拓扑图里点“打开槽位”进对话页，按返回回到拓扑图，焦点和画面都不变，以便看完对话接着看图。
246. 作为用户，我想要电脑上从拓扑图打开的对话开在右边，图留在左边；这时点图上别的槽位，右边换成那个槽位，点别的节点右边关掉，以便边看图边看对话。
247. 作为用户，我想要对话页顶上有一个拓扑图按钮，打开以这个槽位为焦点的拓扑图，看它和哪些窗口、Bot 连着；如果对话页是从拓扑图打开的，这个按钮就是返回，以便两边来回不越叠越多。

### 对话页

248. 作为用户，我想要对话页上我的话是浅灰底带一圈细边的气泡，旁边是我在发来的那个平台的头像，以便在长对话里快速找到自己说的。
249. 作为用户，我想要我的话上方的来源标签换成 Bot 的头像（带平台小标志）加 Bot 名，群聊再加群名；别的槽位用 `rh send` 发来的、子槽位的汇报，照旧写成文字标签，不配我的头像；我在终端里打的话照样是气泡，不配头像，也没有来源标签，以便一眼分出是从哪个 Bot 来的、是不是我说的。

### 页面

250. 作为用户，我想要看板首屏不因为拓扑图变慢：拓扑图的代码点进拓扑图才下载，首屏照旧压缩后不超过 200KB，以便手机走中继时看板照样快。
251. 作为用户，我想要拓扑图的深色和浅色跟着系统，深色下线、框和淡掉的节点都看得清，以便晚上也能用。

### 对话页的详情抽屉

252. 作为用户，我想要详情抽屉里的事件和对话一样从旧到新排：打开时停在最新，有新事件跟着往下走，我往上翻就停下，翻到顶自动接上更早的，以便和读对话一个读法，也翻得到很久以前的事。
253. 作为用户，我想要每种事件有自己的图标和颜色：收到我的消息、提问和回答、状态变化、回合结束、agent 主动发消息、崩溃，各自一眼分得开，出错的是红的，以便扫一眼就找到出事的地方。
254. 作为用户，我想要详情抽屉里字少：每个事件一句话加时间；发出去的消息挂在它的事件下面，发成功的不标，没发出去和结局不明的才标出来；进程只写一行；错误输出空的时候不显示，以便排查时一眼看到要紧的。

## 实现决定

### 已定的大方向

- 只读。不加表，不加迁移，不加配置。
- 服务端把图要的东西整理好给网页。网页不懂绑定的优先级，也不碰平台接口。
- 绑定的优先级用路由里现成的那一份（`src/router.ts` 的 `target()`），导出来用，不抄一份。
- 实时更新照看板现在的做法：收到事件表的事件就重取拓扑图的数据。对话页的临时事件（记录长了、逐字增量）不触发重取（[架构 §7.7](../architecture.md#77-对话记录)）。
- 用 React Flow 12（`@xyflow/react` 写死 12.12.0）画图，用 dagre（`@dagrejs/dagre` 写死 3.1.1）只排左右两栏里节点的上下次序。工作区里的槽位树、线的走法都自己算。
  - React Flow 12 的样式不在 Tailwind 的层里，会压过 Tailwind 的工具类，要放进层里再引入。
  - React Flow 13 出正式版以后再换。
- 布局写成一个纯函数：输入数据、焦点、是否显示已归档、是不是宽屏，输出节点和它们的框、线、点亮的集合、能拖到的范围。测试主要测它。
- 宽屏指至少 1024px 宽，和对话页的分栏一样。
- 实现时把定下的几样补进架构：React Flow、dagre 和拓扑图那一包的上限进 §2；头像缓存进 §7；头像接口和“网页看不到令牌和平台 ID”进 §11；消息块的 `from` 和“开着预览时事件流跟着那个槽位”进 §7.7。

### 接口

| 路径 | 变化 |
|---|---|
| `/api/topology` | 新加。拓扑图的全部数据，不分页 |
| `/api/slot` | 加 `timeline`：这个槽位的每段对话。去掉 `recent`，事件改由下面的 `/api/slot-events` 给 |
| `/api/messages` | 加 `conversation=<对话 ID>` 参数：按对话取，给时间线的预览用。你的话的消息块加 `from` |
| `/api/avatar?id=<ID>` | 新加。一个 Bot 或一个聊天窗口的头像图片 |
| `/api/slot-events?id=<槽位 ID>` | 新加。详情抽屉的事件，一页 50 个，从旧到新，各带发出去的消息。`before=<序号>` 取更早的一页 |

`/api/topology` 回这些：

- Bot：ID、名字（有 `label` 用 `label`，和来源行一样）、平台、是不是主 Bot、连接状态、默认目标、头像地址。
- 聊天窗口：ID、所属 Bot、私聊还是群聊、是不是你的私聊、名字、是不是主窗口、头像地址。
  - 只给三种窗口：你的私聊、有自己目标的窗口、主窗口。陌生人发过消息也会在库里留一行，不给。
  - 私聊还是群聊：v1 只做私聊（[产品说明 §9](../product.md#9-群聊v1-不做规则已定)），一律是私聊，陌生人单独选过槽位的窗口也是。做群聊时按平台给的会话类型分，并存进库里。
  - 名字：Telegram 私聊是你在 Telegram 的名字；QQ 私聊和陌生人的私聊是 `null`，页面写“匿名用户”；群聊是群名。
- 绑定：每个窗口现在的目标槽位，和它是跟着 Bot 的默认目标，还是用 `/rh_use`、`rh use` 选的。
- 工作区：ID、名字。
- 槽位：ID、全名、名字、工作区、父槽位、当前 agent、模式、状态的说法和看板的分组（和 `/api/board` 用同一套）、一次性还是长期、是否归档、联系窗口。
- 不给任何令牌、平台的用户 ID 和群 ID。窗口和 Bot 只用 Rhodium 自己的 ID。
- 用几个月后整份压缩约 40KB，所以不分页。

`/api/slot` 的 `timeline`：

- 每段对话：ID、短 ID（agent 的会话 ID 的前 8 位，和 `/resume`、`rh import` 显示的一样；还没有会话 ID 时是 `null`）、agent、开始时间、最后写入的时间、标题、是不是当前那段。
- 标题和 `/resume` 列表里的一样：pi 的会话名，没有就取你打的第一句话，压成一行。找不到记录或者没说过话的，标题是 `null`。
- 按最后活动排，新的在前。最后活动是最后写入的时间，没有就用开始时间。

`/api/messages?conversation=<对话 ID>`：

- 分页、`before`、`after` 和按槽位取时一样。
- 带 `conversation` 时不看 `slot`。

消息块的 `from`：

- 你的话开头的来源行（[架构 §7.7](../architecture.md#77-对话记录)）在服务端认成 Bot 和聊天窗口。
  - 先去掉排队久了才加的“，发送于 …”。
  - 来源行按发消息那时的叫法写：同一个平台只有一个 Bot 时只写“QQ 私聊”，不带 Bot 名。这时平台现在也只有一个 Bot，就认成它；有几个了，认不出是哪个，只带平台。
- 认出来了，`from` 带：平台、Bot 名、Bot 的头像地址、这个窗口的头像地址（就是你在那个平台的头像），群聊再带群名。
- 一个 Bot 可以有你的几个号（配对时加的）。每条消息配它来自的那个号的头像（2026-10-31 定，#513）。怎么认出是哪个号、认不出时怎么办，见[架构 §7.7](../architecture.md#77-对话记录)。
- Bot 已经删了，只带平台和来源行里写的 Bot 名，没有头像。页面显示平台标志和这个名字。
- 别的（`rh send`、汇报）`from` 是 `null`，页面照旧显示来源行原文。
- 终端里打的话没有来源行，`from` 和来源都是 `null`。

`/api/avatar`：

- 只认 Bot 和聊天窗口的 Rhodium ID。没有头像回 404，页面换成标志。
- 和看板别的路径一样，先过 `Tailscale-User-Login` 的检查（[架构 §11](../architecture.md#11-安全与访问)）。
- 数据里的头像地址带图片内容的哈希。头像变了地址就变，所以浏览器可以一直缓存，和 `assets/` 一样。

### 头像

取的方式（2026-10-23 实测过）：

| 头像 | 从哪取 |
|---|---|
| QQ 上你的头像 | 公开的头像 CDN：`https://q.qlogo.cn/qqapp/<Bot 的 appId>/<你的 openid>/100`，不用凭证 |
| QQ Bot 自己的头像 | QQ 接口 `GET /users/@me`，走 SDK 里现有的、已登录的客户端，不另外申请令牌 |
| Telegram 上你的头像 | `getUserProfilePhotos` 拿到照片，`getFile` 拿到文件路径，再下载 |
| Telegram Bot 自己的头像 | 同上，用 `getMe` 给的 Bot 自己的 ID |
| 你在 Telegram 的名字 | `getChat`，ID 是配置里的 `owner`。取名和姓，都没有就用 `@用户名` |

几点说明：

- QQ 的 openid 每个 Bot 不一样，所以你的头像按 Bot 取：每个 QQ Bot 的私聊各取一次。
- QQ 的 CDN 认不出 ID 时，回一张默认的企鹅图，响应头带 `X-Info: notexist`。这种当作没有头像，不存。
- QQ 私聊不给你的昵称。不编名字，页面写“匿名用户”。
- Telegram 的文件地址里带着 Bot 令牌，所以一定在服务端下载，地址不出 `rhodium`。
- Telegram 的照片取不小于 160px 的最小一张，没有就取最大的。
- 群聊的头像现在不取。以后真有群聊再设计。
- 每个 IM 适配器加一个取资料的方法：Bot 自己的头像、你的头像、你的名字。取不到的就不给，不抛错。假 IM 适配器给固定的图片，测试用它。

缓存和更新：

- 存在状态目录下的 `avatars/` 里，按 Bot 或聊天窗口的 Rhodium ID 存文件。Telegram 的名字也存在这里。
- 头像和 Telegram 的名字一起取：`rhodium` 启动时取一次，之后每天一次。你在平台上换了头像或改了名，最晚一天后跟着变。
- 新加的 Bot 马上取一次。你和一个 Bot 的私聊第一次出现时（配对、你发第一条消息，或 Rhodium 第一次往这里给你发消息），也马上为这个 Bot 取一次，不等第二天。
- 某一个取失败了，留着上次的，下次再试。
- 日志里不写令牌、openid、Telegram 的用户 ID 和任何取头像的地址。出错只写哪个 Bot、哪一种头像、错误的种类。

### 拓扑图页面

地址：

- `#/topology` 是总览，`#/topology/<bot|ws|slot>/<ID>` 是焦点在某个节点。`#/topology/line/<ID>` 是焦点在一条线上，ID 是线的起点那个 Bot 或聊天窗口的。
- 取消焦点后，地址后面加 `?x`，替换当前这一步。刷新以后还是取消的样子。
- 宽屏上对话开在图右边时，地址后面加 `?chat`（和 `?x` 一起时写 `?x&chat`）。刷新或返回到这一步，还是左边拓扑图、右边对话。
- 地址里的节点不存在（比如槽位删了），或者那条线没有了（比如 Bot 没了默认目标），就是总览。

图的排法：

- 左栏是 Bot，每个 Bot 是一个框，里面一行一个聊天窗口。右栏是工作区。
- 两栏里节点的上下次序由 dagre 按“线交叉最少”排，只按全部收起时的图排一次。展开一个工作区不改次序，只把它下面的往下推。
- 只有已归档槽位的工作区不参与排序。开着已归档，或者它是焦点时，它接在工作区那一栏的最后。开关已归档不改两栏的次序，焦点停在屏幕上原来的位置。
- 一次只展开一个工作区：焦点所在的那个。焦点是 Bot、线或者是总览时，都收着。开着“全部展开”时，所有工作区都展开，焦点换到哪都不收。
- 收着的工作区是一个框：标题那一行，下面露出有线指着的槽位（落点，连同草稿里改到的）。露出来的槽位照样排成树，只是没被指着的不画；每一层按列表页的排法：需要你的在前，然后是运行中的，其余在后。没有槽位被指着时，只有标题那一行。有线指着的已归档槽位也露出来。
- 展开的工作区是一个框，只有标题那一行能点。里面的槽位按派生排成树：每个槽位下面紧跟它在同一个工作区里的子槽位，每深一层往右缩进 18px，右边和父槽位对齐。
- 树的线从父槽位左边往下，拐进每个子槽位，细线，不带箭头。
- 一个 Bot 的窗口排序：跟着默认的在前，单独选过的在后；每一组里你的私聊在前，别的在后；单独选过的再按目标在图上的位置排，线交叉最少。按存着的绑定排，草稿不挪窗口。
- 起点和终点：
  - 每个窗口右边一个起点。Bot 标题行的右边一个起点，它左边一点是 Bot 的终点，悬在窗口右边留出的空当上。Bot 框里的窗口右边留出约 24px，给连线走。
  - 每个槽位左边的正中一个终点，几条线都落在这一点，不标数字。平时只有被指着的槽位画终点。
  - 起点实心，终点空心，颜色和线一样。
- 线一律是直角线，拐角带一点圆角。三种：
  - Bot 的线：每个 Bot 一条，从它的起点到它默认目标的终点。粗实线。没有默认目标的 Bot 只有起点，没有线。
  - 连线：每个跟着默认的窗口一条，从它的起点往右到空当里，再往上进它 Bot 的终点。粗实线。几个窗口的连线在空当里汇成一条竖线。
  - 单独选的线：每个单独选过槽位的窗口一条，从它的起点到那个槽位的终点。细虚线。
- 线总落在槽位的终点上：被指着的槽位收着时也露出来，所以不再落到工作区或祖先上。
- 竖着走的那一段，每条线有自己的一道，竖向重叠的线不共用一道。往下走的线，起点越高越靠右；往上走的，起点越低越靠右。
- 一条往上、一条往下的线竖向重叠时，谁在左都正好交叉一次：一条线横着走的那段，穿过另一条竖着走的那段。左右只决定谁穿过谁。
  - Bot 的线（粗）和单独选的线（细）：让粗线穿过细线竖着的那段，不让细线穿过粗线竖着的那段。粗线的起点落在细线竖段的高低之间，粗线排右边；终点落在里面，排左边。
  - 别的情况，往上走的排左边。
  - 同方向的次序优先。两条规矩顾不全时，挑细线穿过粗线最少的排法。
  - 细线的竖段整个落在粗线竖段的高低之间时，细线怎么排都要穿过粗线一次。两条粗线方向相反、竖向重叠，也免不了交叉一次。
- 几条线进同一个槽位时，在槽位左边一点之前各走各的高度，上面来的在上面，再汇到那一个终点。线越多，汇过去的这段越长。树的线照旧从子槽位的上半边进，和终点错开。
- 窗口和槽位在手机上的缩放下至少 44px 高，手指点得准。
- 路径里的一格最宽 11rem，名字更长就在末尾截断，带省略号（#560）。
- 路径那一行的右边两个开关，都是图标按钮，鼠标停在上面时显示它是做什么的：“展开全部工作区”“显示已归档”。
- 全部展开的开关用 lucide 的 `unfold-vertical` 图标，存在这台设备上。开着时所有工作区都展开。开关它不改两栏的次序，焦点停在屏幕上原来的位置。
- 已归档的开关用归档的图标，不记住。开着时，已归档的槽位和没有在用槽位的工作区都画出来，已归档的槽位淡一些。焦点和它的祖先是已归档的也照样画出来。

节点长什么样：

- Bot：左上机器人图标；头像，右下角平台的小标志；名字；主 Bot 带一个星。连接不是在线时，头像右上角一个点：重连中是琥珀色，故障是红色。
- 聊天窗口：你的头像，右下角是私聊（一个人）或群聊（几个人）的标志；名字；主窗口带一个星。没有头像时，私聊或群聊的标志放大顶替头像。
- 收着的工作区：标题行是文件夹图标、名字；没露出来的槽位里需要你、运行中的有几个，各是一个色点加数字，0 个不写；右边一个箭头。下面是露出来的槽位。不显示目录。
- 槽位：左边的色条按看板的分组上色（需要你琥珀、运行中蓝、其余灰）；agent 的 logo；名字；父子跨工作区时一个分叉图标；右边一个小图标，只在这几种时有：已归档、TUI 模式、需要你、崩溃、等额度。无头的运行中和空闲不加图标，色条已经说了。
- 不写 agent 名、“无头”、“子槽位 N”、“对话 N”这类字。

点亮：

- 焦点外面一圈框。和焦点有关的节点保持清楚，其余淡到 30%。
- 有关的：
  - 槽位：父槽位、子槽位（在别的工作区时，点亮那个工作区）、指着它的线。
  - 工作区：它的槽位、指着这些槽位的线。
  - Bot：它的线、它每个窗口的线。
  - 线：它接着走的那一段一起亮。Bot 的线连同跟着这个 Bot 的窗口的连线；连线连同它 Bot 的线。单独选的线只有它自己。
  - 每条点亮的线，连带它两头的节点：起点的窗口或 Bot（窗口再连带它的 Bot），落点的槽位和它的工作区。
- 一个 Bot 只在它是焦点、或者它有窗口被点亮、或者它的线亮着时才亮。别的 Bot 一律变淡。
- 点亮的线变成前景色、加粗一点，画在最上面；别的线淡到几乎看不见。
- 展开的工作区框本身不变淡。

点：

| 点什么 | 结果 |
|---|---|
| 槽位、工作区 | 它成为焦点并点亮，展开它的工作区，详情换成它 |
| Bot | 它成为焦点，只点亮，工作区都收起，路径停在总览 |
| 聊天窗口 | 等于点它的目标槽位。目标槽位已经是焦点时，什么都不变 |
| 线 | 它成为焦点，点亮它和它接着走的那一段，工作区都收起（开着全部展开时除外），路径是“总览”再一格“起点的头像、箭头、落点的 logo 和名字”，详情换成它 |
| 焦点本身 | 取消焦点：什么都不淡，展开的照旧，路径只剩“总览”，详情换回总览。再点一下又成为焦点 |
| 空白处 | 什么都不变 |

| 路径里的一格 | 回到那一格。“总览”还让镜头重新放下全图 |

- 点线：手指离线 18px 以内算点中，离几条线一样近时粗线优先。点在节点上算点节点，不算点线。
- 几个窗口的连线汇在一起的那段竖线，点在两个窗口之间就算下面那个窗口的连线。

镜头：

- 打开页面和点“总览”时：
  - 手机：按宽度放下整张图（Bot 那一栏也在屏幕里），缩放至少 0.85，从上往下看。图的顶边在路径栏下面 16px。
  - 宽屏：整张图放进屏幕，总览最多放大到 1.2，有焦点时最多 1。
  - 从地址直接打开到某个焦点时，先放下焦点和它周围的节点：槽位连同父子和绑着它的窗口；工作区连同它的槽位和绑进来的窗口；Bot 连同它的窗口和默认目标；线连同它点亮的节点。
- 换焦点时，点的那个节点在屏幕上的位置和缩放都不变。布局变了，画面跟着平移补偿。
  - 补偿以后它被挡住或出了屏幕，画面挪最短的距离把它带进来，离边 16px，滑 0.3 秒。整个都在屏幕里的不挪，离边不到 16px 也不挪。焦点是工作区时，只把它的标题带进来。
  - 手机的底部面板停在新高度以后，焦点被盖住了，也这样带进来。
- 边界：拖不出图外 32px；最小缩放是整张图放得下的那一档（在 0.5 和 1 之间），最大 1.5。图比屏幕小的那个方向居中。
  - 手机上竖着例外：图比画布矮时不居中，顶边留在路径栏下面 16px，空出来的地方留给底部面板。拖动和缩小都不把它挪到中间。放大以后往上拖，图的顶边也不出屏幕。
  - 换焦点补偿以后、返回到这一步、屏幕变了大小以后，画面停在哪，那时屏幕上的那一块也算在边界里，直到画面重新放下全图。不然图比屏幕小时，居中会把点的节点挪开，下次一拖画面又跳一下。手机上你自己缩放以后，这一块也不再算，画面滑回边界里。
- 不能拖动节点，双击不缩放。宽屏上滚轮平移。

返回（手机的返回键，电脑上浏览器的后退）：

- 每一步写进浏览器的历史。
- 新加一步：往深处走，或者跳到不同层的地方。
- 只替换当前这一步：在同一层之间换。同一层指路径里的上一格相同：几个 Bot、工作区和线之间（上一格都是总览）、同一个工作区的几个顶层槽位之间、同一个父槽位的几个子槽位之间。
- 不算一步：点空白、开合和拖底部面板、展开预览、取消焦点、开关全部展开和已归档、切列表和拓扑图。
- 往上走用路径。

底部面板（手机）：

- 平时只有一行，66px：左边一个图标（agent logo、Bot 头像、文件夹或总览的房子），名字，下面一行小字是状态。焦点是线时，这一行是起点的头像、箭头、落点的 logo 和全名。槽位和线右边有“打开槽位”按钮；有可展开的内容时最右边一个箭头，顶上一个拖动条。
- 没有箭头时，最右边的“打开槽位”或“新槽位”离屏幕右边 16px，和左边的图标离屏幕左边一样（#560）。
- 点这一行（按钮以外的地方）或者点箭头：收着就升到屏幕的 46%，开着就收回一行。
- 拖这一行：跟着手指走，松手停在那里。拖到不到两行高就收回一行。
- 最高到图的可见部分剩三分之一，留地方给焦点。
  - 转屏、改窗口大小时，这个上限跟着窗口变：比新上限高的面板缩到上限，整页不比屏幕高。存着的高度不变，转回来还是原来那么高（2026-11-10 加，#648）。
- 不比它的内容高。没有可展开的内容时，只有这一行，没有拖动条和箭头，拉不开。
- 高度存在这台设备上：换焦点、离开再回来都不变。
- 换焦点时，底部面板里的内容滚回顶上。

电脑上的详情卡片：

- 浮在图的右边，宽 320px（更宽的屏幕 384px），离边 12px。
- 一直展开，没有拖动条和箭头。内容多高卡片多高，最高到图的高度，再多就在卡片里滚。
  - 电脑上（`pointer: fine`），卡片的滚动条是看板自己那种细的圆角滚动条：没有上下箭头，不被卡片的圆角切掉（2026-11-06 加）。手机上浮在字上（#646）。

底部面板和详情卡片里滚的内容，被切的那头渐隐，不让一行字只露出半截（2026-11-09 加，#638）：

- 还能往上滚时顶上渐隐，还能往下滚时底下渐隐。每头最多 2rem，也不超过这一头还能滚多远。不用滚时没有渐隐。
- 电脑上滚动条不淡；手机上它浮在字上，跟着一起淡（#646）。
- 内容换了（换焦点）、后来才有（数据到了）、展开收起改了高度（例如预览框）时，渐隐跟着变。

详情的内容：

- 总览：房子图标和“总览”，下面一行是需要你、运行中的色点和个数。内容是这两类槽位，各一组，组名带色点。两类都没有时没有内容。
- Bot：头像和名字，主 Bot 带星；连接不是在线时下面一行写“重连中”或“故障”。内容是它的窗口，每行右边是目标槽位的 logo 和名字，点了去那个槽位。
- 工作区：文件夹图标和名字，不写目录。内容是绑进这个工作区的窗口，每行右边是目标槽位，点了去那个槽位。
- 线：起点的头像、箭头、落点的 logo 和全名，带“打开槽位”。没有可展开的内容。
- 槽位：agent logo 和全名，下面一行是状态（色点加说法，例如“运行中”），一次性的再加“一次性”小标签。内容依次是：
  - 绑着它的窗口，私聊在前。联系窗口（[术语表](../../GLOSSARY.md)）不在其中时也列出来，行尾一个发送图标表示它。
  - 派生树：父槽位、它自己（加深底色，不能点）、子槽位，用和图上一样的树线连着。同一个工作区的写名字，别的工作区的写全名。没有父子时整块不显示。
  - 时间线（见下）。
- 聊天窗口那一行：头像（带私聊、群聊标志）、名字、主窗口的星；不在 Bot 的详情里时，后面是平台小标志加 Bot 名。
- 不写“所属工作区”“派生自：没有”“新的在上”“当前”“怎么看”这类字。

时间线和预览：

- 每段一行：agent logo；标题一行，截短；下面一行小字是短 ID（等宽字）和最后活动的时间。当前那段左边一条竖线。
- 按最后活动从新到旧排，正在用的那段通常在第一个。
- 标题是 `null` 的，缩成一行淡色小字：logo、短 ID、时间。不能展开。agent 还没给会话 ID 的，没有短 ID，只有 logo 和时间。
- 先显示最新的 5 段，再多就是一行“还有 N 段”，点了显示全部。
- 点一段，在它下面展开预览框；同一时间只展开一段，再点收起。
- 展开的那一行和它的预览框合成一个框，中间一条分隔线（2026-11-06 改，原来是两个分开的框）。
- 预览框有一截在详情的视野外时（例如手机上底部面板在半高），展开时把它连同那一行滚进视野，看得到最新那几句（2026-11-06 加，2026-11-09 改，#637）。
  - 那一行和框上下各留 2rem，不落在详情两头的渐隐里。
- 预览框手机上最高 240px，宽屏最高 320px，在框里滚。
  - 这么高的框连同它下面留的 2rem 放得下、再加上那一行就放不下时，框缩矮到详情的可视高度减去那一行和上下留的 2rem，那一行和框都完整露出来（2026-11-09 加，#637）。原来框不缩，框的底边对到详情的底边，那一行被滚到详情的顶边外面一截。
    - 只缩详情装不下的那一截。详情还能跟着内容长高时（卡片和底部面板都是内容多高就多高），框不缩；少缩一点整块就放得下、不用滚时，只缩那一点。
  - 这么高的框连同它下面留的 2rem 也放不下时（例如很矮的宽屏窗口），框不缩，也不滚框，改把点的那一行滚到详情顶上，在渐隐下面，下面是框放得下的那截。滚框的话，那一行也会被滚走，要收起得先往上翻（2026-11-06 加，#611）。
  - 详情变高变矮时（拖底部面板、改窗口大小），开着的框照上面两条跟着变：
    - 框变高、底边出了详情时，把它滚回来，放不下就是那一行到了详情顶上。
    - 详情变矮时（例如把窗口一下子改矮）：放得下的框，底边落进底下的渐隐或更下面，把它连同那一行滚回来；放不下的框，那一行落进底下的渐隐或更下面，把那一行滚到详情顶上（2026-11-10 加）。
    - 你自己滚详情，把那一行或框滚得有一截出了视野或落进渐隐以后，不跟着滚，停在你翻到的地方（2026-11-10 加）。放不下的框只看那一行。
      - 例如展开以后翻回顶上看槽位树，再拖底部面板，画面不动。
    - 别的时候不滚。没被你翻走时，拖底部面板，框一直跟着在视野里，画面不跳。
  - 框里的消息列表被切的那头也渐隐，和详情卡片一样（2026-11-09 加）。
  - 框里的滚动条和对话页详情里时间线那块的滚动条，电脑上也是看板自己那种细的圆角滚动条，没有箭头（2026-11-06 加）。手机上浮在字上（#646）。
- 对话页详情里时间线那一块最高是窗口的 60%，再多就在里面滚。被切的那头渐隐，和详情卡片一样（2026-11-09 加，#638）。
  - 它下面的事件列表也一样：被切的那头渐隐，滚动条电脑上是看板自己那种细的圆角滚动条，没有箭头（2026-11-10 加），手机上浮在字上（#646）。
- 预览里的消息和对话页用同一套显示：你的话的气泡和来源标签、agent 的话按 Markdown 显示、工具调用折成一行能逐层点开、思考折起、系统行。
- 先取最新的一页（20 条）。往上翻到顶，接着取更早的一页，一路能翻回第一句，和对话页一样（2026-11-06 改，原来不往前翻）。
- 滚动和对话页同一套：打开时停在最新；有新消息时，在最底就跟着往下走；往上翻就停下；翻回离底 40px 以内又跟着走。
- 预览的是槽位当前那段对话时，和对话页一样实时更新，无头槽位的草稿也逐字出现：预览开着时，页面的事件流带上这个槽位（`/api/events?slot=`），收起就去掉。以前的对话不会再变，不跟。
- 显示消息的代码在对话页那一包里。打开第一个预览时才下载，和进对话页下载的是同一份，拓扑图那一包不含它。

对话页的气泡和来源标签：

- 你的话：右边的气泡，浅灰底加一圈细边（照 T3 Code 的样子），深色下是对应的深灰底和细边。`from` 认出了窗口时，气泡旁边是这个窗口的头像，没有就是平台标志。
- 气泡上方的来源标签：Bot 头像（带平台小标志）、Bot 名，群聊再加群名，后面是时间。
- `from` 是 `null`、来源行还在的（`rh send`、汇报），照旧：来源行原文的文字标签，不配头像。
- 终端里打的话：照样是气泡，不配头像，没有来源标签。以后网页上发的话也和它分不开，一样处理。
- 看板首页每个槽位的最近一句话不变。

对话页的详情抽屉：

- 打开的方式照旧：对话页顶栏右上的“详情”。
- 上面是进程，固定在抽屉顶上，不跟着滚；下面是事件，只有这一块滚动。不再写槽位的目录。
- 进程（只有无头槽位有）：一行，状态的色点加一句话，例如“运行中，PID 1234”“已退出，退出码 1”。不写 unit 名和子状态。
- 错误输出：有内容时是一行“错误输出”，点开是末尾几十行，等宽字，在框里滚。空的不显示。
- 事件从旧到新，每个一行：左边图标，中间一句话，右边时间。

| 事件 | 图标和颜色 | 写什么 |
|---|---|---|
| 收到你的消息 | 消息图标，灰 | 你的话的开头，最多两行。没交给 agent 的，后面写原因。库里最早一条“交给 agent”的记录之前的消息，交没交都没有记录，只写话本身 |
| 提问 | 问号图标，琥珀 | 哪一种提问，现在的结果：等你、已答、超时、作废 |
| 提问答了 | 对勾图标，灰 | “已回答”，超时的写“超时，按默认作答” |

| 回合结束 | 旗子图标，灰 | “回合结束” |
| agent 主动发消息 | 发送图标，蓝 | “agent 发给你一条消息” |
| 崩溃 | 三角图标，红 | “崩溃，退出码 1”或“崩溃，信号 SIGKILL” |
| 别的出错：没能切到终端、没能切回无头、看不懂 agent 说的话、找不到 agent 程序、Herdr 断了 | 三角图标，红 | 一句话说哪里出错，后面是原因，例如“没能切回无头：pane 已关闭” |
| agent 退出 | 方块图标，灰 | “agent 退出” |
| 别的 | 不加图标，灰色细字 | 事件名。点开看原始数据 |

- 发出去的消息挂在它的事件下面，往右缩进，每条一行，截到两行，点开看全文。
  - 挂在哪：同一串事件（同一条你的消息引起的）在这个槽位里最早的那个事件。按整个槽位算，不按这一页算，所以翻页和实时更新都不会挂错、挂两次。服务端算好再给。
  - 发成功的不标。没发出去的前面一个红色的叉，结局不明的一个琥珀色的问号。还在排队、等你回话的写一个灰色小字。
- 滚动和对话页同一套：打开时停在最新，新事件来了在最底就跟着走，往上翻就停下，翻到顶附近自动取更早的一页，画面不跳；不在最底时来了新事件，底部出“新消息”按钮。
- 实时：抽屉开着时，收到这个槽位的事件，就重取最新的一页，按序号接上新的、换掉已有的。
  - 这样最新一页里消息的发送状态、提问的结果也跟着变。
  - 更早几页里的不跟，关了抽屉再开才是新的。
  - 取回的这页和已显示的没有重叠时（比如断线期间来了 50 个以上事件），丢掉已显示的，从这页重新开始。
- 抽屉在手机上照旧从右边滑出，占九成宽。

  - 现在它把首屏以外的 JS 全算成对话页的，要改。

## 测试决定

照 [v1 规格](v1.md#测试决定)的规矩：只测外部看得到的行为，测试名带故事编号。

- 布局的纯函数在 `bun test` 里测，用手写的几份数据：真实规模的一份、约 30 个槽位 10 个窗口的大的一份、再加一个子槽位落在别的工作区的。每种焦点（包括每条线）、宽屏和手机、全部展开和已归档开和关都跑一遍：
  - 节点 ID 不重；每条线两端的节点都显示着；每个节点都在能拖到的范围里；点亮的节点都显示着。
  - 竖向重叠的两条绑定线不共用一道，往下走的起点高的靠右，往上走的起点低的靠右；绑定线和树的线不落在子槽位的同一点。
  - 细线只在它的竖段整个落在粗线竖段的高低之间时，才穿过粗线竖着的那段。拥挤的那份数据里（Echo 有个群聊选了它标题和默认目标之间的槽位），交叉不比往上的一律排左边时多，细线穿过粗线的次数比那时少。
  - 每个父子都在同一个工作区的子槽位，排在父槽位下面，缩进一层，右边对齐，两者之间只有父槽位的后代；每个这样的子槽位有一条树的线。
  - 一个 Bot 亮，当且仅当它是焦点、或它有窗口亮着、或它的线亮着。焦点是一个 Bot 时，别的 Bot 都不亮。
  - 每个 Bot 有默认目标时一条线到它；每个跟着默认的窗口一条连线进它 Bot 的终点；每个单独选过的窗口一条线到它的槽位；没有别的绑定线。
  - 每个槽位最多一个终点，落在它上面的线都到这一点。
  - 总览里收着的工作区只露出被指着的槽位，每一层需要你的在前、运行中的其次；工作区上的个数不含露出来的。
  - 开着全部展开时，每个工作区都展开，换焦点也不收。
  - 焦点是线时，点亮的线就是它和它接着走的那一段，点亮的节点是这些线的两头。
  - 一个 Bot 框里跟着默认的窗口在前，每一组里你的私聊在前。展开工作区、开关全部展开都不改两栏的次序。
- 详情抽屉里每种事件的图标、颜色和那句话，写成纯函数单测。
- 前端别的有逻辑的部分写成纯函数单测：点中哪条线（离几条线一样近时粗线优先，汇在一起的竖线算下面那个窗口的）；路径；返回时新加一步还是替换；镜头的边界、放下、补偿和“挪最短的距离”；底部面板高度的上下限。
- 接口在 `test/board.test.ts` 那一层测：
  - `/api/topology` 不给陌生人的窗口；绑定和路由算的一样；整份回答里找不到种子数据里的令牌、openid 和平台 ID。
  - `/api/slot` 的 `timeline`；`/api/messages` 按对话取；`from` 认出 Bot 和窗口，认不出的是 `null`。
  - `/api/avatar` 过登录检查；没有头像回 404；头像变了，数据里的地址跟着变。
  - `/api/slot-events` 从旧到新；`before` 一路翻回第一个事件，不重不漏；一串事件跨两页时，发出去的消息只挂在最早的那个事件下面，两页里不重复。
- 头像在 `bun test` 里测，平台接口用假的 HTTP 服务：
  - QQ 回 `X-Info: notexist` 时不存。
  - Telegram 的照片在服务端下载，文件地址不出现在日志和任何回答里。
  - 取失败时留着上次的。
  - 日志里没有令牌、openid、用户 ID 和地址。
- Playwright 冒烟测试（`test/board-smoke.test.ts`）拓扑图加几条，真 Chromium、手机尺寸，自己写种子：
  - 打开 `#/topology`，点工作区、点槽位，底部面板只有一行；点“打开槽位”进对话页，返回后焦点还在；再点焦点，取消焦点。
  - 首页切到拓扑图，刷新以后还停在拓扑图；对话页的拓扑图按钮打开时焦点在这个槽位。
  - 拖底部面板到一半，换个焦点，高度不变。
  - 点一条 Bot 的线，路径和底部面板写着它，返回回到总览；打开全部展开，刷新以后还开着。
  - Pixel 7 上照真实实例的名字（“匿名用户”“Echo Agent”等）画总览，图里的名字一个都没被截断。
- 对话页的冒烟测试加一条：种下 60 个事件，打开详情抽屉，停在最新；翻到顶，接上更早的，画面不跳。
- 首屏、对话页那一包、拓扑图那一包的大小，都由 `test/build.test.ts` 守着。
- 真的平台头像接口不在测试里调，靠验收发现变化。

## 你来验收

在手机上：

- 打开看板，首屏和以前一样快。切到“拓扑图”，从桌面图标重新打开：还停在拓扑图。
- 总览：三个 Bot 都是它们真的头像，带平台小标志，框左上有机器人图标。每个私聊窗口是你的头像；QQ 的两个写淡色斜体的“匿名用户”，Telegram 的写你的名字。
- 点 dispatcher，再点 main：有关的线和节点清楚，别的变淡。再点一下 main：都不淡了，dispatcher 还展开着。
- 点 Echo 的框：只有它和它的窗口、线亮着，main 和 telegram 两个 Bot 也淡了，dispatcher 收起来。
- 点 telegram 框里你的私聊：直接到 dispatcher/main。
- 回到总览：每个 Bot 一条粗线到它的默认目标，私聊用粗的连线接进 Bot 的终点；收着的工作区里露出这些线指着的槽位，每个槽位左边只有一个圆点。
- 点 main 那个 Bot 到 dispatcher/main 的粗线：它和 main 框里私聊的连线亮着，底部面板写着这条线，带“打开槽位”。
- 打开“全部展开”：工作区都展开。关掉页面再打开：还开着。电脑上鼠标停在两个开关上，显示它们是做什么的。
- 把底部面板拉到一半，点别的节点：它还在那个高度。关掉页面再打开：还是那个高度。点总览，没事要你管时底部面板只有一行。
- 在 main 的详情里点时间线的一段：预览展开，和对话页一样好看，停在最新。在 QQ 里让 main 说句话：预览跟着往下走；往上翻一点再让它说：不动；翻回最底：又跟着走。
- 让调度员派生两个子槽位：它们出现在 main 下面，缩进一点，有树线连着。
- 点几下：dispatcher、main、一个子槽位，再在两个子槽位之间换几下。按返回：先回到 main，再回 dispatcher，再回总览。
- 在 main 上点“打开槽位”：对话页里你的话是浅灰带细边的气泡，旁边是你的头像，上面是 Bot 头像和名字。按返回：回到拓扑图，焦点和画面没变。
- 从列表进一个槽位，点顶栏的拓扑图按钮：图打开，焦点在这个槽位。按返回回到对话页。
- 在对话页打开详情抽屉：事件从旧到新，停在最新；崩溃是红的，状态变化是一行灰字。往上翻到顶，接上更早的。
- 手机切到深色：图和详情都看得清。

在电脑上：

- 详情是右边一张卡片，内容多高卡片多高。
- 打开槽位：对话开在右边，图在左边。点图上别的槽位，右边跟着换。

| 手动刷新头像 | 按需。现在一天一次 |
| 记住已归档开关 | 按需。全部展开的开关记住 |
| React Flow 13 | 出正式版以后 |
| 网页推送、service worker | 第 3 步再定 |

## 其他说明

### 拆 issue

- 每张工单写明覆盖哪几条故事、被哪张挡住。
- 先做服务端的数据。头像和页面都在它后面，两条可以并行。
- 页面先不带头像也能用：没有头像时显示标志。头像那张合进来以后，页面不用再改就显示头像。
- 入口和对话页的气泡各是一张，分别在页面和头像后面。
- 详情抽屉单独一张，不等别的。
- 预览和详情抽屉都用对话页“停在最新”的滚动。哪张先做，就由它把这段从对话页里抽出来共用。
