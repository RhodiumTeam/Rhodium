# 网页能写规格

这篇回答：网页第 3 步“网页能写”要做成什么样、满足哪些需求、怎么测、怎么验收、明确不做什么，以及怎么拆工单。

前置阅读：[术语表](../../GLOSSARY.md)、[产品说明](../product.md)、[架构](../architecture.md)、[IM 文字与交互规范](../im-style.md)、[v1 规格](v1.md)、[网页对话界面规格](web-chat.md)、[网页拓扑图规格](web-topology.md)

大规则在 2026-10-21 定下，写在[产品说明](../product.md) §7“网页能写以后”那一段。这一步怎么做、先做什么，在 2026-10-24 的拷问里定下，也写进了产品说明 §7。这里不重复，只写需求、接口的变化、测试和交付。

这篇用到几个词：

- 写操作：网页上改东西的操作，例如停止、换 agent、发消息、改绑定。
- 轻提示：页面底部一条小框，写操作的结果。
- 操作条：对话页输入框下面一排按钮：agent 的 logo、模型和思考强度、终端。
- 选择单：从几样里选一样的列表。候选和 IM 的[选择面板](../../GLOSSARY.md)是同一份。原来从底部升起，2026-10-24 起放在[信息卡](../../GLOSSARY.md)里（[产品说明](../product.md) §7）。
- 编辑开关：拓扑图路径那一行的铅笔按钮，按下才能改绑定。
- 草稿：拓扑图上改了、还没确认的绑定。
- 选中的线：编辑时点了的那条线。先选中一条线，才能拿起它的起点或终点。
- 起点、终点、单独选的、连线、落点：见[网页拓扑图规格](web-topology.md)开头。
- [命令面板](../../GLOSSARY.md)、[待发队列](../../GLOSSARY.md)：见术语表。

## 问题

**网页只能看。**

- 停一个回合、换 agent、切到终端，都要回 IM 发命令，或者 ssh 进去敲 `rh`。
- 看板上明明看得到槽位卡住了，手还得换个地方。

**改绑定很绕。**

- 拓扑图画出了哪个窗口交给哪个槽位，但改不了。
- 要改，得去那个窗口里发 `/rh_use`。在终端里 `rh use` 又要写平台的窗口 ID，网页上看不到它。

**提问只能去 IM 答。**

- 对话页底部的提问卡片写着“到 IM 里回答”。人已经在网页上了，还要切回 IM。

**IM 的面板在手机上步数多。**

- 换模型再改思考强度，QQ 上是两条消息、两次点按。
- 面板的候选在 IM 里一页 8 个，多了要翻页。

**网页上开不了对话。**

- 想让某个槽位做件事，只能从它绑着的 IM 窗口说。没有窗口绑着它，就只能 `rh send`。

## 方案

这一步做完后，网页上能做 IM 里大多数 `/rh_` 命令能做的事：发消息、答提问、换 agent 和模型、切终端、改名、归档、新建、导入、改设置，在拓扑图上改绑定。结果显示在网页上，不往 IM 发回执。

对话页，手机上大致是这样：

```
← ✳ dispatcher/main                  ⧉  ⋯  [详情]   ← ⧉ 拓扑图，⋯ 不常用的操作
    空闲                                             ← 模型写在操作条上，这里只写状态

        (main) 11:22                                 ← Bot 头像和名字
        习惯和设定上是不是有些差异？……       (你)
▸ Bash
你观察得对，两份 CLAUDE.md 在这点上确实设定相反……

┌──────────────────────────────────────────────┐
│ 发消息                                         │
│ [✳ v] [Opus 4.5 high v] [>_]          [+] [↑] │  ← 操作条；附件、发送
└──────────────────────────────────────────────┘
```

回合在跑时，发送键按“现在按下去会怎样”换图标。打了字按下，这句排进输入框上面的待发队列，回合跑完再发：

```
正在跑 Bash 查 Rhodium 版本                 3 秒
┌ ≡ 2 ─────────────────────────────────────────┐  ← 待发队列，2 条
│ 顺便看看日志                        ↱  ✎  ✕  │  ← 插话、编辑、删除
│ 再跑一遍测试                        ↱  ✎  ✕  │
└──────────────────────────────────────────────┘
┌──────────────────────────────────────────────┐
│ 还有一件事                                     │
│ [✳ v] [Opus 4.5 high v] [>_]          [+] [≡+]│  ← 有字：排队；没字时是 ■ 停止
└──────────────────────────────────────────────┘
```

打 `/`，输入框上面弹出命令面板，边打边筛。agent 的 logo 和模型按钮，是 `/rh_agent`、`/model` 的快捷方式，弹出同一张选择单：

```
┌──────────────────────────────────────────────┐
│ ■  /stop                     停下这一回合      │
│ ⊕  /new                      开一段新对话      │
│ ↺  /resume  [<对话>]         回到以前的对话    │
│ ◇  /model   [<模型>]         换模型            │
│ …                                              │
└──────────────────────────────────────────────┘
│ /                                              │
```

挂着提问时，输入框换成提问卡片，停止键留着：

```
 ?  更喜欢猫还是狗？                10:42 超时   ■
 [猫]  [狗]
 [自己写                                     ] [↑]
```

拓扑图上改绑定：按铅笔进编辑。点一条线选中它，再点它的终点，把终点拿起来，能放的终点亮起；再点一个，线就改到那里。点它的起点，是和别的起点互换。下图把 QQ 私聊从跟着默认改成单独选 helper：

```
⌂ 总览                                ⇕  ▥  ✎   ← ✎ 按下是编辑
 ┌▣ (QQ) main ★      ○ ●━━━━━━┓
 │(你) 匿名用户 ★     ●┅┛ ─ ┐  ┃     ┌▢ dispatcher───┐
 └────────────────────────┘ │  ┗━━━━○┃✳ main       │
 ┌▣ (TG) telegram    ○ ●━━━━│━━━━━━━━┛└──────────────┘
 │(你) Alex Chen      ●━┛   │
 └────────────────────────┘ │       ┌▢ notes────────┐
                            └ ─ ─ ─○┃✳ helper      │ ← 蓝色细虚线是新加的
                                    └──────────────┘
────────────────────────────────────────────
 改了 1 处                        ↶   ✕   ✓       ← 撤销一步、全部撤销、确认
```

`┅` 是要删掉的连线，画暗红色。

这一步包含：

- 看板收写请求：按你本人交给路由；只认看板自己页面发来的请求。
- 对话页：输入框、附件、发送键、待发队列、命令面板、操作条、能答的提问卡片、TUI 横幅上的“收回终端”。
- 详情抽屉：停掉进程、设置、时间线上“回到这段”。
- 首页：“+”新建槽位和导入；“已归档”里每个槽位的恢复按钮。
- 拓扑图：编辑开关、拿起线的终点或起点改绑定、拖线、草稿和确认、确认后重排、节点上的操作、窗口的工具行开关、工作区的“新槽位”。

## 用户故事

“用户”就是你本人。编号接着[网页拓扑图规格](web-topology.md)，从 255 开始。2026-10-24 改绑定换成新做法时，补的几条从 377 起；换掉的旧故事留着编号，写明换成了哪条。2026-10-28 这一批（#451）补的从 517 起，每条写明哪张工单做。

### 写的规矩

255. 作为用户，我想要网页上的操作以我本人的身份执行，能做的和我在终端里用 `rh` 一样，以便手机上不开 ssh 也能管槽位。
256. 作为用户，我想要操作的结果只在网页上显示：成功的是一条轻提示，几秒后消失；出错的留着，点掉为止，以便 IM 里不多出回执，出错了也不会漏看。2026-10-28 改：出错的也会消失，留 8 秒（故事 543）。
257. 作为用户，我想要按钮按下后、结果回来前转圈，不能再按；网络断了重试，也不会做两遍，以便手抖不会发两条消息。
258. 作为用户，我想要只有看板自己的页面能发写请求：tailnet 上别的页面、别的网站借我的浏览器，都发不进来，以便我开着别的页面也不会被冒充。
259. 作为用户，我想要另一台设备、另一个标签开着的看板，跟着我的操作一起变，以便几处看到的都一样。
260. 作为用户，我想要网页改了某个聊天窗口的目标，Rhodium 在那个窗口说一句；我在终端里用 `rh use`、`rh bind` 改的也这样，以便 IM 那边不会莫名其妙换了人。
261. 作为用户，我想要网页发起的切换（换 agent、切终端）成功了只在网页上说，失败了照旧发故障通知，以便出了事也知道。
262. 作为用户，我想要网页上的回复提到下一步时，指的是网页上的按钮或拓扑图，不是让我去打的命令，以便看完就能接着点。
263. 作为用户，我想要网页上只有收回终端弹确认框，别的操作按下就做，以便常用的操作不多一步。后来切到终端也先确认（故事 476）。
543. 作为用户，我想要出错的轻提示也自己消失：留 8 秒，底边一条进度条连续地缩短，和带撤销的那条一样；点一下照旧马上关，以便不用一条条点掉。2026-10-28 加的（#460）。

### 停止和槽位上的操作

264. 作为用户，我想要回合在跑时有一个停止键，挂着提问时也在，按下停在这一回合，进程留着，以便看到 agent 跑偏时马上叫停。
265. 作为用户，我想要操作条上一个终端按钮，把槽位切到 TUI；回合在跑时问我“跑完再切”还是“打断，马上切”；切过去后电脑上 Herdr 的焦点停在那个 pane，和 IM 里一样，以便要动手时一按就到终端。
266. 作为用户，我想要 TUI 横幅上有“收回终端”，弹框确认后切回无头，以便不用去 IM 里再确认一次。
267. 作为用户，我想要在“⋯”里改名，标题原地变成输入框，以便不用记命令的写法。
268. 作为用户，我想要在“⋯”里归档，不弹框；轻提示里有“撤销”，留 8 秒，一条进度条平滑地缩短；8 秒内按下，槽位恢复，归档时改回默认的窗口也指回去，以便手滑了能反悔。
269. 作为用户，我想要首页“已归档”里每个槽位有一个恢复按钮，以便不用记命令。
270. 作为用户，我想要在详情抽屉进程那一行停掉进程，对话留着，以便槽位卡住时不用去终端。
271. 作为用户，我想要拓扑图上槽位的详情里有同一批操作：停下回合、停掉进程、切到终端或收回终端、归档；电脑上右键槽位弹出同一排，以便在图上看到问题就地处理。
535. 作为用户，我想要在首页列表和放大模式的侧栏里右键或长按一个槽位，弹出一个小菜单：没归档的无头槽位是“归档”，已归档的无头槽位是“恢复”“删除”；在终端里的槽位不管归没归档都不弹，以便不进对话也能收拾槽位。2026-10-28 加的（#458），那时只有安卓上能长按；2026-10-31 iPad、iPhone 上也能了（#504）。2026-10-31 又加了几项，见故事 550。
536. 作为用户，我想要已归档的无头槽位的对话“⋯”里也有“删除”，以便看着它时就能删。2026-10-28 加的（#458）。
537. 作为用户，我想要删除先弹框确认，确认就删，不给撤销；删的是正开着的对话，就离开它，以便删除这种回不来的事不会手滑，也不会停在一个没了的槽位上。2026-10-28 加的（#458）。
550. 作为用户，我想要列表行的菜单里，没归档的无头槽位还有“开新对话”“改名”“切到终端”，回合在跑时最前面还有“停止”，做的和对话里的一样，以便不进对话也能做常用的事。2026-10-31 加的（#491）。
560. 作为用户，我想要列表行的菜单里，没归档的无头槽位有“置顶”，置顶了的换成“取消置顶”，以便把常用的槽位钉在列表上面，不用记命令。2026-10-31 加的（#506），置顶怎么排见[产品说明](../product.md) §7。

### 发消息

272. 作为用户，我想要在对话页底部给这个槽位发消息，和在 IM 里一样：空闲时开新回合，进程没起时拉起，以便不开 IM 也能和 agent 聊。
273. 作为用户，我想要发出去马上出一个淡色的气泡，agent 读到后换成正式的气泡；没发成的变红，带重试，以便知道发出去没有。
274. 作为用户，我想要从网页开始的回合，过程和回复只在网页上显示，IM 什么都收不到；回合中途我从 IM 插一句，后面的回复改发 IM，以便在哪说就在哪看。
275. 作为用户，我想要网页开始的回合里 agent 提问，我在 IM 里答了，后面的过程和回复也改发 IM，以便提问把我叫回 IM 以后，不用再回网页看结果。
276. 作为用户，我想要发图片和文件，agent 看得到图片；发之前能删掉选错的，以便在手机上把截图交给 agent。
277. 作为用户，我想要没发出去的字按槽位留在这台设备上，以便切走再回来不丢。
278. 作为用户，我想要槽位在终端里时输入框换成 TUI 横幅，挂着提问时换成提问卡片，磁盘不够时写明原因，以便知道为什么现在发不了。
279. 作为用户，我想要输入框里 `!` 开头的话和 Rhodium 认识的 `/` 命令，和在 IM 里一样处理；Rhodium 不认识的 `/` 命令原样交给 agent；网页上另有地方做的命令（例如 `/rh_use`、`/rh_release`），回一句去哪里做，以便手上的习惯不用改，也不会绕过网页上的确认。
280. 作为用户，我想要我在网页上发的话，在对话里和终端里打的一样：气泡，不带头像和来源标签，以便和 2026-10-23 定的一致。
281. 作为用户，我想要 agent 收到网页发的话时，开头的来源行写“[来自 网页]”，以便它知道这句不是从 IM 来的。
511. 作为用户，我想要右键发送键（手机上长按）选“Ctrl+Enter 发送”还是“Enter 发送”，Mac 上写 ⌘；选 Enter 时，Ctrl、⌘、Shift 加 Enter 都换行；这台设备记住我选的，以便按自己的习惯打字。

### 回合在跑时

282. 作为用户，我想要只有一个发送键，图标跟着“现在按下去会怎样”变：没在跑是发送；在跑、没打字是停止；打了字是排队；`!` 开头是打断再发；Rhodium 认识的命令是发送，马上执行，以便看一眼就知道按下去会怎样。
283. 作为用户，我想要回合在跑时打的话排进输入框上面的待发队列：每条一行，带“插话”（马上并进这一回合）、“编辑”（放回输入框）、“删除”，以便想清楚再发，也能随时插进去。
284. 作为用户，我想要回合跑完，待发队列里的一起作为下一个回合交给 agent，回复在网页上，以便不用守着回合结束再发。
285. 作为用户，我想要按了停止，待发队列不自动发，之后别的回合跑完也不发：队列头上换成暂停，带“继续”；每条的“插话”换成“发送”，以便停下来是为了改主意时，排着的不会冲出去。
286. 作为用户，我想要 Rhodium 替我扣着的网页消息（等额度、等打断生效、正在停止）也列在待发队列里，下面一行写为什么，只能删，以便知道这条为什么还没到 agent 手里。
287. 作为用户，我想要待发队列里的被 Rhodium 撤下时（例如切到终端），那几条回到输入框，轻提示写明为什么，IM 不收到它们，以便不丢，也不在 IM 里多出一堆。
288. 作为用户，我想要电脑上，命令面板没开时在输入框里按 Esc 就是停止，以便键盘上一下叫停。

### 命令面板和选择单

294. 作为用户，我想要在输入框开头打 `/` 弹出命令面板，贴着输入框上沿，和输入框一样宽，列出这个槽位能用的 agent 那边的命令；Rhodium 自己的 `/rh_` 命令网页上都有按钮，不列，以便面板里只有按钮之外的事。
295. 作为用户，我想要每条一行：图标、命令名、灰色的参数提示、灰色的一句说明，不分组，以便扫一眼就找到。
296. 作为用户，我想要边打边筛：命令名开头对上的在前，命令名里有的其次，说明里有的最后；打中文也找得到，例如 `/压缩` 找到 `/compact`；电脑上 ↑↓ 移动，回车或 Tab 选，Esc 关，以便手机和键盘都快。
297. 作为用户，我想要选中一条：要从几样里挑的，弹出选择单；不用参数的，马上执行；网页上有按钮的命令，选了就和按那个按钮一样，以便同一件事只有一种样子。

## 实现决定

### 已定的大方向

- 写操作走路由，和 IM 的 `/rh_x`、`/x` 同一条路。看板把请求变成一种路由输入，按你本人跑现成的 `rh()`、`common()`、`answerAsk()`。不另写一套业务。
- 不加表，不加配置，不加迁移。
  - 只加两种事件：`board_act`（每个网页操作一条）、`board_routed`（网页发的消息，对应 IM 的 `im_routed`）。
  - 待发队列用现成的 `agentInput` 排队，加一种排队原因，见[待发队列](#待发队列)。
- 不做乐观更新，等写请求的回复。回复在事务提交后同步回来，一般几十到几百毫秒。只有发消息先画一个待发的气泡。
- 页面刷新照旧靠事件流：有事件就重取。不加 WebSocket，不加 service worker，不加限流。
- 网页上的选择单和 IM 的面板用同一份候选（[IM 文字与交互规范 §9.1](../im-style.md#91-哪些命令有面板面板怎么走)）。网页不导入 `src/commands.ts`，候选由服务端给。
- 同一件事只有一种样子。命令面板里的命令，网页上有按钮的，选了就和按那个按钮一样：同一张选择单、同一个输入框、同一个确认框。

### 写请求

两个写接口：

| 路径 | 请求体 | 上限 | 做什么 |
|---|---|---|---|
| `POST /api/act` | JSON | 1MB | 按钮、选择单、改绑定、答提问、待发队列、工具行开关、不带附件的消息 |
| `POST /api/send` | multipart | 20MB | 带附件的消息 |

为什么两个：JSON 的请求，浏览器跨源发之前要先问一声，靠它挡跨源；附件太大，不适合塞进 JSON。

`/api/act` 的请求体：

```
{ id: "<页面生成，重试时不变>", act: <下面几种之一> }

{ kind: "common", slot: "<槽位 ID>", name: "stop", args?: "" }           // 通用命令，和 IM 里发 /stop、/model 一样
{ kind: "rh", argv: ["agent", "<槽位 ID>", "pi"], sure?: true }          // 白名单里的 rh 命令，和终端里一样
{ kind: "bind", changes: [{ chat, from, to } | { bot, from, to }], unarchive?: "<槽位 ID>" }  // 改窗口或 Bot 的目标
{ kind: "answer", ask: "<提问 ID>", text: "1" }                           // 答提问，text 和 IM 里回的一样
{ kind: "say", slot: "<槽位 ID>", text: "…" }                              // 发消息，也包括 ! 和 / 开头的
{ kind: "queued", slot: "<槽位 ID>", op: "now" | "drop", input?: "<排着的那条>" }  // 待发队列
{ kind: "verbose", chat: "<窗口行 ID>", on: true }                       // 窗口的工具行写法
```

- 回复沿用 `rh` 的 `RhReply`：`{ ok: true, text, panel?, undo?, slot? }` 或 `{ ok: false, error }`，都是 200。HTTP 状态码只留给传输层：403 身份或来源不对，405 方法不对，400 请求体不对，413 太大。
  - `panel`：要选的候选，见[面板回网页](#面板回网页)。
  - `undo`：撤销这次操作要发的请求，页面按“撤销”时原样发回。现在只有归档带它。
  - `slot`：新建的槽位 ID，页面拿它直接进对话页。`rh new` 的回复带它；导入是晚到的结果，它的回复也带。
- 看板不自己生成请求 ID，用页面给的 `id`。它也是这次操作的追踪 ID。
- 进主循环：
  - `src/contracts.ts` 里没用上的 `{ kind: "board"; id; path }` 换成 `{ kind: "board"; id; act }`。
  - 守护进程登记 `id` 到 `rh` socket 用的那张等回复的表，再放进主循环，和 `rh` 同一个 `rh_reply` 效果。
  - 主循环出错时，现在只给 `rh` 输入回“内部错误”。`board` 输入也要回，不然页面一直转圈。
- 路由里 `routed()` 加一个分支 `board()`，写法照 `rhCommand()`：
  - 身份是 `{ kind: "you", board: true }`，不经过 `caller()`。
  - 这次产生的事件来源改成 `board`，追踪 ID 是请求的 `id`。
- `common`：照 IM 的 `im()` 里 `/x` 那一支跑 `common()`。
  - 和 IM 一样排在提问前面：挂着提问时照样能停。TUI 里照 IM 只认 `/status`。
  - 不调 `contacted()`：网页不改联系窗口。
  - 停止键、“⋯”里的开新对话和压缩，都发它。选择单上的模型、思考强度和“回到这段”照[面板回网页](#面板回网页)当成打的命令发（`say`），路由同样交给 `common()`。
- `rh` 的白名单：`agent`、`tui`、`release`、`stop`、`archive`、`unarchive`、`rename`、`set`、`new`、`ws`、`import`，2026-10-28 加 `rm`（见[删除](#删除)）。
  - `stop` 只收 `stop <槽位>`，就是停掉进程。带 `--all` 的拒：急停不上网页。
  - 改目标只走 `bind`，不收 `use`、`bind`：它们不查改之前的样子。
  - 白名单不是安全边界（本机程序能直接连 socket），它让接口只做界面上有的事。
- `bind`：每处带“改之前是什么”，服务端比对，见[拓扑图上的改绑定](#拓扑图上的改绑定)。带 `unarchive` 时，先恢复那个槽位，再改，一个事务。
- 重试不重做：
  - 每个网页操作至少记一条 `board_act`。
  - 主循环算 `board` 输入前，用现成的 `store.traced()` 查这个 `id`。做过了，回“已经做过”，不再执行。
  - 被拒的操作不记事件，重试照样再拒一次。
- 晚到的结果（要 agent 答的命令、`/rh_import` 列出的对话）：请求一直等着，结果来了再回，和终端里的 `rh` 一样。
  - 看板读完请求体以后，不会因为空闲断开等着的请求（2026-10-24 实测 Bun）。
  - 网络断了，页面用同一个 `id` 重发，回“已经做过了”：命令照样做完，这次的结果看不到。
  - 页面关了，结果就只在详情抽屉的事件里。和终端里按了 Ctrl-C 一样，命令照样做完。

### 只认看板自己的页面

产品说明 §7 定了“看板只认它自己页面发来的请求”。`ts.net` 在公共后缀列表上，你 tailnet 里所有主机、所有端口彼此算“同站”，其中有 agent 写的页面，还有一个开着 Funnel 对公网开放。所以要求“同源”，不能只要求“同站”。

对每个写请求，在现有的 `Tailscale-User-Login` 检查之后：

1. 方法必须是 POST。
2. `/api/act` 的 `Content-Type` 必须是 `application/json`。
3. 有 `Sec-Fetch-Site` 时，必须是 `same-origin`。没有时，`Origin` 必须在，而且它的主机加端口等于 `Host`。两个都没有，拒。
   - 只比主机加端口：`Origin` 是 `https://`，`tailscale serve` 转给看板时是 `http://`。
4. 收回终端的请求必须带 `sure: true`。页面弹框确认后才带。防的是页面出 bug 跳过弹框，一行检查。

2026-10-24 在本机实测过，这套检查靠得住：

- `tailscale serve` 把 `Host`、`Origin`、`Sec-Fetch-Site` 原样转给后端。
- 从 `:8471` 端口的页面向同一台主机 `:8460` 端口发 POST，Chromium 带的是 `Sec-Fetch-Site: same-site`，`Origin` 是 `:8471` 的。同源的请求带 `same-origin`。
- `tailscale serve` 不查 `Host`：tailnet 上的程序能写任意 `Host`。这挡不住，也不用挡，浏览器做不到。

另外三样便宜的：

- 所有路径（读的也算）先检查 `Host` 的主机名是 `*.ts.net`、`127.0.0.1` 或 `localhost`，否则 403。
  - 挡的是 DNS 重绑定：本机浏览器里的恶意页面把自己的域名解析到看板。那时 `Host` 是它自己的域名，过不了。
  - 本机名照收，所以现有测试照旧连 `127.0.0.1`，排障时直接连 `127.0.0.1` 上看板的端口也照旧能用。
  - 这也补上了现在只读看板的同一个洞。
- HTML 加 `Content-Security-Policy: frame-ancestors 'none'; script-src 'self'`。
  - `frame-ancestors`：别的页面不能把看板嵌进去骗你点。
  - `script-src`：页面本来没有内联脚本。agent 写的东西万一混进一段脚本，也跑不起来。
- agent 写的东西（对话里的话、计划的全文）现在显示在一张能写的页面上。它们共用一份 Markdown 设置（`web/src/tools.tsx` 的 `MARKDOWN`）：不认原始 HTML，照原文显示；链接只认 `http:`、`https:`，别的只显示文字。
- 请求体上限见上表。Bun 默认 128MB。

不用页面令牌，不用 cookie。本机程序绕过 Tailscale 冒充你，照旧挡不住，2026-10-21 已经接受（[架构 §11](../architecture.md#11-安全与访问)）。

### 和 IM、终端不一样的地方

| 地方 | IM | 终端 | 网页 |
|---|---|---|---|
| 收回终端 | 发一条确认请求到 IM | 直接做 | 页面弹框，确认后直接做 |
| 切到 TUI 时 Herdr 的焦点 | 切过去 | 不切 | 切过去，和 IM 一样 |
| 切换的结果发到哪 | 发起的窗口 | 联系窗口；成功的只在有窗口指着槽位时发 | 成功只在网页；失败照旧发故障通知 |
| 回合在跑时发的话 | 插话 | 不适用 | 排进待发队列，能改成插话 |
| 回复里的“这里” | 用“这里” | 用名字 | 用名字 |
| 回复里的窗口 | 窗口名 | 现在写平台窗口 ID（要改） | 窗口名，永远不出平台 ID |
| 回复里提到下一步 | IM 命令，例如 `/rh_bind` | `rh` 命令，例如 `rh bind` | 网页上的按钮或拓扑图，例如“先在拓扑图上给 main 换一个默认目标，再归档” |

最后一行靠身份里的 `board: true`：路由现在按 `who.im` 选 `/rh_bind` 还是 `rh bind`，加一支选网页的说法。要改的回复，每张工单碰到哪条改哪条，至少有归档被拒那句、TUI 拒收那句。

### 面板回网页

- `RhReply` 的成功分支加一个可选的 `panel: { head: string[]; candidates: Candidate[] }`。`rh` 命令行只打 `text`，不受影响。
- 候选和 IM 面板的一样：名字、它的命令、是不是“现在”。页面不解析命令，按下就把这条命令当成在输入框里打的发出去（`say`），和 IM 里按按钮一样。
  - 候选在 IM 里按下后还要你接着写字的（例如 `/rh_import` 选了一个，接着要名字），带一个 `fill`：按下不发，把它写进输入框。
- 路由的回复去处是第一张工单起就有的 `board`，请求 ID 顶替 IM 消息的 ID：
  - `answer()` 见到它，不写出站消息，改成回复。带的按钮（例如 `/status` 的）除了“取消”都放进 `panel`。
  - `showIn()` 见到它，不翻页、不记窗口的面板，把问句和全部候选放进回复。
- 要 agent 答的命令（`/model`、`/effort`、`/compact`、`/context`、`/usage`、`/resume` 的列表）：`command` 效果和 `command_result` 事件本来就带着去处和请求 ID，运行器原样带回，路由按上面的去处回。没做成的回 `ok: false`。
- `rhCommand()` 现在要 Bot 和窗口来算“这里”。把“这里的槽位”改成参数：IM 传窗口的目标，网页传页面的槽位。

### 网页开始的回合

照 `im()` 的顺序走，下面是不同的地方：

- 回合的发起窗口 `turnChat` 记成固定值 `board`。它不是任何窗口的行 ID，不会撞。
  - 回合结束时找不到这个窗口，不往 IM 发。现成。
  - 内部消息（汇报、`rh send`、确认的结果）在有发起窗口的回合里排到回合后面。`board` 不是空的，自动排后面。现成。
- 回合的 `turnInbound` 记成这条消息的请求 `id`，它也是追踪 ID。和 `board` 一样，它不是 inbound 表的行 ID。
  - 不留空，是因为 `rh stop` 停进程时，退出后要不要再起进程，看的是 `turnInbound` 为不为空（停的过程中来了你的消息）。网页的消息也要能再起进程。
  - 用它找 inbound 行的地方（QQ 的被动回复额度、清理记录时的时间）找不到，照没有处理。现成。
- IM 插话时接管回合：`im()` 里四支只在没人占着回合时接管：“并入没有发起窗口的回合”、打断、等额度三支看 `turnChat` 为空，正在停止那一支看 `turnInbound` 为空。四支都改成：为空，或者 `turnChat` 是 `board`，都接管。这就是“回复改发 IM”。
  - 在 IM 里答了这个回合的提问，也算 IM 插话：`answerAsk()` 的 `by` 是窗口时，`turnChat` 是 `board` 就换成那个窗口，`turnInbound` 换成那条回答。之后的过程和回复发到那里。
    - 为什么：提问一定推到 IM（`pushAsk()` 发到联系窗口），网页又不推送。你多半是被 IM 叫回来答的，答完人在 IM。
- 不调 `contacted()`：网页不改联系窗口。
- 来源行用 `sourceLine("网页")`，写出来是 `[来自 网页]`。
- agent 的系统提示加一句：来自网页的回合，回复由网页显示，不要用 `rh send me` 再发一遍。
- 附件照 IM（[架构 §8.3](../architecture.md#83-媒体)）：存进状态目录的 `media/`，图片认出类型，正文里每个一行，图片另放进 `images`。图片和文件一次最多 20MB，照 Telegram 的上限。
- 不写 inbound 表（它要窗口和平台消息 ID）。另记 `board_routed`，`data` 里放正文开头，详情抽屉照样显示“收到你的消息”。
- 输入框里打的话照 IM 解析（`parseCommand()`）：
  - `!` 开头打断再发；只有 `!` 就是停止。
  - Rhodium 的通用命令走 `common()`，和 `common` 请求一样。
  - `/rh_` 开头的走 `rhCommand()`，“这里”是页面的槽位，和从命令面板里选一样。
  - 网页上另有地方做的 Rhodium 命令不做，回一句去哪里：`/rh_use`、`/rh_bind` 去拓扑图；`/rh_verbose` 去拓扑图上窗口的详情；`/rh_release` 点 TUI 横幅上的“收回终端”。`/rh_ls` 和 `/rh_help` 不回话，直接带你去：`/rh_ls` 回到首页列表，`/rh_help` 打开命令面板（2026-10-24 第 31 轮改）。
    - 为什么：`/rh_release` 走 `rhCommand()` 时身份是你、不是 IM，会直接收回终端，绕过网页唯一的确认框（`sure: true` 只查 `rh` 请求）。另外几条要 Bot 和窗口，网页没有。
  - 不认识的 `/` 命令原样交给 agent。
- 回合在跑时，普通的话不插话，排进待发队列，见下。
- 拒收：挂着提问（回“先答提问”）、在 TUI 里、磁盘不够。回复写原因。
- 已归档的槽位：照 IM，消息照投，槽位恢复。
- 回复里写这条去了哪，就是 `im()` 算出的那句原因。

### 待发队列

回合在跑时发消息，照 T3 Code 和 Orca 的做法。2026-10-24 读了两家的源码，正是先前描述的那样：

- 没打字时那个键是停止；打了字，它换成发送。
- 发出去的不进对话，排在输入框上面一个框里，头上写着几条。
- 每条右边有“插话”（Orca 写的是“提交，不打断模型”）。没在跑时那个按钮叫“立即发送”。
- 两家默认都是排队，按停止会把队列暂停，要手动“继续”。

所以不用拷问时选的“有字时停止键变打断”。打断再发照 IM：开头写 `!`。IM 那边不变，回合在跑时发的照旧直接插话：IM 里没有地方显示队列。

发送键是 `(回合在不在跑, 输入框里的字)` 的一个纯函数，和服务端 `parseCommand()` 的判断一致：

| 情况 | 键的图标 | 按下 |
|---|---|---|
| 没在跑，有字 | ↑ 发送 | 开新回合 |
| 在跑，没字 | ■ 停止 | 停下这一回合 |
| 在跑，有字 | 排队 | 排进待发队列 |
| 在跑，`!` 开头 | 打断再发 | 打断这一回合，这句作为新回合发出 |
| 在跑，Rhodium 认识的命令 | ↑ 发送 | 马上执行，不排队。网页上另有地方做的那几条，马上回一句去哪里 |

- “在跑”指槽位在启动或运行中，有回合在进行。
- 打了字时停止键不在。要停，开头写 `!`，或者清空再按停止；电脑上按 Esc。两家的手机版都只留一个键，免得误碰停止。

服务端：

- 排着的是一条 `agentInput`，`source: "human"`。不加表，加两种排队原因：
  - `web_queue`：排着，等这一回合跑完。
  - `web_paused`：暂停了，等你按“继续”或者这一条的“发送”。
- 认网页发的消息：`source: "human"`，追踪 ID 是请求的 `id`，inbound 表里没有它，所以路由的 `chatOf` 里也没有它。`/api/slot` 的待发队列和下面的撤下都这样认。
- `/api/slot` 带上这个槽位排着的网页消息：ID、正文、排队原因、附件个数。
- `say`：`im()` 会让这句插话、或者并进没有发起窗口的回合时，网页的改成写 `web_queue`，不交给 agent，回复“排队”。别的情况（开新回合、拉起进程、等打断生效、等额度、正在停止）照 `im()`。
- 运行器写排着的消息时（`src/runner.ts` 的 `deliver()`），跳过这两种原因，和跳过 `after_turn` 一样。
  - 不跳的话，第一条排着的网页消息会挡住它后面的一切：IM 的插话、队列里第二条的插话、暂停时新发的一句（槽位进了运行中，回合却起不来）。
- 回合正常跑完：`web_queue` 的清掉排队原因，开一个网页的回合：`turnChat` 是 `board`，`turnInbound` 是第一条的追踪 ID。运行器按先后写：第一条开回合，后面的并进去，和回合中途发的几条一样。
  - 不拼成一条：每条留着自己的来源行和追踪 ID，透传的 `/x` 照样是命令，页面也能一条一条认出待发的气泡。
  - 等回合结束的内部消息（`after_turn`）接着等：这个网页的回合有发起窗口，它们排在它后面。现成。
  - 审批模式改过（`approvalStale`）的进程，回合结束时本来要关掉，有等打断、等回合结束的消息要接着跑时除外。`web_queue` 也算进这个“除外”。
- 回合被额度拒了：`web_queue` 的和 `after_turn` 一样，改成 `after_quota`，额度恢复时交给 agent。
- 停止就暂停，而且一直停着：
  - 停止键、Esc、`/stop`、只有 `!`、停掉进程：按下时就把这个槽位的 `web_queue` 改成 `web_paused`。
  - 回合被别的事结束（`!` 打断再发、切到终端、换 agent、进程退出或崩溃）：结束时同样改成 `web_paused`。
  - `web_paused` 只有你能放：按“继续”，或者那一条的“发送”。回合跑完、内部回合（汇报、`rh send`）、你新发的消息都不放它。
  - `rh stop` 停完要不要再起进程，只看 `after_stop`、`after_turn` 和停的过程中你发来的消息（`src/router.ts` 退出那一支的 `waited`），不看这两种。暂停的不会把进程拉起来。
  - 切终端失败、留在无头时也一样：只有运行器会写的才把进程拉起来。不然进程起来了却没有回合，槽位一直停在“启动中”。
- 换对话（`/new`、`/resume`、换 agent，“跑完再换”也一样）：这两种排着的跟着槽位进新对话，一律改成 `web_paused`，要你按“继续”。
  - 为什么：`moveTo()` 现在把排着的留在旧对话、清掉原因，等你回到旧对话才写。网页排的会从队列里消失，以后又冒出来。
  - 改两处：`moveTo()` 把它们挪进新对话、改成暂停；“跑完再换”那一支挪你排着的消息时（`held`），跳过它们。
  - 先停着，不直接交给新的对话：换了对话，排着的话不一定还合适。
- `{ kind: "queued", op: "now", input }`：那一条清掉排队原因，交给 agent。回合在跑就是插话；没在跑就开一个网页的回合。挂着提问时拒收，回“先答提问”，和直接发的一样。
- `{ kind: "queued", op: "now" }`，不带 `input`，就是“继续”：`web_paused` 的全部改回 `web_queue`。回合在跑，它们等它跑完；没在跑，马上照回合正常跑完那样放出去。
  - 等额度时改成 `after_quota`，和这时发的一句一样，额度恢复时交给 agent。改回 `web_queue` 的话，关了自动继续或者 `/stop` 过，额度恢复时没有回合，它们就一直排着。
- `{ kind: "queued", op: "drop", input }`：删掉那一条。已经交给 agent 了，回“已经交给 agent”。
- “编辑”是页面上的：先发 `drop`，成了再把正文放回输入框，接在原有的字后面。
  - 带附件的那条没有“编辑”，只能插话（暂停时是发送）或删除：附件放不回输入框。
- Rhodium 替你扣着的网页消息（`after_interrupt` 等打断生效、`after_quota` 等额度、槽位正在停止）照旧走现在的路。`/api/slot` 一样把它们列进待发队列，带上原因；页面在下面一行写原因，只能删。
- 撤下：切到终端、急停时，现成的 `giveBack()` 把你排着的消息撤下来，暂停的也撤。网页的记一条 `input_returned`，`data` 里带原文，不往 IM 发引用。
  - `giveBack()` 不把网页的交给 `quoteBack()`。不然 `quoteBack()` 按 `chatOf` 分组，网页的落在“没有窗口”那一组，引用会发到联系窗口。
  - 页面开着，就把原文放回输入框，轻提示写原因；关着的话，详情抽屉的事件里看得到。

页面：

- 待发队列在对话和输入框之间，贴着输入框上沿。没有排着的，整块不显示。
- 头一行：列表图标和条数。有暂停的（`web_paused`）时换成暂停图标，右边一个“继续”（▶）。

### 提问

- `/api/slot` 的 `asks` 加结构化的部分：
  - 是/否的按钮字：`askButtons()` 给的那两个。
  - 选择题：每题的题目、选项（名字和说明）、能不能多选。
  - 审批：工具和摘录。计划：全文，用和对话同一份 Markdown 设置显示（见[只认看板自己的页面](#只认看板自己的页面)）。
- 网页答：`{ kind: "answer", ask, text }`。`text` 拼成 IM 里回的样子：编号，多选用空格隔开，几题一行一题；自己写的照原文。路由照旧 `parseAnswer()`，再 `answerAsk(by = "web")`。不另写解析。
- 两处要改：
  - `decide()` 把 `by` 当窗口 ID 用（导入的结果、切换的结果发去哪）。`by = "web"` 时只回网页。
    - 交给 agent 的决定里，请它把结果写在回复里，不用 `rh send me`（故事 478）。切换要等结果的，在等着的决定里记一个 `web`，`switched()` 照它说。
  - `answerAsk()` 的回答会解除 `rh send me` 的接管，恢复往 IM 的转发。网页的回答不解除：你在网页上。
- IM 那边：
  - Telegram：`unbutton` 效果加一个可选的 `said`。有它时，把那条提问改成原文下面加一行“已在网页回答：……”，撤掉按钮。没带按钮的提问（多选、几道题、没有选项的）也改。改不成（例如加上这行超过 4096 字），照旧只撤按钮。
  - QQ：改不了，往提问推去的那个窗口补发一行，记一次主动消息的额度。
- 网页答过的提问不再出现在 IM 的编号列表里。现成：列表只列挂着的。
- 提问已经不是挂着的：回 `ok: false, gone: true`，写明“已在 QQ 私聊回答”“已超时”“提问已撤回”。窗口用名字，不用 ID。页面把卡片换成这句。
- 别的失败（连不上、没看懂回答、内部错误）：卡片留着，写好的和选好的都在，出错的轻提示说明原因。
- 页面上正显示着的提问，在别处答了或超时了：`/api/slot` 的 `gone` 列出这个槽位刚答掉的提问（`ask_answered` 事件在 10 秒内，事件的 `data` 带提问 ID）和同样的那句话。页面把显示过的那张卡片换成这句，几秒后消失。撤回的不列，卡片直接消失。
- 卡片上不写“选择题”“审批”这类字，用图标分。
- 多选题的选项前有个方框，选中打勾。单选的没有。

思考强度的拖动条（2026-10-28 定，#454）：

- 没发成，弹回槽位现在的那档，出错的轻提示写原因。
- 换了模型带来新的几档，拖动条照新的重画，不沿用旧的位置。
- 宽屏上最宽约 28rem，不拉满整张卡片。

模型的搜索和分组（2026-10-28 定，#455）：

- 模型多于 8 个（IM 里一页的个数）时，单子顶上固定一个搜索框。

  - 候选多带一个 `group`，就是 pi 报的提供商。Claude、Codex 不带：Codex 的 `model/list` 没有按模型的提供商。页面不从命令里拆提供商，命令超过 64 字节会换成编号。
  - 每组一行组名，点了折起或展开。只有一个提供商时不画组名。
  - 模型多于 8 个时，只有现在的模型所在的那组开着，别的收着。

### 槽位上的操作

- 终端按钮发 `rh tui`。切过去后 Herdr 的焦点停在那个 pane，和 IM 发的 `/rh_tui` 一样（产品说明 §4.2）。
- 终端按钮按下先弹框确认，和收回终端同一个样子（2026-10-27 加，故事 476）：
  - 标题“切到终端？”。没回合在跑：“取消”“切换”。
  - 回合在跑：“取消”“跑完再切”，下面一行“打断，马上切”，后者带 `!`。原来的小菜单去掉。
  - “切换”和“跑完再切”在同一个位置，发的也是同一条：不带 `!` 的 `rh tui` 会等回合跑完。框开着时回合刚好开始，同一个位置也不会变成打断：框按上边定位，多出的一行长在下面。
  - 拓扑图的“⋯”和右键菜单里只有一项“切到终端”，弹同一个框。
  - 在输入框里打 `/rh_tui` 不弹框：打出来的命令就是确认。
- 切换的结果：`switched()` 只管切到终端和切回无头。它对没有发起窗口的切换，成功只在有窗口指着槽位时通知（[产品说明](../product.md) §5.10，2026-10-27 改）。网页发起的只在失败时通知，成功的是网页上的轻提示。
  - 网页发起时，槽位上记着的切换决定（`switchDecision`）里记一笔“网页”，`switched()` 见到它，成功就不通知。不加列。
  - 这和终端按钮在同一张工单，不然网页每切一次，IM 都收到一句。
- “收回终端”弹框确认，确认后发带 `sure: true` 的 `rh release`。
- 改名：标题原地变成输入框，回车或点外面发 `rh rename`，Esc 放弃。
- 停掉进程：详情抽屉进程那一行右边一个“停掉”，发 `rh stop <槽位>`。
- 拓扑图上槽位的详情：状态那一行末尾一个“⋯”，点开是这批操作。电脑上右键槽位，在指针处弹出同一张菜单。
  - 放在状态那一行，标题照旧占满一行。手机上详情收着时，还是一行高。
- 设置：发 `rh set`，改了就生效，不要“保存”键。

### 归档和撤销

- 归档照 `rh archive`：先停掉进程，再把指着它的窗口改回 Bot 的默认目标，每个窗口说一句（产品说明 §5.2）。
- 网页上的归档，回复带 `undo`：`{ kind: "bind", unarchive: "<槽位 ID>", changes: [{ chat, from: <归档后的样子>, to: "<槽位 ID>" }] }`。每个被改回默认的窗口一处。
- 轻提示带“撤销”，留 8 秒。按下把 `undo` 原样发回：
  - 和拓扑图上的确认是同一个 `bind`：每处比对“改之前”。都对上，恢复槽位、窗口指回去，各说一句“这里的消息改交给……”，一个事务。
  - 有一处对不上（这几秒里别处改过它），整个不做。回复写明哪个窗口被改成了什么，槽位还能去“已归档”恢复。
  - 服务端不限时间，靠比对挡住过时的撤销。
- 这是产品说明 §5.2“`rh unarchive` 恢复槽位，窗口不会自动指回它”的例外，写在那里。

### 列表行的菜单

2026-10-28 定的（#458）。

- 首页列表和放大模式侧栏里的槽位行，右键在指针处弹一个菜单。
- 触屏上手指按住一行约 0.5 秒不动，在手指处弹出同一个菜单。2026-10-31 加的（#504）。
  - 为什么要自己做：iPad、iPhone 上的浏览器（Safari 和 Chrome 都是）长按不发右键，只弹它自己的链接预览，原来在那上面打不开这个菜单。
  - 手指动了超过 10px、抬起、或者列表滚动了，不算长按，照旧是轻点或滚动。
  - 只对触屏：行上不出浏览器的链接预览、长按菜单，不选中文字。
  - 菜单弹出后抬起手指，不打开这个槽位。
  - 安卓上同一次长按平台还会发一次右键，在我们的之前或之后都有可能（看系统的长按时长设置）。只弹一个菜单；这次右键落在菜单上时，也不弹浏览器自己的菜单。
  - 鼠标右键、iPad 接触控板时的双指点，照旧走右键。
- 菜单项看槽位：
  - 没归档的无头槽位，从上到下（2026-10-31 加了停止、开新对话、改名、切到终端，#491；同一天加了置顶，#506）：
    - “停止”：只在回合在跑时有（启动中、运行中、需要你）。和发送键的停止一样，进程留着。
    - “置顶”，置顶了的是“取消置顶”：不弹框，轻提示写“已置顶 w/x。”。发 `{ kind: "pin", slot, on }`，不是 `rh` 命令。置顶后行等鼠标移开（触屏上抬手 3 秒后）再挪进置顶，和别的重排一样。
    - “开新对话”：和“⋯”里的一样，不弹框。
    - “改名”：这一行换成一个输入框，只有输入框带边框，和“⋯”里改名的那个一样：回车或点外面就改，Esc 放弃。
    - “切到终端”：弹和终端按钮同一个确认框，回合在跑时有“跑完再切”“打断，马上切”。
    - “归档”：和“⋯”里的一样，不弹框，轻提示带 8 秒的撤销。
  - 已归档的无头槽位：“恢复”“删除”。
  - 在终端里的槽位，不管归没归档，一项都没有，不弹菜单。`rh archive` 归档得了它，`rh rm` 却会拒（[架构](../architecture.md) §9.8）。
  - 别的都不放：压缩上下文、详情要进对话看。
- 菜单的代码按需加载，看板首屏不变大。右键不算要打开这个槽位，不预取它的对话。
- 列表要分出无头和 TUI：`/api/board` 的每个槽位加 `mode`。

### 删除

2026-10-28 定的：`rh rm` 是 #457，网页上的是 #458。删除是什么、谁能删，见[产品说明](../product.md) §4、§6.2 和 [v1 规格](v1.md#rh-命令)。

### 拓扑图上的改绑定

编辑开关：

- 在路径那一行右边，“已归档”开关旁边。不记住，每次打开拓扑图都不在编辑。
- 有草稿时，铅笔按不了。退出编辑要先确认或全部撤销，不另弹“放弃改动？”的框。

编辑时的圆点和线：

- 线和平时一样画（[网页拓扑图规格](web-topology.md)“图的排法”），不拆开：Bot 的线、跟着默认的窗口进 Bot 终点的连线、单独选的线。
- 起点：每个窗口一个，每个 Bot 一个，和平时同一个地方。终点：每个 Bot 一个；每个显示着、没归档的槽位一个，没有线落在那里的也画。编辑时圆点用运行中的蓝色。
- 起点只能换成起点，终点只能换成终点。
- 点圆点：点的是离手指最近的那个，在 22px 以内；选中的线两头放宽到 24px，拿起时能放的那些放宽到 26px。
- 离圆点远一点、点在节点上时：
  - 没选线时，点窗口或 Bot 标题算点它的起点，点槽位算点它的终点。
  - 拿着起点或终点时，点节点算点它能放的那个圆点，见“拿起终点”“拿起起点”。
  - 选中了线、没拿着时，不算点圆点，见“选中一条线”。

选中一条线：

- 没选线时，点线（照平时点线的规矩，[网页拓扑图规格](web-topology.md)“点”）、点一个起点、点窗口或 Bot 那一行，都是选中那条线。
- 选中以后：
  - 点它起点或终点的圆点（24px 以内）：拿起那一头，见“拿起终点”“拿起起点”。
  - 再点一下这条线，或者点它的窗口或 Bot 那一行别的地方：取消选中。
  - 点别的线、别的起点、别的窗口或 Bot 那一行：改成选中那条线。
  - 点一个槽位（不在圆点上）或者别的终点：和“点终点”一样，点亮落在那里的线。
  - 点空白处：取消选中。
- 选中的线画成蓝色、加粗，两头的圆点放大；别的线和节点变淡。
- 底部面板换成一行：起点的头像、箭头、终点（槽位的 logo 和名字；Bot 的终点是 Bot 头像，后面淡色写它现在的默认目标），右边一个 ✕ 取消。
- 编辑时不跳转、不设焦点，点工作区的标题只是展开或收起它。

拿起终点：

- 选中一条线后，点它的终点。
- 能放的终点亮起，带一圈光晕，别的变淡：
  - 窗口的线：每个没归档的槽位，再加它自己 Bot 的终点。别的 Bot 的终点不行。
  - Bot 的线：每个没归档的槽位。
  - 它现在的终点不算。
- 底部面板：起点的头像、箭头、一个虚线的空框，右边 ✕ 放下。
- 点一个亮着的终点（或者它的槽位、它的 Bot 标题）：线改到那里，成为草稿，线放下，不再选中。
- 点收着的工作区：它展开，终点还拿着（故事 311）。
- 点别处、点 ✕ 或者按 Esc：放下，什么都不变，线还选着。
- 放到自己 Bot 的终点上：跟着默认，草稿记成 `to: null`。
- 放到一个槽位上：单独选它，草稿记成 `to: <槽位 ID>`，哪怕它正好是 Bot 的默认目标。原来“放回默认目标那个槽位就是回到默认”的规矩不要了：只有 Bot 的终点是跟着默认。
- Bot 的线放到一个槽位上：改的是 Bot 的默认目标。接在它终点上的窗口不用动，连线还接着 Bot，跟着 Bot 的线走。
- 没有默认目标的 Bot 只有起点，选中它就直接拿起终点。

拿起起点（互换）：

- 选中一条线后，点它的起点。
- 能换的起点亮起，别的变淡：同一种的起点（窗口对窗口，Bot 对 Bot），而且两边现在到的槽位不一样。两边本来就到同一个槽位的不亮，换了也什么都不变。到不了槽位的（没有默认目标的 Bot，以及跟着它的窗口）不能换，也不亮。
- 底部面板：一个虚线的空框、互换图标、起点的头像、箭头、它现在的终点，右边 ✕ 放下。
- 点一个亮着的起点（或者它的窗口、它的 Bot 标题）：两边互换，算一步，可能是两处草稿。
- 互换按具体的槽位算：
  - 两个窗口：各自拿到对方现在到的那个槽位，都成了单独选的，不再跟着默认。例如 A 跟着 Bot X 的默认 W，B 跟着 Bot Y 的默认 V，换完 A 单独选 V，B 单独选 W。
  - 两个 Bot：互换默认目标。跟着它们的窗口各自跟过去。
- 放下的规矩和拿起终点一样。

点终点：

- 没拿着起点或终点时点一个终点：没选线时点终点或槽位；选中了线时点槽位或别的终点，只要不在它两头的圆点上。
- 落在这个终点上的线都点亮，终点放大，别的变淡。
- 底部面板：一排起点的头像，每个能点，箭头，这个终点。点一个头像，选中那条线。
- 只有一条线落在这里时，直接选中它。没有线落在这里时，什么都不变。
- 再点一下这个终点，或者点空白处，取消。

拖：

- 从起点拖：
  - 手机上按住起点约 0.3 秒（300ms）开始，轻轻一震；手指在这之前挪了 8px 以上，就是平移画面，不画线。鼠标按下挪 4px 以上马上开始。
  - 开始画线等于选中这条线、拿起它的终点：能放的终点亮起，别的起点变淡。
  - 手指下面还没有能放的终点时，从起点到手指画一条细线。指着一个能放的终点时（离它 30px 以内，或者在它的槽位、它的 Bot 标题上），改成画一条到它的预览线，蓝色虚线，这条线原来那段变淡。
  - 松在能放的终点上，和点了它一样，成为草稿。松在别处，放下，什么都不变。
- 从终点拖（反过来）：
  - 按住一个终点，同样的时长和距离开始。能连到这里的起点亮起，别的终点变淡：
    - 槽位的终点：每个现在不到这个终点的起点，窗口和 Bot 都算。跟着默认、默认目标正好是这个槽位的窗口也亮：连过来就成了单独选它。
    - Bot 的终点：这个 Bot 自己的、单独选过槽位的窗口。
  - 指着一个能连的起点时，画一条从它到这个终点的预览线。松在它上面，等于选中那个起点的线、把终点放到这里。
- 画线时画面不跟着手指滚，长按不弹浏览器的菜单。
- 从圆点以外按下，照旧是平移画面。用自己的指针处理，不用 React Flow 的连接（线本来就是自己算的）。

陌生人的窗口：

- 图上只画你的私聊、主窗口和单独选过槽位的窗口（[网页拓扑图规格](web-topology.md)“接口”）。陌生人的窗口只在单独选过时出现。
- 把它放回 Bot 的终点，草稿里它还画着，接着 Bot 的终点。确认以后，新的拓扑数据里没有它了，它从图上消失。
- 确认后 8 秒内的撤销照样能把它改回去：撤销那一批在确认时就算好了，不看它还在不在图上。

草稿：

- 草稿是盖在拓扑数据上的一层。布局本来是纯函数（`web/src/topology/model.ts`），把草稿套进数据再算一遍，就画出改后的样子。
- 新加的线画成蓝色虚线，和原型一样，免得像选中的线：Bot 的线和连线画粗虚线，单独选的照旧细虚线。
- 要删掉的线画成暗红色，不再只是变淡，粗细和虚实照平时。几个窗口的连线共用一段竖线时，要删的线画在没变的线下面，免得整段看着都要删。
- 两种红是颜色变量，浅色和深色各一个值：
  - `--draft-removed`（要删掉的线）：浅色 `#a3433e`，深色 `#a85550`。深色下和背景（`oklch(0.145 0 0)`）的对比约 3.9 比 1，不低于 3 比 1。
  - `--draft-conflict`（冲突）：等于各自主题的 `--destructive`，比要删掉的红亮。
- 草稿只挪线，不挪节点：窗口在 Bot 框里的次序按存着的绑定排。草稿里改到的槽位在收着的工作区里也露出来，下面的节点被往下推，次序不变。
- 底部一条栏：“改了 N 处”，右边“撤销一步”（↶）、“全部撤销”（✕）、“确认”（✓）。N 数的是窗口和 Bot 各几处，一次互换算两处、一步。
- 撤销一步：把草稿退回这一步之前的样子，原样恢复，不是只删掉这一步留下的那几处。做法是每一步之前存一份草稿，撤销时取回最近那份。这样互换不会只剩一半：
  - 第一步 A、B 互换：A 到 V，B 到 W（存着的是 A 到 W，B 到 V）。
  - 第二步把 A 的终点改到 U。同一处只留最后一次，A 的第一处被盖掉。
  - 撤销一步：草稿回到第一步之后，A 到 V，B 到 W。不会变成只删掉第二步的那处，A 回到存着的 W，B 还在 W。
- 同一处改两次，只留最后一次。改回原样，那处草稿就没了。
- 冲突：事件流带来新的拓扑数据时，每处草稿的“改之前”和新数据比一遍。对不上的那处，新加的线和它的起点画成 `--draft-conflict`，起点上再加一个出错的小图标（lucide 的 `triangle-alert`），不只靠颜色分；确认按不了，直到撤销或重做那一处。

确认和撤销：

- 确认：一个 `bind` 请求。每处带“改之前是什么”：窗口 `{ chat, from: { slot, use }, to: <槽位 ID> | null }`（`null` 是回到默认），Bot `{ bot, from, to }`。服务端用路由现成的 `target()` 重算比对，有一处对不上整批拒，写明哪个窗口被谁改成了什么；都对上，一个事务写完。
- 网页只用 Rhodium 自己的窗口行 ID。路由换成 `<Bot>/<平台窗口 ID>` 再调 `rh use`。
- 确认后底部那条栏留 8 秒，只剩一个撤销。按下发一个反向的 `bind`，同样带“改之前”。
- 窗口里说的那句：每个目标变了的窗口一句，写它最后交给谁，例如“这里的消息改交给 notes/helper。”。不提“在网页上改的”，和 `/rh_use` 的回复一样。改 Bot 的默认目标时，跟着默认的窗口里只在你和这个 Bot 的私聊里说，陌生人的窗口不说（[架构 §14.7](../architecture.md#147-rhodium-自己的话不碰程序的-bot)）。终端里的 `rh use`、`rh bind` 现在不说，槽位按钮那张工单补上（故事 260）。
- `rh use` 不是在 IM 里发的时候，回复现在写 `<Bot>/<平台窗口 ID>`。改用窗口名。

重排：

- 确认成功、撤销成功以后，按新的绑定重算一次两栏的上下次序（dagre，线交叉最少），照[网页拓扑图规格](web-topology.md)“图的排法”。
- 次序没变，什么都不动。变了，节点滑到新位置，0.3 秒。焦点在屏幕上的位置不变，画面跟着补偿；没有焦点时镜头不动。
- 编辑中途不重排：草稿只挪线，不挪节点，免得点着点着节点跑了。
- 别处（IM、终端）改的绑定照旧不重排，和现在一样。

其他：

- `/api/topology` 加每个窗口的工具行写法（详细还是简略），给窗口详情里的开关。开关发 `{ kind: "verbose", chat, on }`，路由照 `/rh_verbose` 改那个窗口，不往窗口里说。

### 新建和导入

- 新建槽位的单子：目录选择器、槽位名、agent。网页建的都是长期槽位。不单做“派生”：新建再发第一条消息就是。
  - 原来是工作区下拉框，能顺手新建工作区、写名字和目录。2026-10-28 换成目录选择器，见下面[目录选择器](#目录选择器)。
  - 从拓扑图工作区的详情点进来，选择器从那个工作区的目录开始。
- 目录可以写 `~/…`。网页发的 `rh ws` 和 `rh import --dir` 没有 shell 展开 `~`，路由把开头的 `~` 换成你的家目录。
- 建好、导入好，页面按回复里的 `slot` 直接进它的对话页。
- 导入：单子上先在目录选择器里选文件夹，按“列出”才去找。列表是 Herdr 里的 agent pane，加上这个目录里的对话，和 IM 的 `/rh_import` 同一份候选。pane 是整个 Herdr 会话里的，不按文件夹筛。IM 的 `/rh_import` 列的是窗口所在槽位的目录，网页上没有这个“所在”，所以让你选。
  - “列出”发 `rh import --dir <目录>`。每次列出都是一个写操作，会记一条事件、刷新页面，所以不跟着文件夹自动列（2026-10-28 定）。
  - 选一个、写名字，页面把候选的命令加上名字当 `rh import` 发出去；名字不写用默认名。
  - 导入从首页的“+”进来。放大模式里，侧栏顶上另有“新建槽位”“导入”两个入口（2026-10-25 第 32 轮加）。

### 目录选择器

2026-10-28 定的（#459）。新建槽位和导入共用一个。

```
┌──────────────────────────────────────────┐
│ ⌂  ~/Rhodium                           ↑ │  ← 路径框，能改；⌂ 回家目录，↑ 上一级
│ [Rhodium] [dispatcher] [notes] [shop] …  │  ← 工作区按钮，放不下横着滚
│ ⎇ main   ▣ Rhodium   ◉ 2                 │  ← 分支、落到哪个工作区、几个槽位在这里
│ README.md  package.json  bun.lock  +9    │  ← 前 8 个文件名
│ ▸ docs                                   │
│ ▸ holder                                 │
│ ▸ web                                    │
└──────────────────────────────────────────┘
```

- 停在哪个文件夹，选的就是哪个，不用再点“选择”。
- 新建槽位、从磁盘导入对话时，文件夹决定工作区：
  - 正好是哪个工作区的默认目录，槽位就进那个工作区。
  - 不是，就用文件夹名新建一个工作区，名字写在预览里，能改。重名照导入的规矩加 -2、-3。
  - 这和派生、导入找工作区是一个规矩（[产品说明](../product.md) §4.3、§6.1）。
  - 所以网页建的槽位，目录总是它工作区的默认目录，不发 `--dir`。
- 从 Herdr pane 导入不看文件夹：pane 按它自己的目录落到工作区，由路由去找，找不到就建。
- 工作区按钮：一排，每个工作区一个，顺序同首页，放不下横着滚。点了跳到它的目录。现在所在的那个（接口回的落到哪个工作区）加底色。它们换掉了原来的工作区下拉框。
- 从哪开始：首页的“+”从 `~` 开始。放大模式侧栏的“新建槽位”、拓扑图上工作区的“新槽位”，从那个工作区的目录开始。
- 路径框：
  - 一个能改的框，写成 `~` 开头的样子。左边 ⌂ 回家目录，右边 ↑ 上一级。没有能逐段点的路径。
  - 边打边补全：取最后一个 `/` 前面那级目录的列表，筛出开头对上的文件夹，不分大小写。Tab 补到几个候选共同的开头；只剩一个时补全，再加 `/`。
  - 回车进打的那个文件夹，不提交单子。
- 预览当前文件夹，图标不带字：
  - git 分支。不在分支上时不写。
  - 槽位会落到哪：工作区名，或者新建的名字（能改的框）。导入时选中了 Herdr pane，这一项连同那个框都不显示。
  - 有几个在用的槽位就在这个文件夹，大于 0 才写。已归档的不算。
  - 前 8 个文件名，多的写“+N”，N 是接口回的没列出的文件个数。
  - 不写“这里有几段对话”：Codex 的对话按日期存，不按目录，数不准，会和导入的列表对不上。
- 文件夹列表：
  - 每行一个文件夹，点了就进去。
  - 隐藏的文件夹（名字以 `.` 开头）平时不显示。路径最后一段打了 `.` 才显示，和终端里按 Tab 补全一样。
  - 最多列 500 个，多的写个数。要进没列出来的，在路径框里打它的名字。
  - 空文件夹写“空”。出错时一行原因占列表的位置，⌂、↑ 和工作区按钮照样能用。
- 能浏览整个磁盘，一直到 `/`，只读。没有“新建文件夹”：那是看板第一次往磁盘上写，要另做检查，手机上真要时再加。
- 建和导入，路由都不改：
  - 新建：文件夹是某个工作区的默认目录，发 `rh new <工作区>/<名字> --agent <agent>`，和原来一样。不是，先发 `rh ws <名字> <目录>`，再发 `rh new`。
  - 从磁盘导入：直接发 `rh import`。路由按对话的目录找工作区，找不到就用同一个规矩新建。只有你改了建议的名字，才先发 `rh ws <名字> <目录>`。
    - 已知的限制：工作区存着的目录经过符号链接时，预览按真实路径说落到这个工作区。路由却把对话的目录和工作区存着的目录逐字比，对不上，就在同一个文件夹上再建一个工作区。这种情况少见，这一批不改路由。新建槽位不受影响，它发的是 `rh new <工作区>/<名字>`。
  - 从 Herdr pane 导入：直接发 `rh import`，不先建工作区。
- 接口 `GET /api/dirs?path=<路径>`，只读。谁能调见[架构](../architecture.md) §11。
  - `path` 是 `~` 开头的或绝对路径，空的就是 `~`。`~` 按 `rhodium` 自己的 `HOME` 展开。
  - 回：真实路径（`~` 开头的写法）、子文件夹名（隐藏的排后面）和没列出的个数、前 8 个文件名和没列出的个数、git 分支、落到哪个工作区（或建议的新名字）、几个在用的槽位在这里、出错的原因。
  - 符号链接：指向文件夹的才列；进去以后是真实路径。
  - 找落到哪个工作区、数在用的槽位时，两边都取真实路径：当前文件夹，和工作区、槽位存着的目录。存着的目录是当时的写法，可能经过符号链接。不这样，经过符号链接的工作区对不上，预览会提议在同一个文件夹上再建一个。
  - 分支：从这个目录往上找 `.git`，读它的 `HEAD`；worktree 的 `.git` 是个文件，照它的 `gitdir:` 找。不起 git 进程。
  - 出错：没有这个目录、没有权限读这个目录、不是目录。
  - 建议的新名字照导入、派生找工作区时起名的那一处算，不另写一份。

### 页面

- 轻提示：底部，输入框上面；手机的拓扑图上在详情上面。成功的 3 秒后消失。出错的 8 秒后消失，底边一条进度条，点一下马上关（2026-10-28 改，#460；原来出错的留着，点掉为止）。可以带一个按钮（撤销、打断马上换）。
- 轻提示还在时，回到首页也看得到。菜单盖在轻提示上面。
- 带撤销的轻提示、出错的轻提示和拓扑图确认后的那条栏，都留 8 秒，底边一条进度条平滑地缩短，不一段一段地跳：一次 8 秒的 CSS 动画；页面重画时，用负的 `animation-delay` 接上已经走过的进度。
- 按钮按下后转圈、禁用，直到回复回来。
- 对话页：
  - 输入框：多行，发送键发。键盘上默认回车换行，Ctrl+Enter 或 ⌘+Enter 发（故事 511）：
    - 右键发送键弹出菜单，两项“Ctrl+Enter 发送”“Enter 发送”，现在用的打勾。手机上长按发送键，平台会弹右键菜单的地方一样弹。
    - 输入框空着时发送键按不了，右键照样弹菜单。它只标成按不了，不真禁用：Firefox 不给禁用的按钮发右键。
    - 选完或关上菜单，光标回到输入框。
    - 菜单上的字按系统写：Mac 和 iPad 上第一项写“⌘ Enter 发送”。按键不分系统，Ctrl 和 ⌘ 都算。
    - 选“Enter 发送”：回车发；Ctrl、⌘、Shift 加回车，在光标处换行。浏览器自己不会给 Ctrl+Enter 换行，页面替它插。输入框空着时回车什么都不做，回合在跑时也不会停下回合。
    - 选的存在这台设备的 `localStorage`，读写包在 try 里，存不了就用默认。
    - 输入法还在打字时的回车不算；命令面板开着时，回车照旧选命令。
  - 操作条在输入框下面：agent logo、模型和思考强度、终端按钮；右边附件、发送键。
  - 往输入框里粘贴图片或文件，或者把文件拖到对话区放下，都和点附件按钮一样进附件列表（#286）。剪贴板里有文字时照旧粘成文字，例如从表格复制的、还带着一张图的。
  - 文件拖偏了，放在列表、顶栏或别的地方，页面不收它，浏览器也不会打开它离开看板。
  - 已归档的槽位，操作条上不给终端按钮，和拓扑图的菜单一样。输入框留着：发消息会恢复它（见“网页开始的回合”）。
  - “⋯”：开新对话、压缩上下文、改名、归档。已归档的槽位是恢复、删除；删除只给无头的（2026-10-28 加）。
  - TUI 时：输入框和操作条换成横幅，横幅上“收回终端”。

### 要先改的地方

调研时找到的，括号里是在哪张工单改：

1. 终端里 `rh use`、`rh bind` 没在那个窗口说一句（产品说明 §7 要求）。（槽位按钮）
2. `rh use` 不在 IM 里发时，回复带平台窗口 ID。（槽位按钮）
3. `decide()` 把 `by` 当窗口 ID。（答提问）
4. `answerAsk()` 对网页的回答也解除 `rh send me` 的接管。（答提问）
5. `switched()` 对没有发起窗口的切换，成功也通知联系窗口。网页发起的只在失败时通知。（槽位按钮）
6. `contracts.ts` 里 `board` 输入是空壳。（底子和停止键）
7. 来源行：代码写 `[来自 网页]`，产品说明原来写“[来自网页]”。产品说明已经跟着改了。（发消息）
8. IM 插话接管回合只认 `turnChat` 为空（正在停止那一支认 `turnInbound` 为空），要加上 `board`；IM 里答提问也要接管。（发消息）
9. `rhCommand()` 要 Bot 和窗口算“这里”。（命令面板）
10. 时间线只给会话 ID 的前 8 位，`/resume` 按开头匹配会撞。（agent 和模型按钮）
11. 回复里提到下一步时写 IM 命令或 `rh` 命令，网页要换成按钮的说法。（底子和停止键起，碰到哪条改哪条）
12. agent 的 Markdown 认原始 HTML、什么链接都认；HTML 没有 `script-src`。（底子和停止键）
13. 输入框里打的 `/rh_release` 走 `rhCommand()` 会直接收回终端，绕过确认框；`/rh_use`、`/rh_bind`、`/rh_verbose`、`/rh_ls` 要 Bot 和窗口。（发消息）
14. 运行器写排着的消息时只跳过 `after_turn`，要再跳过 `web_queue`、`web_paused`。（待发队列）
15. `moveTo()` 把排着的留在旧对话；“跑完再换”那一支把你排着的都挪进新对话、清掉原因。网页排的要挪进新对话、改成暂停。（待发队列）
16. `quoteBack()` 把没有窗口的消息引用到联系窗口。`giveBack()` 撤下网页的消息时不交给它。（待发队列）

## 不做的事

| 不做的事 | 什么时候再说 |
|---|---|
| 急停 | 照旧只在 ssh 里。2026-10-21 定：“急停不是要在手机上做的操作” |
| 网页推送 | 不做（2026-10-24 定）。IM 照旧是推送的渠道。回合跑完另有未读和电脑上的跑完提醒，见[产品说明](../product.md) §7 |
